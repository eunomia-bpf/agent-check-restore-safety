\title{When Can Agents Safely Checkpoint, Fork, Restore, and Merge?\\
% Agent 何时能够安全地 Checkpoint、Fork、Restore 和 Merge？
Exact Checking for Execution Edits}
% 执行编辑的精确检查

\author{}

\begin{document}
\maketitle

\begin{abstract}
Agent runtimes can Checkpoint an execution, Fork it, Restore a checkpoint, or Merge branches without restarting a task.
% Agent 运行时可以 Checkpoint 一次执行、Fork 它、Restore 一个检查点或 Merge 多个分支，而无需重新开始任务。
We call these operations \emph{execution edits} because they change which parts of the workflow will run next.
% 我们把这些操作称为\emph{执行编辑}，因为它们会改变工作流接下来执行哪些部分。
An edit changes future work without undoing a tool action that has already been authorized or released.
% 编辑会改变未来的工作，但不会撤销已经获得授权或已经发出的工具动作。
An unsafe edit can therefore authorize the same action twice, discard a result the workflow still requires, or conflict with a call that began before the edit.
% 因此，不安全的编辑可能两次授权同一个动作、丢弃工作流仍然要求的结果，或与编辑前已经开始的调用冲突。
Existing Agent systems support Fork, Restore, or Merge, but neither these systems nor existing synthesis methods derive a requested edit's safety conditions from the current execution record.
% 现有 Agent 系统支持 Fork、Restore 或 Merge，但这些系统和现有综合方法都不会从当前执行记录中推导一次编辑的安全条件。
We give an algorithm that decides exactly whether the requested operation is safe.
% 我们给出一种算法，精确判定所请求的操作是否安全。
It returns all safe ways to continue, or proves that none exists.
% 它给出全部安全继续方式，或者证明不存在安全方式。
The Agent is untrusted and cannot choose which past actions or required results to ignore; the runtime determines both from its own records.
% Agent 不能自行选择忽略哪些过去的动作或要求实现的结果；运行时根据自己的记录确定二者。
To make this decision, the algorithm lists every way the task can finish without violating policy.
% 为作出这一判定，算法列出任务在不违反策略的情况下完成的每种方式。
It removes any way that could make a still-required result impossible to finish later.
% 如果某种方式可能导致仍然要求实现的结果以后无法完成，算法就将其删除。
If none remain, it returns a checkable proof that no safe implementation exists.
% 如果没有方式留下，算法就返回一份可检查的证明，说明不存在安全实现。
Otherwise, the remaining ways describe exactly what the runtime may allow.
% 否则，剩余方式精确描述运行时可以允许的行为。
The main theorem covers Checkpoint and the six forms of Fork, Restore, and Merge, together with extensions, atomic enforcement, and the information every exact checker needs.
% 主定理覆盖 Checkpoint 以及 Fork、Restore 和 Merge 的六种形式，并涵盖扩展、原子强制执行以及每个精确检查器所需的信息。
Lean proofs and executable tests validate the theory and checker.
% Lean 证明和可执行测试验证了该理论与检查器。
\end{abstract}
