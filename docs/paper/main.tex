\title{When Are Agent Execution Edits Safe?\\
% Agent 执行编辑何时安全？
An Exact Theory of Fork, Restore, and Merge}
% Fork、Restore 与 Merge 的精确理论

\author{}

\begin{document}
\maketitle

\begin{abstract}
Agent runtimes can Fork an execution, Restore a checkpoint, or Merge branches without restarting a task.
% Agent 运行时可以 Fork 一次执行、Restore 一个检查点或 Merge 多个分支，而无需重新开始任务。
We call these operations \emph{execution edits} because they change which parts of the workflow will run next.
% 我们把这些操作称为\emph{执行编辑}，因为它们会改变工作流接下来执行哪些部分。
An edit changes future work without undoing a tool action that has already been authorized or released.
% 编辑会改变未来的工作，但不会撤销已经获得授权或已经发出的工具动作。
An unsafe edit can therefore authorize the same action twice, discard a result the workflow still requires, or conflict with a call that began before the edit.
% 因此，不安全的编辑可能两次授权同一个动作、丢弃工作流仍然要求的结果，或与编辑前已经开始的调用冲突。
Existing Agent systems support Fork, Restore, or Merge, but neither these systems nor existing synthesis methods derive a requested edit's safety conditions from the current execution record.
% 现有 Agent 系统支持 Fork、Restore 或 Merge，但这些系统和现有综合方法都不会从当前执行记录中推导一次编辑的安全条件。
We give an exact procedure for deciding whether an execution edit is safe.
% 我们给出一个精确过程，用于判定一次执行编辑是否安全。
It either computes every safe way for the edited workflow to continue or proves that every possible implementation is unsafe.
% 它要么计算编辑后工作流安全继续执行的全部方式，要么证明该编辑的每种可能实现都不安全。
Given a registered workflow and execution record, a trusted controller derives the edited workflow and the outcomes that it must preserve.
% 给定一个已注册工作流及执行记录，可信控制器推导编辑后的工作流及其必须保留的结果。
The procedure constructs the complete executions allowed by the workflow and policy, then removes any execution whose prefix would leave a still-required outcome with no safe completion.
% 该过程构造工作流与策略允许的完整执行，然后删除任何会在某个前缀后使仍然要求实现的结果无法安全完成的执行。
If no execution remains, it returns a finite, independently checkable proof that the edit has no safe implementation.
% 如果没有执行留下，它就返回一个有限且可独立检查的证明，说明该编辑不存在安全实现。
Otherwise, the remaining executions contain every safe continuation, and the runtime permits exactly their prefixes.
% 否则，剩余执行包含全部安全继续方式，运行时只允许它们的前缀。
The main theorem covers six edits, registered extensions, atomic enforcement, and the information every exact checker needs.
% 主定理覆盖六种编辑、注册扩展、原子执行以及每个精确检查器所需的信息。
Lean proofs and executable tests validate the theory and checker.
% Lean 证明和可执行测试验证了该理论与检查器。
\end{abstract}
