\title{When Can Agents Safely Checkpoint, Fork, Restore, and Merge?\\
% Agent 何时能够安全地 Checkpoint、Fork、Restore 和 Merge？
Exact Checking for Execution Edits}
% 执行编辑的精确检查

\author{}

\begin{document}
\maketitle

\begin{abstract}
Agent runtimes can Checkpoint an execution, Fork it, Restore a checkpoint, or Merge branches without restarting a task.
% Agent 运行时可以 Checkpoint 一次执行、Fork 它、Restore 一个检查点或 Merge 多个分支，而无需重新开始任务。
We call these operations \emph{execution edits}, with Checkpoint recording the current execution for later use and Fork, Restore, and Merge changing what the Agent will do next.
% 我们把这些操作称为\emph{执行编辑}，其中 Checkpoint 记录当前执行供之后使用，而 Fork、Restore 和 Merge 改变 Agent 接下来做什么。
An execution edit cannot undo an earlier authorization or a tool request already sent.
% 执行编辑不能撤销先前的授权或已经发出的工具请求。
An unsafe edit can therefore authorize the same action twice, discard a result the task still requires, or conflict with a call that began before the edit.
% 因此，不安全的编辑可能两次授权同一个动作、丢弃任务仍然要求的结果，或与编辑前已经开始的调用冲突。
The Agent is untrusted, so the runtime uses its own records to determine which past actions an edit must account for and which required results it must preserve to keep the subsequent execution safe.
% Agent 不受信任，因此运行时根据自己的记录确定一次编辑必须考虑哪些过去的动作、保留哪些要求实现的结果，以保证后续执行安全。
Yet existing Agent systems support such operations without deriving what each edit must preserve from the running execution, whereas prior methods for computing safe behavior take that requirement as input.
% 然而，现有 Agent 系统支持这类操作，却不会从正在进行的执行中推导每次编辑必须保留什么，而以往用于计算安全行为的方法则把这一要求作为输入。
We give an algorithm that decides exactly whether an edit is safe.
% 我们给出一种算法，精确判定一次编辑是否安全。
It returns all safe ways to continue, or proves that none exists.
% 它给出全部安全继续方式，或者证明不存在安全方式。
To make this decision, the algorithm lists every way the task can finish without violating policy.
% 为作出这一判定，算法列出任务在不违反策略的情况下完成的每种方式。
It removes any way that could make a still-required result impossible to finish later.
% 如果某种方式可能导致仍然要求实现的结果以后无法完成，算法就将其删除。
If none remain, it returns a checkable proof that no safe implementation exists.
% 如果没有方式留下，算法就返回一份可检查的证明，说明不存在安全实现。
Otherwise, the remaining ways describe exactly what the runtime may allow.
% 否则，剩余方式精确描述运行时可以允许的行为。
Our formal results cover Checkpoint and the six forms of Fork, Restore, and Merge, together with extensions, atomic enforcement, and the information every exact checker needs.
% 我们的形式结果覆盖 Checkpoint 以及 Fork、Restore 和 Merge 的六种形式，并涵盖扩展、原子强制执行以及每个精确检查器所需的信息。
Lean mechanizes the finite checker and runtime invariant, and tests validate all six edit forms.
% Lean 对有限检查器及运行时不变量进行机械化证明，测试验证全部六种编辑形式。
\end{abstract}
