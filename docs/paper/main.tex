\title{When Are Agent Execution Edits Safe?\\
% Agent 执行编辑何时安全？
An Exact Theory of Fork, Restore, and Merge}
% Fork、Restore 与 Merge 的精确理论

\author{}

\begin{document}
\maketitle

\begin{abstract}
Agent runtimes can Fork an execution, Restore a checkpoint, or Merge branches without restarting a task; we call these operations \emph{execution edits}.
% Agent 运行时可以 Fork 一次执行、Restore 一个检查点或 Merge 多个分支，而无需重新开始任务；我们把这些操作称为\emph{执行编辑}。
Because an execution edit cannot undo an authorized or released tool call, it can duplicate a protected action, discard required work, or race with an earlier call.
% 由于执行编辑无法撤销已经获得授权或已经发出的工具调用，它可能重复执行受控动作、丢弃仍要求完成的工作，或与较早的调用发生竞态。
Deciding safety requires the \emph{execution record}: the current workflow, checkpoints, call--action map, prior authorizations, queued requests, and current monitor version.
% 判定安全性需要\emph{执行记录}：当前工作流、检查点、调用—动作映射、既有授权、排队请求和当前监控器版本。
Existing Agent recovery systems implement particular edits, while synthesis methods assume that possible executions and completion conditions are already known; neither derives a requested edit's complete safety condition from this record.
% 现有 Agent 恢复系统实现特定编辑，而综合方法假定可能执行及完成条件已经给定；二者都不会从该记录推导请求编辑的完整安全条件。
We show that every outcome required before the edit must remain required, be satisfied by the recorded execution, or be explicitly removed by the same authority that required it.
% 我们证明，编辑前要求实现的每个结果都必须继续作为要求、已经由所记录的执行满足，或由提出该要求的同一权限方明确移除。
Our executable checker constructs all complete executions allowed by the registered workflow and policy, then removes any execution whose prefix leaves a still-required outcome without a safe completion.
% 我们的可执行检查器构造已注册工作流和策略允许的全部完整执行，再删除其某个前缀会使仍要求实现的结果失去安全完成方式的执行。
If none remain, it returns a finite, independently checkable rejection certificate; otherwise, the remaining executions define the unique most-permissive runtime monitor.
% 如果没有执行留下，检查器返回有限且可独立检查的拒绝证书；否则，剩余执行定义唯一且限制最少的运行时监控器。
For all six registered Fork, Restore, and Merge edits and authenticated registered extensions, our main theorem proves that the checker accepts exactly when a safe implementation exists.
% 对全部六种已注册的 Fork、Restore 和 Merge 编辑以及经认证的已注册扩展，我们的主定理证明，当且仅当安全实现存在时，检查器才会接受。
The theorem further proves atomic installation despite racing calls, identifies the workflow structure, call--action map, prior authorizations, and monitor version that every exact checker needs, establishes ideal--runtime Agent-visible equivalence, and preserves the security invariant across every finite execution.
% 该定理还证明调用竞态下的原子安装，确定每个精确检查器都需要的工作流结构、调用—动作映射、既有授权和监控器版本，建立理想机与运行时的 Agent 可见等价性，并在每段有限执行上保持安全不变量。
Six Lean modules mechanize the theorem chain, and 19 paper-specific tests and measurements over 2--128 outcomes exercise the executable checker.
% 六个 Lean 模块机械化定理链，19 项论文专用测试与覆盖 2--128 个结果的测量检验可执行检查器。
\end{abstract}
