Recall the authorization-label alphabet \(\mathcal U\) and regular prefix-closed policy \(\mathcal A\subseteq\mathcal U^*\).
% 回顾授权标签字母表 \(\mathcal U\) 和正则前缀闭合策略 \(\mathcal A\subseteq\mathcal U^*\)。
For authorization log \(\Delta\), \(\mathsf{lab}(\Delta)\in\mathcal A\) is its authorization sequence and \(D_\Delta\) is the set of actions that already have authorization records.
% 对于授权日志 \(\Delta\)，\(\mathsf{lab}(\Delta)\in\mathcal A\) 是其授权序列，\(D_\Delta\) 是已经具有授权记录的动作集合。
Fix \(\Theta=(\kappa,H,\Delta,\mathsf{out},\mathcal A,u)\) and write \(\mathsf{state}(\Theta)=(\kappa,H,\Delta,\mathsf{out},\mathcal A)\).
% 固定 \(\Theta=(\kappa,H,\Delta,\mathsf{out},\mathcal A,u)\)，并记 \(\mathsf{state}(\Theta)=(\kappa,H,\Delta,\mathsf{out},\mathcal A)\)。
\(\mathsf{Derive}\) is partial.
% \(\mathsf{Derive}\) 是偏函数。
Whenever the initial rule update, an execution edit, or a later registered extension is valid, it produces a unique derived record.
% 当初始规则更新、执行编辑或后续注册扩展有效时，它产生唯一的派生记录。
When defined, write \(\mathsf{Derive}(\Theta)=(\kappa_u,H_u,\mathcal A_u,\mathcal C_u,\eta^-,\eta^+)\).
% 当有定义时，记 \(\mathsf{Derive}(\Theta)=(\kappa_u,H_u,\mathcal A_u,\mathcal C_u,\eta^-,\eta^+)\)。
Root derivation additionally requires that \(\mathsf{CheckReg}(\mathcal W,\mathcal R)\) accept.
% 根推导还要求 \(\mathsf{CheckReg}(\mathcal W,\mathcal R)\) 接受。
An execution edit has \((\kappa_u,\mathcal A_u)=(\kappa,\mathcal A)\) and uses the unique execution-edit judgment.
% 执行编辑满足 \((\kappa_u,\mathcal A_u)=(\kappa,\mathcal A)\) 并使用唯一的执行编辑判定。
\(\mathsf{Extend}(\xi)\) adds authenticated edit-rule, call, outcome-authority, and policy entries while preserving the current workflow, its progress, and all earlier authorizations.
% \(\mathsf{Extend}(\xi)\) 添加经认证的编辑规则、调用、结果权限和策略条目，同时保留当前工作流、其进展及所有先前授权。
\Cref{app:registered-extension} gives the judgment.
% 该判定见 \cref{app:registered-extension}。
Let \(\rho_u\) be the target registry in \(H_u\), let \(O_{H,u}=O_{\mathcal C_u}\), and use \(H'=H_u\) and \(\rho'=\rho_u\) where earlier notation is convenient.
% 令 \(\rho_u\) 为 \(H_u\) 中的目标注册表，令 \(O_{H,u}=O_{\mathcal C_u}\)，并在沿用先前记法更方便时使用 \(H'=H_u\) 和 \(\rho'=\rho_u\)。
The execution sets below use \(\Theta\), the edit-rule registry, \(\rho_u\), and target policy \(\mathcal A_u\).
% 下文执行集合使用 \(\Theta\)、编辑规则注册表、\(\rho_u\) 和目标策略 \(\mathcal A_u\)。
Before the rules change, the trusted runtime checks the complete record again, including queued requests \(\mathsf{out}\), so a concurrent release makes an earlier answer stale.
% 规则改变之前，可信运行时会再次检查完整记录，其中包括排队请求 \(\mathsf{out}\)，因此并发发出请求会使较早的判定结果过期。
We abbreviate the fixed parameters by writing \(H,u\).
% 我们用 \(H,u\) 简写固定参数。

\subsection{New and Reused Authorizations}
% 新授权与授权复用

Function \(\Resolve^{\rho_u}_\Delta\) keeps every workflow call and annotates it as creating a new authorization or reusing an earlier one.
% 函数 \(\Resolve^{\rho_u}_\Delta\) 保留每个工作流调用，并标注它是创建新授权还是复用先前授权。
Starting with \(D_0=D_\Delta\), it maps a call sequence \(w=x_1\cdots x_n\) to annotated sequence \(z_1\cdots z_n\).
% 从 \(D_0=D_\Delta\) 开始，它把调用序列 \(w=x_1\cdots x_n\) 映射为带标注序列 \(z_1\cdots z_n\)。
For \(d_i=q^{\rho_u}_{\rm act}(x_i)\),
% 对于 \(d_i=q^{\rho_u}_{\rm act}(x_i)\)，定义 \(z_i\) 如下：
\begin{equation}
\label{eq:resolve}
 z_i=
 \begin{cases}
  \Fresh(x_i,d_i), & d_i\notin D_{i-1},
       \quad D_i=D_{i-1}\cup\{d_i\};\\
  \Alias(x_i,d_i), & d_i\in D_{i-1},
       \quad D_i=D_{i-1}.
 \end{cases}
\end{equation}
\(\mathsf{auth}\) keeps the authorization label of each new authorization and contributes nothing for reuse.
% \(\mathsf{auth}\) 保留每次新授权的授权标签，而授权复用不贡献标签。
\[
 \mathsf{auth}(\Fresh(x,d))=\ell(d),\qquad
 \mathsf{auth}(\Alias(x,d))=\epsilon .
\]
For annotated \(z\), \(\mathsf{raw}(z)\) drops the new/reuse annotation and action while preserving the ordered workflow-call IDs.
% 对于带标注的 \(z\)，\(\mathsf{raw}(z)\) 去除新建/复用标注和动作，同时保留有序工作流调用标识。
A \Retry repeats the same canonical request and adds no workflow call.
% \Retry 重复同一个规范请求，不增加任何工作流调用。
Restored workflow calls that share an action remain distinct.
% 共享同一动作的恢复工作流调用仍彼此有别。
The first call creates the authorization record, and later calls reuse it.
% 第一个调用创建授权记录，后续调用则复用它。

\begin{lemma}[New/reuse classification]
% 新建/复用分类
\label{lem:resolution}
\(\Resolve^{\rho_u}_\Delta\) is deterministic, preserves length, and gives the same annotations on every shared prefix.
% \(\Resolve^{\rho_u}_\Delta\) 是确定性的、保持长度，并在每个共享前缀上给出相同标注。
Among calls annotated as new, each action occurs at most once outside \(D_\Delta\), and dropping the annotations gives exactly the input sequence.
% 在标注为新授权的调用中，\(D_\Delta\) 之外的每个动作至多出现一次，并且去掉标注后恰好得到输入序列。
Moreover, if \(\Resolve^{\rho_u}_\Delta(rv)=zv'\), then \(z=\Resolve^{\rho_u}_\Delta(r)\) and \(v'=\Resolve^{\rho_u}_{\Delta_z}(v)\), where \(\Delta_z\) extends \(\Delta\) by the new authorizations in \(z\).
% 此外，若 \(\Resolve^{\rho_u}_\Delta(rv)=zv'\)，则 \(z=\Resolve^{\rho_u}_\Delta(r)\) 且 \(v'=\Resolve^{\rho_u}_{\Delta_z}(v)\)，其中 \(\Delta_z\) 通过加入 \(z\) 中的新授权来扩展 \(\Delta\)。
\end{lemma}
\begin{proof}
Induction on input length shows that the function emits one prefix-determined annotation per input symbol and updates \(D_i\) exactly when it creates a new authorization.
% 对输入长度作归纳表明，该函数为每个输入符号产生一个由前缀决定的标注，并且恰在创建新授权时更新 \(D_i\)。
Set membership ensures at most one new authorization per action.
% 集合成员关系确保每个动作至多创建一次新授权。
Both cases retain \(x_i\).
% 两种情形都会保留 \(x_i\)。
Splitting after \(r\) gives the stated composition equation.
% 在 \(r\) 之后拆分即可得到所述组合等式。
\end{proof}
Thus a retry changes neither the processed-call record nor the authorization sequence, although its successful API reply is observable as \(\mathsf{Return}(t,[v]_{\cong})\).
% 因而，重试既不改变已处理调用记录，也不改变授权序列，但其成功 API 回复仍可观测为 \(\mathsf{Return}(t,[v]_{\cong})\)。
A copied workflow call that reuses an authorization record advances the processed-call record without changing the authorization sequence.
% 复用授权记录的复制工作流调用会推进已处理调用记录，但不会改变授权序列。

\subsection{Safe Completion After Every Prefix}
% 每个前缀之后的安全完成

\subsubsection{Computing all safe behavior}
% 计算全部安全行为

For each derived outcome \(o\in O_{H,u}\), define all of its complete executions and the subset allowed by policy.
% 对每个推导出的结果 \(o\in O_{H,u}\)，定义其全部完整执行以及策略允许的子集。
\begin{equation}
\label{eq:safe-completions}
\begin{aligned}
 R_o(H,u)&=\{\Resolve^{\rho_u}_\Delta(w)\mid w\in\Lin(p_o)\},\\
 M_o(H,u)&=\{z\in R_o(H,u)\mid
   \mathsf{lab}(\Delta)\mathsf{auth}(z)\in\mathcal A_u\}.
\end{aligned}
\end{equation}
For an annotated prefix \(z\), let
% 对于带标注前缀 \(z\)，定义 \(\mathsf{Compat}(z)\) 如下：
\[
 \mathsf{Compat}(z)=
 \{o\mid \mathsf{raw}(z)\preceq_{\rm pref}w
		          \text{ for some }w\in\Lin(p_o)\}.
\]
\(\mathsf{PreservesRequired}(H,u,\widehat B)\) means that every outcome in \(\mathsf{StillRequired}_u\) is covered by some target outcome represented in \(\widehat B\):
% \(\mathsf{PreservesRequired}(H,u,\widehat B)\) 表示 \(\mathsf{StillRequired}_u\) 中的每个结果都被 \(\widehat B\) 所表示的某个目标结果覆盖：
\[
 \forall a\in\mathsf{StillRequired}_u.\quad
 \exists (t,y)\in\widehat B.\ \mathsf{Covers}_u(t,a).
\]

\begin{definition}[Safe execution set]
% 安全执行集合
\label{def:safe-execution-set}
A safe execution set is a pair \((L,\widehat B)\), where \(L\) contains allowed partial executions and \(\widehat B\) contains allowed complete executions labeled by outcome, satisfying the conditions below.
% 安全执行集合是二元组 \((L,\widehat B)\)，其中 \(L\) 包含获准的部分执行，\(\widehat B\) 包含按结果标记的获准完整执行，并满足下列条件。
\begin{enumerate}[leftmargin=*,itemsep=1pt]
 \item \(\widehat B\ne\varnothing\);
% \(\widehat B\) 非空；
 \item \emph{workflow and outcomes:} \(\mathsf{PreservesRequired}(H,u,\widehat B)\), \(\widehat B\subseteq \biguplus_{o\in O_{H,u}}\{o\}\times R_o(H,u)\), and \(L\subseteq\Pref(\bigcup_{o\in O_{H,u}}R_o(H,u))\);
% 工作流与结果：\(\mathsf{PreservesRequired}(H,u,\widehat B)\)、\(\widehat B\subseteq \biguplus_{o\in O_{H,u}}\{o\}\times R_o(H,u)\)，且 \(L\subseteq\Pref(\bigcup_{o\in O_{H,u}}R_o(H,u))\)。
 \item \emph{policy:} \(\mathsf{lab}(\Delta)\,\mathsf{auth}(z)\in\mathcal A_u\) for every \(z\in L\);
% 策略：对每个 \(z\in L\)，均有 \(\mathsf{lab}(\Delta)\,\mathsf{auth}(z)\in\mathcal A_u\)。
 \item \emph{some completion after every prefix:} \(L=\Pref(\pi_2\widehat B)\); and
% 每个前缀之后都有某种完成方式：\(L=\Pref(\pi_2\widehat B)\)；并且
 \item \emph{every compatible outcome remains completable:} for every \(z\in L\) and \(o\in\mathsf{Compat}(z)\), some \((o,y)\in\widehat B\) extends \(z\).
% 每个兼容结果仍可完成：对于每个 \(z\in L\) 和 \(o\in\mathsf{Compat}(z)\)，都存在某个 \((o,y)\in\widehat B\) 扩展 \(z\)。
\end{enumerate}
\end{definition}

Checking each outcome separately is insufficient.
% 单独检查每个结果并不充分。
After a partial execution shared by several outcomes, every outcome still compatible with that partial execution must retain a policy-safe completion.
% 在多个结果共享的一段部分执行之后，每个仍与该部分执行兼容的结果都必须保留一条策略安全的完成路径。
The operator below removes exactly the complete executions that violate this condition.
% 下列算子恰好删除违反这一条件的完整执行。
Put
% 令 \(\widehat B_0\) 如下：
\[
 \widehat B_0=\biguplus_{o\in O_{H,u}}\{o\}\times M_o .
\]
For \(\widehat B\subseteq\widehat B_0\), define the monotone operator
% 对于 \(\widehat B\subseteq\widehat B_0\)，定义如下单调算子：
\begin{equation}
\label{eq:robust-operator}
\widehat\Phi(\widehat B)=
\left\{(o,y)\in\widehat B_0\ \middle|\
\begin{array}{l}
\forall z\preceq_{\rm pref} y.\ \forall o'\in\mathsf{Compat}(z).\\[-2pt]
\exists (o',y')\in\widehat B.\ z\preceq_{\rm pref}y'
\end{array}\right\}.
\end{equation}
Set \(\widehat B_{i+1}=\widehat\Phi(\widehat B_i)\).
% 令 \(\widehat B_{i+1}=\widehat\Phi(\widehat B_i)\)。
Since \(\widehat B_1\subseteq\widehat B_0\), repeated application removes executions until the finite set stops changing:
% 由于 \(\widehat B_1\subseteq\widehat B_0\)，反复应用该算子会移除执行，直至有限集合不再变化：
\[
\begin{aligned}
 \widehat B^\dagger_{H,u}
   &=\nu\widehat B.\widehat\Phi(\widehat B)
     =\bigcap_{i\geq 0}\widehat B_i,\\
 B^\dagger_{H,u}&=\pi_2\widehat B^\dagger_{H,u},
 &W^\dagger_{H,u}&=\Pref(B^\dagger_{H,u}).
\end{aligned}
\]
\begin{definition}[Safe execution edit]
% 安全执行编辑
\label{def:safe-execution-edit}
\begin{equation}
\label{eq:largest-safe-set}
\mathsf{SafeEdit}(\Theta)
 \quad\Longleftrightarrow\quad
 \begin{cases}
 \widehat B^\dagger_{H,u}\ne\varnothing,
   & \mathsf{Derive}(\Theta)\text{ is defined};\\
 \mathsf{false},&\text{otherwise}.
 \end{cases}
\end{equation}
\end{definition}
At \(z=\epsilon\), the fixed-point condition retains a completion for every target outcome, and the checked coverage maps cover every required source outcome.
% 在 \(z=\epsilon\) 处，不动点条件为每个目标结果保留一条完成路径，经过检查的覆盖映射则覆盖每个要求实现的源结果。
The existential quantifier chooses a call order, and the universal condition keeps every compatible outcome completable after every prefix.
% 存在量词选择调用次序，而全称条件保证每个兼容结果在每个前缀之后仍可完成。

\begin{lemma}[Largest safe execution set]
% 最大安全执行集合
\label{lem:largest-safe-family}
A safe execution set exists iff \(\mathsf{SafeEdit}(\Theta)\).
% 当且仅当 \(\mathsf{SafeEdit}(\Theta)\) 成立时，安全执行集合存在。
When the edit is safe, \((W^\dagger_{H,u},\widehat B^\dagger_{H,u})\) is a safe execution set, and every safe execution set \((L,\widehat B)\) satisfies \(\widehat B\subseteq\widehat B^\dagger_{H,u}\) and \(L\subseteq W^\dagger_{H,u}\).
% 当编辑安全时，\((W^\dagger_{H,u},\widehat B^\dagger_{H,u})\) 是安全执行集合，并且每个安全执行集合 \((L,\widehat B)\) 都满足 \(\widehat B\subseteq\widehat B^\dagger_{H,u}\) 和 \(L\subseteq W^\dagger_{H,u}\)。
\end{lemma}
\begin{proof}
The workflow, outcome, and policy conditions place every safe execution set's complete executions inside \(\widehat B_0\).
% 工作流、结果和策略条件使每个安全执行集合的完整执行都包含于 \(\widehat B_0\)。
The final condition makes this set post-fixed, so monotonicity and finite Knaster--Tarski place it inside \(\widehat B^\dagger\), and projected prefixes give \(L\subseteq W^\dagger\).
% 最后一项条件使该集合成为后不动点，因此由单调性和有限 Knaster--Tarski 可知其包含于 \(\widehat B^\dagger\)，而投影前缀给出 \(L\subseteq W^\dagger\)。
Conversely, \(\widehat B^\dagger=\widehat\Phi(\widehat B^\dagger)\) keeps every compatible outcome completable.
% 反之，\(\widehat B^\dagger=\widehat\Phi(\widehat B^\dagger)\) 保证每个兼容结果仍可完成。
At the empty prefix, this condition and the checked coverage witnesses from \cref{lem:history-derivation} establish \(\mathsf{PreservesRequired}\).
% 在空前缀处，该条件与 \cref{lem:history-derivation} 中经检查的覆盖见证共同建立 \(\mathsf{PreservesRequired}\)。
The inclusion \(\widehat B^\dagger\subseteq\widehat B_0\) ensures that complete executions follow the edited workflow and policy, while prefix closure of \(\mathcal A_u\) makes every allowed prefix safe.
% 包含关系 \(\widehat B^\dagger\subseteq\widehat B_0\) 保证完整执行遵守编辑后的工作流与策略，而 \(\mathcal A_u\) 的前缀闭包保证每个获准前缀安全。
Finally, \(W^\dagger=\Pref(\pi_2\widehat B^\dagger)\) gives a completion after every allowed prefix.
% 最后，\(W^\dagger=\Pref(\pi_2\widehat B^\dagger)\) 为每个获准前缀给出完成方式。
Hence the fixed point is a safe execution set exactly when nonempty.
% 因此，该不动点恰在非空时构成安全执行集合。
\end{proof}

\(\mathsf{MaxSafe}(\Theta;L,\widehat B)\) means that \((L,\widehat B)\) is safe and contains every other safe execution set.
% \(\mathsf{MaxSafe}(\Theta;L,\widehat B)\) 表示 \((L,\widehat B)\) 安全且包含每个其他安全执行集合。
When such a pair exists, write its unique value as \(\mathsf{SafeBehavior}(\Theta)\).
% 当这样的二元组存在时，将其唯一值记为 \(\mathsf{SafeBehavior}(\Theta)\)。
\Cref{lem:largest-safe-family} proves that this witness exists exactly when \(\widehat B^\dagger_{H,u}\ne\varnothing\) and then equals \((W^\dagger_{H,u},\widehat B^\dagger_{H,u})\).
% \Cref{lem:largest-safe-family} 证明该见证恰在 \(\widehat B^\dagger_{H,u}\ne\varnothing\) 时存在，并且此时等于 \((W^\dagger_{H,u},\widehat B^\dagger_{H,u})\)。

\subsubsection{Why Outcome-by-Outcome Checking Fails}
% 逐结果检查的反例

\Cref{sec:lifecycle} introduced the contract \(X\otimes(Y\oplus Z)\) under policy \(\Pref\{yx,xz\}\).
% \Cref{sec:lifecycle} 已介绍策略 \(\Pref\{yx,xz\}\) 下的契约 \(X\otimes(Y\oplus Z)\)。
For its annotated calls, write \(\bar x=\Fresh(x_o,d_x)\), \(\bar y=\Fresh(y_o,d_y)\), and \(\bar z=\Fresh(z_o,d_z)\).
% 对其带标注调用，记 \(\bar x=\Fresh(x_o,d_x)\)、\(\bar y=\Fresh(y_o,d_y)\) 和 \(\bar z=\Fresh(z_o,d_z)\)。
The candidate family initially contains \(\bar y\bar x\) and \(\bar x\bar z\).
% 初始候选族包含 \(\bar y\bar x\) 与 \(\bar x\bar z\)。
The first fixed-point iteration removes \(\bar x\bar z\).
% 第一次不动点迭代移除 \(\bar x\bar z\)。
The second iteration removes \(\bar y\bar x\), because after the first removal the empty prefix no longer has a completion for the \(X\otimes Z\) outcome.
% 第二次迭代移除 \(\bar y\bar x\)，因为第一次移除后，空前缀不再为 \(X\otimes Z\) 结果保留完成路径。
The empty fixed point is the formal reason the exact checker rejects.
% 空不动点就是精确检查器拒绝该编辑的形式原因。

\begin{proposition}[Exact correspondence with generalized nonblocking]
% 与广义非阻塞的精确对应
\label{prop:outcome-necessary}
For nonempty \(\widehat B\subseteq\widehat B_0\), let \(\mathcal T_{\widehat B}\) be the prefix trie of \(L_{\widehat B}=\Pref(\pi_2\widehat B)\).
% 对于非空的 \(\widehat B\subseteq\widehat B_0\)，令 \(\mathcal T_{\widehat B}\) 为 \(L_{\widehat B}=\Pref(\pi_2\widehat B)\) 的前缀字典树。
Mark state \(z\) by \(\mathsf{possible}_o\) exactly when \(o\in\mathsf{Compat}(z)\), and mark state \(y\) by \(\mathsf{done}_o\) exactly when \((o,y)\in\widehat B\).
% 当且仅当 \(o\in\mathsf{Compat}(z)\) 时用 \(\mathsf{possible}_o\) 标记状态 \(z\)，并且当且仅当 \((o,y)\in\widehat B\) 时用 \(\mathsf{done}_o\) 标记状态 \(y\)。
Then
% 则有以下等价关系：
\[
\begin{gathered}
 \widehat B\subseteq\widehat\Phi(\widehat B)\\[-2pt]
 \Longleftrightarrow\
 \forall o\in O_{H,u}.\;
 \mathcal T_{\widehat B}\text{ is }
 (\mathsf{possible}_o,\mathsf{done}_o)\text{-nonblocking}.
\end{gathered}
\]
Consequently, if \(\widehat B^\dagger\) is nonempty, it is the largest nonempty completion subfamily of \(\widehat B_0\) satisfying these outcome-specific nonblocking conditions.
% 因此，若 \(\widehat B^\dagger\) 非空，则它是 \(\widehat B_0\) 中满足这些特定于结果的非阻塞条件的最大非空完成路径子族。
If it is empty, no nonempty subfamily satisfies the conditions.
% 若它为空，则没有任何非空子族满足这些条件。
Ordinary marker nonblocking of the unaugmented projected language is strictly weaker.
% 未增广投影语言的普通标记非阻塞性严格更弱。
\end{proposition}
\begin{proof}
From reachable prefix \(z\), a \(\mathsf{done}_o\)-marked state is reachable exactly when some \((o,y)\in\widehat B\) extends \(z\).
% 从可达前缀 \(z\) 出发，当且仅当某个 \((o,y)\in\widehat B\) 扩展 \(z\) 时，才可到达一个带 \(\mathsf{done}_o\) 标记的状态。
Quantifying over exactly the states marked \(\mathsf{possible}_o\) is therefore the post-fixed-point condition.
% 因此，恰好对带 \(\mathsf{possible}_o\) 标记的状态进行量化就是后不动点条件。
Greatestness follows from the greatest-fixed-point construction.
% 最大性由最大不动点构造得到。
For strictness, the preceding instance has the marker-nonblocking projected pair \((\Pref\{\bar y\bar x,\bar x\bar z\}, \{\bar y\bar x,\bar x\bar z\})\), but its indexed fixed point is empty.
% 关于严格性，前述实例具有标记非阻塞的投影二元组 \((\Pref\{\bar y\bar x,\bar x\bar z\}, \{\bar y\bar x,\bar x\bar z\})\)，但其带索引不动点为空。
\end{proof}

\Cref{prop:outcome-necessary} relates the fixed point to generalized nonblocking after the trusted runtime has derived the outcome-specific completion conditions~\cite{dequeiroz2005multitasking,malik2008generalised}.
% \Cref{prop:outcome-necessary} 表明，在可信运行时推导出各结果的完成条件之后，该不动点与广义非阻塞相对应~\cite{dequeiroz2005multitasking,malik2008generalised}。
The trusted runtime derives those conditions from the requested edit, authorized removals, actions, authorization records, and the execution record.
% 可信运行时根据请求的编辑、获准移除、动作、授权记录和执行记录推导这些条件。
It also decides whether each protected call creates or reuses an authorization, computes every safe continuation or a rejection proof, and puts an accepted result into effect atomically.
% 它还判断每个受控调用是创建还是复用授权，计算全部安全继续方式或拒绝证明，并使接受的结果原子生效。

\subsubsection{Rejection Proofs}
% 拒绝证明

Each removed \((o_{\rm rem},y)\) records its rank \(i\), a prefix \(z\preceq y\), and uncovered \(o_{\rm miss}\in\mathsf{Compat}(z)\).
% 每个被移除的 \((o_{\rm rem},y)\) 记录其秩 \(i\)、前缀 \(z\preceq y\) 与未覆盖的 \(o_{\rm miss}\in\mathsf{Compat}(z)\)。
Induction shows that every post-fixed \(P\) is contained in every \(\widehat B_i\).
% 归纳表明每个后不动点 \(P\) 都包含于每个 \(\widehat B_i\)。
An empty final family therefore proves that no safe execution set exists.
% 因此，最终执行族为空证明不存在安全执行集合。
Before the rule update, the trusted runtime recomputes both the removal order and the remaining completions.
% 规则更新之前，可信运行时会重新计算删除顺序与剩余完成路径。

\subsubsection{Checking Again After a Permitted Prefix}
% 在获准前缀之后再次检查

To show that the checker can be applied again after each permitted partial execution, fix \(H,u,\mathcal A_u\) after deriving \(\mathcal C\), and write \(W^\dagger(\mathcal C,\Delta)\) and \(\widehat B^\dagger(\mathcal C,\Delta)\) with those parameters suppressed.
% 为证明检查器能在每段允许的部分执行之后再次应用，先在推导 \(\mathcal C\) 后固定 \(H,u,\mathcal A_u\)，再将省略这些参数的记法写作 \(W^\dagger(\mathcal C,\Delta)\) 和 \(\widehat B^\dagger(\mathcal C,\Delta)\)。
\begin{lemma}[Rechecking after a prefix]
% 在前缀之后重新检查
\label{lem:residual-coherence}
If \(z\in W^\dagger(\mathcal C,\Delta)\), then
% 若 \(z\in W^\dagger(\mathcal C,\Delta)\)，则：
\(\Resolve^{\rho'}_\Delta(\mathsf{raw}(z))=z\),
\(\mathsf{lab}(\Delta_z)=
 \mathsf{lab}(\Delta)\mathsf{auth}(z)\), and
\[
\begin{aligned}
 W^\dagger(\mathcal C,\Delta)/z
  &=W^\dagger(\mathcal C/\mathsf{raw}(z),\Delta_z),\\
 \widehat B^\dagger(\mathcal C,\Delta)/z
  &=\widehat B^\dagger(
      \mathcal C/\mathsf{raw}(z),\Delta_z),
\end{aligned}
\]
where
% 其中
\(\widehat B/z=\{(o,v)\mid(o,zv)\in\widehat B\}\).
\end{lemma}
\begin{proof}[Proof sketch]
% 证明概要。
Streaming resolution recovers the original calls, gives the authorization-log equality, and makes the candidate executions after \(z\) identical on both sides.
% 流式解析恢复原始调用，给出授权日志等式，并使 \(z\) 之后两侧的候选执行相同。
Removing prefix \(z\) from \(\widehat B^\dagger\) gives a post-fixed family for the next check, while adding \(z\) to any such family gives one for the original check.
% 从 \(\widehat B^\dagger\) 中移除前缀 \(z\) 会得到下一次检查的后不动点族，而给任何这样的族加上 \(z\) 会得到原检查的后不动点族。
Greatestness yields the fixed-point equality, and \(\Pref(B)/z=\Pref(B/z)\) yields the generated-language equality.
% 最大性给出不动点等式，且 \(\Pref(B)/z=\Pref(B/z)\) 给出生成语言等式。
The full proof is in \cref{app:residual-coherence-proof}.
% 完整证明见 \cref{app:residual-coherence-proof}。
\end{proof}
Thus every accepted prefix retains a safe completion for every outcome that remains compatible with that prefix.
% 因此，每个被接受的前缀都会为仍与该前缀兼容的每个结果保留一条安全完成路径。

\subsubsection{Checker Outputs}
% 检查器输出

The checker returns \(\mathsf{Invalid}\) when derivation fails, \(\mathsf{Reject}\) with the ordered reasons for removing every execution when the fixed point is empty, and \(\mathsf{Accepted}\) with the largest safe execution set otherwise.
% 当推导失败时，检查器返回 \(\mathsf{Invalid}\)；当不动点为空时，返回 \(\mathsf{Reject}\) 以及删除每段执行的有序理由；否则返回携带最大安全执行集合的 \(\mathsf{Accepted}\)。
Write \(\mathsf{Check}(\Theta)\) for this deterministic output.
% 将这一确定性输出记为 \(\mathsf{Check}(\Theta)\)。
Each answer includes a digest of the execution record that was checked.
% 每个判定结果都包含所检查执行记录的摘要。
\Cref{app:returned-data} gives the exact returned data and verification rules.
% \Cref{app:returned-data} 给出精确返回数据与验证规则。
\Cref{prop:app-output-complexity} proves an output-sensitive \(O(D+n\Lambda+|\mathcal G_{\rm cov}|+V_B\log(2+V_B))\)-time, \(O(D+\Lambda+|\mathcal G_{\rm cov}|)\)-space bound.
% \Cref{prop:app-output-complexity} 证明一种输出敏感的 \(O(D+n\Lambda+|\mathcal G_{\rm cov}|+V_B\log(2+V_B))\) 时间、\(O(D+\Lambda+|\mathcal G_{\rm cov}|)\) 空间界。
Exponential growth occurs only in explicitly emitted linearizations and prefix--required-outcome support pairs.
% 指数增长只出现在显式输出的线性化和前缀--要求实现结果支持对中。
