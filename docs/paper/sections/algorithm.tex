\section{Building and Installing the Runtime Monitor}
% 构造并安装运行时监控器
\label{sec:kernel}

The safety checker produces either an impossibility certificate or the largest safe family of completed executions.
% 安全检查器生成不可能性证书或最大的安全完整执行族。
The installation kernel turns a nonempty family into runtime enforcement in three steps.
% 安装内核分三步将非空执行族转化为运行时强制执行。
It builds a monitor for the family's partial executions, binds that monitor to the authenticated source snapshot, and atomically installs it under a new monitor version.
% 它为该执行族的部分执行构造监控器，将监控器绑定到认证源状态快照，并在新的监控器版本下原子安装。
The rules below serialize every overlapping protected call either before or after installation.
% 下列规则将每个重叠的受控调用完整地排列在安装之前或之后。

\subsection{Building an occurrence-sensitive monitor}
% 构造发生项敏感监控器

The greatest realization has the finite, canonically installable projected pair \((W,B)=(W^\dagger_{H,u},B^\dagger_{H,u})\).
% 最大实现具有有限且可规范安装的投影对 \((W,B)=(W^\dagger_{H,u},B^\dagger_{H,u})\)。
For \(L/z=\{v\mid zv\in L\}\), use residual states \(q_z=(W^\dagger/z,B^\dagger/z)\).
% 对于 \(L/z=\{v\mid zv\in L\}\)，使用残余状态 \(q_z=(W^\dagger/z,B^\dagger/z)\)。
\begin{equation}
\label{eq:canonical-program}
\begin{aligned}
 Q_{W,B} &= \{q_z\mid z\in W\},\\
 q^0&=q_\epsilon=(W^\dagger,B^\dagger),\\
 q_z\xrightarrow{a}q_{za}
 &\quad\Longleftrightarrow\quad za\in W .
\end{aligned}
\end{equation}
Call this monitor automaton \(\mathsf{Can}(W,B)\).
% 将该监控器自动机记作 \(\mathsf{Can}(W,B)\)。
Every state is reachable and is marked exactly when \(\epsilon\in B^\dagger/z\).
% 每个状态均可达，并且恰在 \(\epsilon\in B^\dagger/z\) 时被标记。
Each transition symbol \(a\) contains occurrence \(x\), effect identity \(d\), and its \Fresh or \Alias mode, so one call position cannot use another position's monitor entry.
% 每个转移符号 \(a\) 都包含发生项 \(x\)、效果标识 \(d\) 以及 \Fresh/\Alias 模式，因此一个调用位置无法使用另一个位置的监控器入口。

\begin{lemma}[Exact compiled realization]
% 精确的编译实现
\label{lem:compiled-language}
The generated and marked languages of the program in \cref{eq:canonical-program} are exactly \((W^\dagger_{H,u},B^\dagger_{H,u})\).
% \cref{eq:canonical-program} 中程序的生成语言和标记语言恰为 \((W^\dagger_{H,u},B^\dagger_{H,u})\)。
The program is the smallest deterministic marked partial automaton for this pair up to state renaming.
% 在忽略状态重命名的意义下，该程序是实现这对语言的最小确定性标记偏自动机。
\end{lemma}
\begin{proof}
Induction on \(z\) shows that the automaton reaches \((W^\dagger/z,B^\dagger/z)\), enables \(a\) iff \(za\in W^\dagger\), and marks the reached state iff \(z\in B^\dagger\).
% 对 \(z\) 的归纳表明，该自动机到达 \((W^\dagger/z,B^\dagger/z)\)，当且仅当 \(za\in W^\dagger\) 时启用 \(a\)，并且当且仅当 \(z\in B^\dagger\) 时标记所到达的状态。
Distinct states differ on a generated or marked suffix and must remain distinct.
% 不同状态在某个生成后缀或标记后缀上存在差异，因此必须保持不同。
The automaton is the paired-language derivative construction~\cite{brzozowski1964derivatives}.
% 该自动机是成对语言的导数构造~\cite{brzozowski1964derivatives}。
\end{proof}

For \(\Theta=(\kappa,H,\Delta,\mathsf{out},\mathcal A,u)\), let \(\gamma(\Theta)=\mathsf{Seal}_{\rm cut}(\mathsf{enc}(\mathsf{request},\omega,\zeta,\kappa,H,\Delta,\mathsf{out},\mathcal A,u))\) bind an answer to its source snapshot.
% 对于 \(\Theta=(\kappa,H,\Delta,\mathsf{out},\mathcal A,u)\)，令 \(\gamma(\Theta)=\mathsf{Seal}_{\rm cut}(\mathsf{enc}(\mathsf{request},\omega,\zeta,\kappa,H,\Delta,\mathsf{out},\mathcal A,u))\) 将答案绑定到其源状态快照。
\[
\begin{aligned}
\mathsf{CheckOutput}(\Theta)::={}&\mathsf{Invalid}([\gamma,C_{\rm str}]_{\cong})
\mid\mathsf{Reject}([\gamma,C_{\rm fp}]_{\cong})\\
&\mid\mathsf{Installable}(\delta,W^\dagger,\widehat B^\dagger,Z).
\end{aligned}
\]
\(\mathsf{Compile}(\Theta)\) returns \(\mathsf{Invalid}\) with a verified invalid-edit transcript if derivation is undefined.
% 若推导未定义，\(\mathsf{Compile}(\Theta)\) 返回带经验证无效编辑记录的 \(\mathsf{Invalid}\)。
It returns \(\mathsf{Reject}\) with the complete ranked rejection certificate if \(\widehat B^\dagger=\varnothing\).
% 若 \(\widehat B^\dagger=\varnothing\)，它返回带完整带秩拒绝证书的 \(\mathsf{Reject}\)。
Otherwise, it returns \(\mathsf{Installable}\) with the unique \(\delta\), coverage witnesses, monitor automaton \(\mathsf{prog}_Z=\mathsf{Can}(W^\dagger,B^\dagger)\), and
% 否则，它返回带唯一 \(\delta\)、覆盖见证、监控器自动机 \(\mathsf{prog}_Z=\mathsf{Can}(W^\dagger,B^\dagger)\) 以及下述内容的 \(\mathsf{Installable}\)
\[
 Z=(\omega,\zeta,\kappa_Z,\mathsf{cut}_Z,u,
    H_{\mathsf{prog}},\eta^-,\eta^+),
\]
where \(\kappa_Z=\kappa\), \(H_c=H\) is the authenticated source record, and the edit derivation creates \(\eta^+\).
% 其中 \(\kappa_Z=\kappa\)，\(H_c=H\) 是认证源记录，而编辑推导创建 \(\eta^+\)。
Canonical encoding order makes all three finite checker outputs unique and equivariant.
% 规范编码顺序使三种有限检查器输出均唯一且保持等变性。
The bounded implementation may instead return \(\mathsf{ResourceLimit}(b,n)\), which installs nothing and proves neither safety nor impossibility.
% 有界实现可能改为返回 \(\mathsf{ResourceLimit}(b,n)\)，它不安装任何内容，也不证明安全性或不可能性。

Let \(\mathsf{enc}\) be canonical and length-delimited, with \(\kappa\) authenticating \(\mathcal A\).
% 令 \(\mathsf{enc}\) 为规范且带长度分隔的编码，并由 \(\kappa\) 认证 \(\mathcal A\)。
The symbolic LTS uses domain-separated injective authenticated constructors \(\mathsf{Seal}_{\rm prog}\) and \(\mathsf{Seal}_{\rm cut}\), so equal seals have equal payloads.
% 符号 LTS 使用域分离、单射且经认证的构造器 \(\mathsf{Seal}_{\rm prog}\) 和 \(\mathsf{Seal}_{\rm cut}\)，因此相同封印具有相同载荷。
Define
% 定义
\[
 H_{\mathsf{prog}}=
 \mathsf{Seal}_{\rm prog}(
   \mathsf{enc}(\mathsf{prog}_Z,\widehat B^\dagger_{H,u})).
\]
The source-snapshot seal is
% 源状态快照封印为
\begin{equation}
\label{eq:cut-seal}
\begin{split}
 \mathsf{cut}_Z=
 \mathsf{Seal}_{\rm cut}(\mathsf{enc}(&\omega,\zeta,\kappa,H,\Delta,
     \mathsf{out},u,\mathcal C_{H,u},\\[-2pt]
     &H_{\mathsf{prog}},\eta^-,\eta^+)).
\end{split}
\end{equation}
Because \(H\) contains \(\chi,\nu,\rho,\beta\), the source-snapshot seal binds workflow progress, record version, registry state, and monitor-entry/version bindings.
% 由于 \(H\) 包含 \(\chi,\nu,\rho,\beta\)，该源状态快照封印绑定工作流推进、记录版本、注册表状态和监控器入口/版本绑定。
It also binds the receipt log and dispatch queue directly.
% 它还直接绑定回执日志与派发队列。
Search and inactive preloading remain untrusted because the installation checker re-derives the schema judgment and complete indexed fixed point, reconstructs \((W^\dagger,B^\dagger)\), verifies both seals, and checks
% 搜索和非活跃预加载仍不受信任，因为安装检查器会重新推导模式判定和完整的带索引不动点，重建 \((W^\dagger,B^\dagger)\)，验证两个封印，并检查
\[
 \mathsf{prog}_Z\cong\mathsf{Can}(W^\dagger,B^\dagger),
\]
as a full automaton isomorphism preserving the initial state, marking, and every labeled transition.
% 其是否为保持初始状态、标记及每个带标签转移的完整自动机同构。
A byte implementation may use signatures or collision-resistant digests over \(\mathsf{enc}\), yielding computational refinement up to forgery or collision, while exact bisimulation uses the symbolic constructors.
% 字节级实现可对 \(\mathsf{enc}\) 使用签名或抗碰撞摘要，从而得到除伪造或碰撞外的计算精化，而精确互模拟使用符号构造器。

\subsection{Installation kernel}
% 安装内核

The compiled state for one policy domain is
% 一个策略域的编译状态为
\[
S=(\kappa,H,\Delta,\mathsf{out},\mathcal A,
    \mathsf{phase},\mathsf{bind},\mathsf{prog},\mathsf q,\mathsf{cert}),
\]
where \(\mathsf{phase}\) records whether each monitor version \(\eta\) is unallocated (\(\bot\)), inactive, active, or closed.
% 其中 \(\mathsf{phase}\) 记录每个监控器版本 \(\eta\) 是未分配（\(\bot\)）、非活动、活动还是已关闭。
Reserve \(u=\mathsf{Root}(R,n)\) for bootstrap only.
% 保留 \(u=\mathsf{Root}(R,n)\) 仅用于引导。
The root rule is enabled only when \(\mathsf{CheckReg}(\mathcal W,R)\) accepts a finite-state boundary-finite typed Agent workflow \(\mathcal W\) and finite registered call model \(R\).
% 只有当 \(\mathsf{CheckReg}(\mathcal W,R)\) 接受有限状态且边界有限的类型化 Agent 工作流 \(\mathcal W\) 与有限已注册调用模型 \(R\) 时，根规则才启用。
The deterministic judgment \(\mathsf{Reg}(R,n)\vdash\mathsf{Root}\Downarrow(H_R^+,\mathcal C_R,\bot,\eta_R)\) constructs \(\mathsf{src}_R^-=(\kappa,H_R^-,\epsilon,\epsilon,\mathcal A)\) from registered call model \(R\) and private namespace \(n\), with empty progress, checkpoints, bindings, and monitor version, sets \(\mathsf{Req}_{\mathsf{Root}}\) to \(R\)'s root outcomes, and defines \(\mathsf{Lift}_{\mathsf{Root}}(t,o)\Longleftrightarrow t=o\).
% 确定性判定 \(\mathsf{Reg}(R,n)\vdash\mathsf{Root}\Downarrow(H_R^+,\mathcal C_R,\bot,\eta_R)\) 从已注册调用模型 \(R\) 和私有命名空间 \(n\) 构造 \(\mathsf{src}_R^-=(\kappa,H_R^-,\epsilon,\epsilon,\mathcal A)\)，其中进度、检查点、绑定和监控器版本均为空；它将 \(\mathsf{Req}_{\mathsf{Root}}\) 设为 \(R\) 的根结果，并定义 \(\mathsf{Lift}_{\mathsf{Root}}(t,o)\Longleftrightarrow t=o\)。
The checked record \(\mathsf{cert}(\eta)=c=(\mathsf{src}_c,H_c^+,u,W,\widehat B,Z)\) contains source snapshot \(\mathsf{src}_c=(\kappa,H_c,\Delta_c,\mathsf{out}_c,\mathcal A)\), target state \(H_c^+\) before any protected call, and ideal projection \(\mathsf{icut}(c)=(H_c,u,W,\widehat B)\).
% 经检查记录 \(\mathsf{cert}(\eta)=c=(\mathsf{src}_c,H_c^+,u,W,\widehat B,Z)\) 包含源状态快照 \(\mathsf{src}_c=(\kappa,H_c,\Delta_c,\mathsf{out}_c,\mathcal A)\)、任何受控调用前的目标状态 \(H_c^+\)，以及理想投影 \(\mathsf{icut}(c)=(H_c,u,W,\widehat B)\)。
Its tagged origin is the checked root judgment exactly when \(u=\mathsf{Root}(R,n)\) and \(\mathsf{src}_c=\mathsf{src}_R^-\); otherwise it is the checked derivation of one of the six execution edits or a registered extension.
% 当且仅当 \(u=\mathsf{Root}(R,n)\) 且 \(\mathsf{src}_c=\mathsf{src}_R^-\) 时，其带标签来源为经检查根判定；否则，它是六种执行编辑之一或已注册扩展的经检查推导。
Its indexed family appears only in the proof, while \(W^\dagger\), \(B^\dagger\), and the seal are checked enforcement data.
% 其带索引族只出现在证明中，而 \(W^\dagger\)、\(B^\dagger\) 和封印是经检查的强制执行数据。
\(\mathsf{Gen}(P,q)\) and \(\mathsf{Mark}(P,q)\) denote \(P\)'s generated and marked languages from \(q\).
% \(\mathsf{Gen}(P,q)\) 和 \(\mathsf{Mark}(P,q)\) 表示 \(P\) 从 \(q\) 出发的生成语言和标记语言。

\begin{definition}[Agent security-state invariant]
% Agent 安全状态不变量
\label{def:agent-sec}
For \(c=(\mathsf{src}_c,H_c^+,u,W,\widehat B,Z)\) and resolved \(r\), \(\mathsf{AgentSec}(S;c,r)\) holds exactly when the following clauses hold.
% 对 \(c=(\mathsf{src}_c,H_c^+,u,W,\widehat B,Z)\) 和已解析词 \(r\)，当且仅当下列条款成立时，\(\mathsf{AgentSec}(S;c,r)\) 成立。
\begin{enumerate}[leftmargin=*,itemsep=1pt]
\item \emph{Core and schema coherence.}
% 核心与模式一致性。
The current security state is well formed, \(c=\mathsf{cert}(\eta)\), and the tagged origin derives \((H_c^+,\mathcal C,\eta^-,\eta)\) by its corresponding checked root, execution-edit, or registered-extension judgment; each \(a\in\mathsf{Req}_u\) has a checked full-target \(\mathsf{Lift}_u\) witness.
% 当前安全状态良构，\(c=\mathsf{cert}(\eta)\)，且带标签来源通过相应的经检查根判定、执行编辑判定或已注册扩展判定推导出 \((H_c^+,\mathcal C,\eta^-,\eta)\)；每个 \(a\in\mathsf{Req}_u\) 都有经检查的完整目标 \(\mathsf{Lift}_u\) 见证。
\item \emph{Required-outcome coherence.}
% 要求实现结果的一致性。
\(\widehat B=\widehat B^\dagger_{H_c,u}\ne\varnothing\), \(W=\Pref(\pi_2\widehat B)\), and the stored certificate passed \(\mathsf{Verify}_Z(W,\pi_2\widehat B,\widehat B)\) at its source snapshot.
% \(\widehat B=\widehat B^\dagger_{H_c,u}\ne\varnothing\)、\(W=\Pref(\pi_2\widehat B)\)，并且所存证书已在其源状态快照处通过 \(\mathsf{Verify}_Z(W,\pi_2\widehat B,\widehat B)\)。
\item \emph{Execution coherence.}
% 执行一致性。
\((H.G,H.T)=\mathsf{HRes}((H_c^+.G,H_c^+.T),r)\), \(H.\chi=H_c^+.\chi\,r\), \(\mathsf{lab}(\Delta)=\mathsf{lab}(\Delta_c)\mathsf{auth}(r)\), and each occurrence in \(r\) appears once in \(\chi\).
% \((H.G,H.T)=\mathsf{HRes}((H_c^+.G,H_c^+.T),r)\)，\(H.\chi=H_c^+.\chi\,r\)，\(\mathsf{lab}(\Delta)=\mathsf{lab}(\Delta_c)\mathsf{auth}(r)\)，且 \(r\) 中每个发生项都在 \(\chi\) 中出现一次。
Each \Fresh has its unique receipt and ordered dispatch-queue entry, each \Alias names an earlier receipt, receipt phases and releases advance only monotonically, and \(K\) differs from \(H_c^+.K\) only by authenticated \(\mathsf{Save}\) extensions.
% 每个 \Fresh 都有其唯一回执和有序派发队列条目，每个 \Alias 都指明更早的回执，回执阶段和释放仅单调推进，且 \(K\) 与 \(H_c^+.K\) 的差异仅为经认证的 \(\mathsf{Save}\) 扩展。
\item \emph{Monitor coherence.}
% 监控器一致性。
For \(B=\pi_2\widehat B\), checked installation gives \(\mathsf{prog}(\eta)\cong\mathsf{Can}(W,B)\) and makes \(\mathsf q(\eta)\) correspond to canonical derivative \(q_r=(W/r,B/r)\).
% 对 \(B=\pi_2\widehat B\)，经检查的安装给出 \(\mathsf{prog}(\eta)\cong\mathsf{Can}(W,B)\)，并使 \(\mathsf q(\eta)\) 对应规范导数 \(q_r=(W/r,B/r)\)。
\item \emph{Monitor-version coherence.}
% 监控器版本一致性。
Only \(\eta\) is active.
% 仅 \(\eta\) 处于活跃状态。
Each current occurrence has exactly one authenticated monitor entry and authorization token bound to \(\eta\).
% 每个当前发生项都具有绑定到 \(\eta\) 的唯一认证监控器入口和授权令牌。
Inactive monitor versions expose no authorization token.
% 非活动监控器版本不暴露授权令牌。
Closed monitor versions never reactivate.
% 已关闭监控器版本永不重新激活。
Each target monitor version deterministically minted from the current source snapshot for a registered request is unallocated or inactive and unbound.
% 根据当前源状态快照为已注册请求确定性生成的每个目标监控器版本都未分配，或处于非活动且未绑定状态。
\end{enumerate}
\end{definition}
The full system starts from one empty initial state, accepts a checked finite registration containing only contracts, schemas, policy, and authenticated identity rows, and then performs root installation to construct empty receipt, cursor, and dispatch-queue state together with the first monitor version, its certificate, and its monitor.
% 完整系统从唯一的空初始状态开始，接受一个只包含契约、模式、策略和经认证标识行的经检查有限注册，随后执行根安装，以构造空的回执、游标和派发队列状态，以及第一个监控器版本、其证书和监控器。
Registration cannot supply runtime fields, while every later installed state is produced by an execution-edit derivation or a registered extension.
% 注册过程不能提供运行时字段，而此后的每个已安装状态都由执行编辑推导或已注册扩展产生。

\paragraph{Atomic protected call}
% 原子受控调用
For submitted tool request \(m\), set \(m^\circ=\mathsf{canon}_\kappa(m)\).
% 对于提交的工具请求 \(m\)，令 \(m^\circ=\mathsf{canon}_\kappa(m)\)。
For \(x\) bound to monitor entry \(j\) in version \(\eta\), \(\mathsf{VerifyHandle}(h,\rho(x),j,d,m^\circ)\) verifies the call-authorizing service, scope, monitor entry, effect identity, lineage, and signed digest and requires \(m^\circ=\mathsf{inv}_\rho(d)\).
% 对于版本 \(\eta\) 中绑定到监控器入口 \(j\) 的 \(x\)，\(\mathsf{VerifyHandle}(h,\rho(x),j,d,m^\circ)\) 验证调用授权服务、作用域、监控器入口、效果标识、谱系和签名摘要，并要求 \(m^\circ=\mathsf{inv}_\rho(d)\)。
Set \(a=\Fresh(x,d)\) if \(d\notin D_\Delta\), otherwise \(a=\Alias(x,d)\), and let \(\Use_x(m)=\mathsf{Use}(x,j,h,m)\).
% 若 \(d\notin D_\Delta\)，则令 \(a=\Fresh(x,d)\)，否则令 \(a=\Alias(x,d)\)，并令 \(\Use_x(m)=\mathsf{Use}(x,j,h,m)\)。
Its sole durable transition is the rule below.
% 其唯一持久转移是下列规则。
\begin{equation}
\label{eq:use-rule}
\frac{
\begin{gathered}
 x\text{ enabled in }T\quad
 \mathsf{bind}(x)=(j,\eta)\\[-2pt]
 \eta=H.\mathsf{epoch}\quad
 \mathsf{phase}(\eta)=\mathsf{active}\\[-2pt]
 \mathsf{VerifyHandle}(h,\rho(x),j,d,m^\circ)\quad
 \mathsf q(\eta)\xrightarrow{a}_{\mathsf{prog}(\eta)}q'
\end{gathered}}
{S\xrightarrow{\Use_x(m)/a}S'} .
\end{equation}
The unique structured residual \(T/(x,a)\) removes \(x\) from its leaf contract, selects the containing arm beneath an open choice, and preserves every workflow constructor.
% 唯一结构化残余 \(T/(x,a)\) 从其叶契约移除 \(x\)，在开放选择下选中包含 \(x\) 的分支，并保留每个工作流构造器。
The paired update \(\mathsf{HStep}((G,T),a)\) also appends \(a\) to the unique current branch cursor.
% 成对更新 \(\mathsf{HStep}((G,T),a)\) 还会把 \(a\) 追加到唯一的当前分支游标。
\(\mathsf{Advance}(S,x,a,q')\) changes exactly the fields below.
% \(\mathsf{Advance}(S,x,a,q')\) 仅修改下列字段。
\[
\begin{aligned}
 (H.G,H.T)&:=\mathsf{HStep}((G,T),a),&
 H.\chi&:=\chi a,\\
 H.\nu&:=\nu+1,& H.\beta&:=\beta\setminus\{x\},\\
 \mathsf{bind}&:=\mathsf{bind}\setminus\{x\},&
 \mathsf q(\eta)&:=q'.
\end{aligned}
\]
In addition, \Fresh appends the immutable labeled receipt and ordered dispatch-queue item \((d,\mathsf{inv}_\rho(d))\), never an unchecked caller buffer.
% 此外，\Fresh 追加不可变的带标签回执和有序派发队列条目 \((d,\mathsf{inv}_\rho(d))\)，绝不存储未经检查的调用方缓冲区。
\Alias records the effect identity's durable return link without changing \(\Delta\), and all other fields remain unchanged.
% \Alias 记录该效果标识的持久返回链接且不改变 \(\Delta\)，其余字段保持不变。

An already-resolved \(x\) is a \Retry exactly when \(\mathsf{VerifyRetry}(h,x,j,d,m^\circ,\chi,\Delta)\) authenticates the same normalized tool request through the archived \(\chi\)-to-receipt link.
% 已解析的 \(x\) 当且仅当 \(\mathsf{VerifyRetry}(h,x,j,d,m^\circ,\chi,\Delta)\) 通过归档的从 \(\chi\) 到回执链接认证同一规范化工具请求时才构成 \Retry。
If the linked return record contains stable value \(v\) under its authenticated reply token \(t\), success is the state-preserving observable transition \(S\xrightarrow{\mathsf{Return}(t,[v]_{\cong})}S\).
% 若所链接的返回记录在其认证回复令牌 \(t\) 下包含稳定值 \(v\)，则成功是保持状态的可观测转移 \(S\xrightarrow{\mathsf{Return}(t,[v]_{\cong})}S\)。
For unresolved \(x\), \cref{eq:use-rule} applies exactly when all premises hold, while a missing transition, invalid authorization token, unbound occurrence, disabled branch, or closed monitor version returns \(\mathsf{deny}(x)\) without changing state.
% 对未解析的 \(x\)，当且仅当全部前提成立时才应用 \cref{eq:use-rule}，而缺失转移、无效授权令牌、未绑定发生项、禁用分支或已关闭监控器版本都会返回 \(\mathsf{deny}(x)\) 且不改变状态。
\Dispatch releases exactly the stored normalized tool request in the oldest dispatch-queue item.
% \Dispatch 恰好释放最早派发队列条目中存储的规范化工具请求。
Settlement preserves \(\mathsf{AgentSec}\) and its permission trace, and crash is a state self-loop.
% 结算保持 \(\mathsf{AgentSec}\) 及其权限轨迹，而崩溃是状态自环。
Here \(\Dispatch\) is the durable local release of a queued request, not evidence of exactly-once execution by a remote service.
% 此处的 \(\Dispatch\) 是排队请求的持久本地释放，而不是远程服务恰好执行一次的证据。

\subsubsection{Answer verification and atomic installation}
% 答案验证与原子安装
At its linearization point, the kernel ignores any caller-supplied replacement workflow or monitor version, sets \(\Theta_S(u)=(\kappa,H,\Delta,\mathsf{out},\mathcal A,u)\), and re-runs \(\mathsf{Derive}(\Theta_S(u))\) from the current state.
% 在其线性化点，内核忽略调用方提供的任何替代工作流或监控器版本，令 \(\Theta_S(u)=(\kappa,H,\Delta,\mathsf{out},\mathcal A,u)\)，并根据当前状态重新执行 \(\mathsf{Derive}(\Theta_S(u))\)。
\(\mathsf{VerifyInv}\) accepts exactly a current \(\gamma\), an undefined derivation, and a verified invalid-edit transcript.
% \(\mathsf{VerifyInv}\) 恰好接受当前 \(\gamma\)、未定义推导和经验证无效编辑记录。
In contrast, \(\mathsf{VerifyRej}\) accepts exactly a current \(\gamma\), a defined derivation, an empty fixed point, and a ranked rejection certificate.
% 相比之下，\(\mathsf{VerifyRej}\) 恰好接受当前 \(\gamma\)、已定义推导、空不动点和带秩拒绝证书。
Both read-only transactions preserve state and emit the corresponding \(\mathsf{Invalid}\) or \(\mathsf{Reject}\) label.
% \(\mathsf{VerifyInv}\) 恰好接受当前 \(\gamma\)、未定义推导与规范检查失败记录，而 \(\mathsf{VerifyRej}\) 恰好接受当前 \(\gamma\)、已定义推导、空不动点与规范淘汰链；它们的只读事务发出相应的 \(\mathsf{Invalid}\) 或 \(\mathsf{Reject}\) 标签并保持状态。
For the positive case, write \(\mathsf{Derive}(\Theta_S(u))=(\kappa_u,H_u,\mathcal A_u,\mathcal C_u,\eta^-,\eta^+)\).
% 对于正面情形，记 \(\mathsf{Derive}(\Theta_S(u))=(\kappa_u,H_u,\mathcal A_u,\mathcal C_u,\eta^-,\eta^+)\)。
\(\mathsf{ReCut}(S,u,Z)\) is undefined without this root, execution-edit, or registered-extension derivation and otherwise recomputes the right-hand side of \cref{eq:cut-seal}.
% 若无这一根推导、执行编辑推导或已注册扩展推导，则 \(\mathsf{ReCut}(S,u,Z)\) 未定义；否则，它重新计算 \cref{eq:cut-seal} 的右侧。
\(\mathsf{Verify}_Z(W,B,\widehat B)\) holds exactly when the trusted checker (1) recomputes \(\widehat B_0\) and every fixed-point iteration, (2) verifies all ranked removal causes and surviving coverage witnesses, (3) checks the stabilized \(\widehat B\ne\varnothing\), (4) reconstructs \(B=\pi_2\widehat B\) and \(W=\Pref(B)\), (5) establishes \(\mathsf{prog}_Z\cong\mathsf{Can}(W,B)\), and (6) verifies the program seal.
% 当且仅当可信检查器执行以下操作时，\(\mathsf{Verify}_Z(W,B,\widehat B)\) 成立：(1) 重新计算 \(\widehat B_0\) 及每次不动点迭代；(2) 验证全部带秩的移除原因和幸存覆盖见证；(3) 检查稳定后的 \(\widehat B\ne\varnothing\)；(4) 重建 \(B=\pi_2\widehat B\) 与 \(W=\Pref(B)\)；(5) 建立 \(\mathsf{prog}_Z\cong\mathsf{Can}(W,B)\)；以及 (6) 验证程序封印。
Installation requires
% 安装要求
\begin{equation}
\label{eq:install-premise}
\begin{gathered}
 \kappa=\kappa_Z,\qquad
 \mathsf{ReCut}(S,u,Z)=\mathsf{cut}_Z,\\
 \mathsf{Verify}_Z(W^\dagger_{H,u},B^\dagger_{H,u},
    \widehat B^\dagger_{H,u}),\\
 H.\mathsf{epoch}=\eta^-,\qquad
 \mathsf{phase}(\eta^+)\in\{\bot,\mathsf{inactive}\}.
\end{gathered}
\end{equation}
\(\mathsf{Ready}(S,u,Y)\) holds when \(Y=\mathsf{Installable}(\delta,W^\dagger,\widehat B^\dagger,Z)\), the current derivation is \(\delta\), and all state-dependent premises of \cref{eq:install-premise} hold in \(S\).
% 当 \(Y=\mathsf{Installable}(\delta,W^\dagger,\widehat B^\dagger,Z)\)、当前推导为 \(\delta\) 且 \cref{eq:install-premise} 的全部状态相关前提在 \(S\) 中成立时，\(\mathsf{Ready}(S,u,Y)\) 成立。
If these premises hold, one domain transaction verifies that every target binding in \(H_u\) names a new monitor entry owned by \(\eta^+\) and every replacement triple in \(\mathcal H_u^+\) passes the authorization-token check against \(\rho_u\) and its registered effect identity.
% 若这些前提成立，一个域事务便验证 \(H_u\) 中的每个目标绑定均指向由 \(\eta^+\) 拥有的新监控器入口，并验证 \(\mathcal H_u^+\) 中的每个替换三元组均依据 \(\rho_u\) 及其注册效果标识通过授权令牌检查。
Let \(c^+=(\mathsf{src}(\Theta_S(u)),H_u,u,W^\dagger,\widehat B^\dagger,Z)\).
% 令 \(c^+=(\mathsf{src}(\Theta_S(u)),H_u,u,W^\dagger,\widehat B^\dagger,Z)\)。
It then applies
% 随后应用
\[
\begin{aligned}
 \kappa&:=\kappa_u,& \mathcal A&:=\mathcal A_u,\\
 H&:=H_u,&
 \mathsf{phase}(\eta^-)&:=\mathsf{closed},\\
 \mathsf{phase}(\eta^+)&:=\mathsf{active},&
 \mathsf{bind}|_{X_{\sem{H_u.T}}}&:=H_u.\beta,\\
 \mathsf{prog}(\eta^+)&:=\mathsf{prog}_Z,&
 \mathsf q(\eta^+)&:=q^0,\\
 \mathsf{cert}(\eta^+)&:=c^+.
\end{aligned}
\]
The transaction preserves unrelated inactive or closed records, exposes \(\mathcal H_u^+\) only after \(\eta^+\) becomes active, and lets recovery retrieve a lost reply from the durable target registry.
% 该事务保留无关的非活跃或已关闭记录，仅在 \(\eta^+\) 激活后公开 \(\mathcal H_u^+\)，并让恢复过程从持久目标注册表取回丢失的回复。
Old authorization tokens for unresolved occurrences fail the refreshed registry and monitor-entry check, whereas same-invocation \Retry follows its archived \(\chi\)-to-receipt link.
% 未解析发生项的旧授权令牌无法通过更新后的注册表与监控器入口检查，而同调用 \Retry 沿其已归档的从 \(\chi\) 到回执链接。
Success is observed as \(\mathsf{Edge}(u,[\mathcal H_u^+]_{\cong})\), returning the schema-determined authorization tokens up to consistent renaming of private identifiers.
% 成功被观测为 \(\mathsf{Edge}(u,[\mathcal H_u^+]_{\cong})\)，并在私有标识一致重命名的意义下返回由模式决定的授权令牌。
A stale or malformed precomputed candidate emits no answer, is discarded as an internal stutter, and must be recomputed against the current source snapshot before any visible response.
% 过期或畸形的预计算候选不会发出答案，而是作为内部停顿被丢弃，并且必须针对当前源状态快照重新计算后才能产生任何可见响应。

\(\mathsf{Preload}(\eta,Z)\) is a \(\tau\)-step that may allocate an unallocated monitor version or change an inactive, unbound one, and it leaves that version inactive.

\begin{lemma}[Edit--call serialization]
% 编辑--调用串行化
\label{lem:cut-linearization}
In every reachable well-formed compiled state, a visible edit answer and a protected call in the same policy domain have a unique order at the installation point.
% 在每个可达的良构编译状态中，同一策略域内的一项可见编辑答案与一次受控调用在安装点具有唯一顺序。
If the use commits first, that seal cannot install.
% 若该使用先提交，则该封印无法安装。
If \Install commits first, the old use cannot resolve \Fresh or \Alias.
% 若 \Install 先提交，则旧使用无法解析 \Fresh 或 \Alias。
Steps in independent domains commute by product semantics.
% 独立域中的步骤依据乘积语义可交换。
\end{lemma}
\begin{proof}
Prior \Fresh/\Alias invalidates every old source-snapshot seal, while prior installation closes the old monitor version.
% 先发生的 \Fresh/\Alias 会使每个旧源状态快照封印失效，而先发生的安装会关闭旧监控器版本。
Disjoint-domain steps commute, and the persisted target and certificate restore the invariant.
% 互不相交域中的步骤可交换，持久目标与证书则恢复不变量。
\end{proof}

Exponential growth occurs only in explicitly emitted linearizations and prefix--required-outcome support pairs.
% 指数增长只出现在显式输出的线性化和前缀--要求实现结果支持对中。
The TCB consists of the registries, receipt log, atomic rules, policy signer, call-authorizing service, certificate verifier, and complete mediation.

Search, minimization, and preloading remain untrusted because installation checks them again.
