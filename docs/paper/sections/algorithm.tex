\section{Certifying History-Admission Compiler}
\label{sec:algorithm}

The theory suggests a small tool rather than a replacement agent runtime.
Our artifact is an offline compiler for one proposed Fork, Restore, or Merge
edge, paired with an independent verifier.
It does not create checkpoints or execute tools.
Instead, a runtime adapter supplies a finite manifest, and the compiler either
constructs a structurally admissible future or returns a replayable reason why
the proposed history edge or controller layout is unsafe.

\subsection{Manifest boundary}

A request contains five kinds of evidence.
First, an authority family and a source future contract describe which
authority atoms and source cells may coexist.
Second, a source receipt frontier and current append-only ledger identify the
durable prefix.
Third, each typed operator arm supplies normalized cell records and
\emph{may}/\emph{required} maximal configurations; an arm is marked either
exact or a sound overapproximation.
A \texttt{sound\_overapprox} label is itself an attestation: the parser checks
its form, but neither executable proves the claimed inclusion.
Fourth, explicit alias records justify when occurrences from different arms
refer to one redemption cell.
An alias must preserve its stable cell anchor, authority atom, commitment key,
and effect-binding digest.
Parent and lease evidence is checked separately, because identity can remain
valid even when inheritance or lease transport does not.
Finally, each gate-use record attests an origin-gate identifier, an
authoritative controller anchor, and a local future family.  Its member list
must equal that family's normalized support, implementing the support-induced
$E_L$ subclass of the relational model.  Controller-future maxima generate the
full downward-closed $\Gamma$ for one co-durable epoch; the accompanying
\texttt{controller\_future\_coverage} value is either \texttt{exact} or
\texttt{sound\_overapprox}.

These fields are attestations, not facts inferred from a transcript.
The adapter remains responsible for their authenticity and completeness.
In particular, a natural-language task does not establish a cell alias,
controller identity, or a complete leaf future contract.

\subsection{Compilation pipeline}

The compiler follows the proof decomposition.

\begin{enumerate}[leftmargin=*,itemsep=2pt]
  \item It arm-tags every target occurrence, then folds only alias classes
  backed by explicit stable-cell evidence.  This computes
  $q_{\mathrm{cell}}$ without conflating it with controller identity.

  \item It applies the typed operator rule to the leaf families, producing
  $\mathsf{Candidate}$ and $\mathsf{Required}$ and checking
  $\mathsf{Required}\subseteq\mathsf{Candidate}$.

  \item It filters the candidate against the current durable prefix and
  normalized lineage.  The result is the greatest admitted family inside this
  fixed candidate; the compiler also records prefix-replay, lineage-collision,
  or forbidden-union reasons for removed configurations.

  \item It recomputes whether the source envelope is structurally inheritable.
  This requires an unchanged durable prefix and a commuting, collision-free
  parent map into the source future.  The prototype does not consume a prior
  verification seal or implement certificate-chain reuse; \textsc{Inherit}
  reports eligibility inside the canonical recomputation.

  \item Independently, it normalizes gate uses by controller anchor and expands
  the supplied full $\Gamma$ to form the raw physical family
  \[
    \mathsf{RawPhysical}
      =\bigcup_{G\in\Gamma}\ \bigotimes_{g\in G} L_g,
  \]
  where $L_g$ is controller $g$'s local family after cell normalization.
  It does not replace $\Gamma$ by a graph or another low-arity projection.

  \item It checks the manifest-level deployment sandwich
  \[
    \mathsf{Required}\subseteq\mathsf{RawPhysical}
      \subseteq\mathsf{Admitted}
  \]
  and emits a positive certificate or a compact negative witness.  It also
  reports \texttt{required\_coliveness\_arity}, the contract-only value in
  \cref{eq:required-coliveness-arity}.
\end{enumerate}

The coverage labels are adapter attestations.  The parser checks their form,
and a declared sound overapproximation yields a conservative decision, but
neither executable proves that the supplied full $\Gamma$ covers the runtime's
co-durable epoch.  The seal therefore retains
\texttt{controller\_coliveness\_coverage\_attestation} as an external
obligation; the reported arity diagnoses how much exact co-liveness evidence
would suffice, rather than certifying that the evidence was collected.

The semantic and deployment axes remain separate.
The semantic result is \textsc{Inherit}, \textsc{ReadmitOK},
\textsc{NeedsMechanism}, or \textsc{Reject}.
The controller realization is classified as exact, a safe restriction,
an unsafe overapproximation, missing required behavior, or both unsafe and
incomplete.
A safe restriction is accepted because it removes only optional behavior;
exact fidelity is reported separately.  Thus \textsc{NeedsMechanism} is a
semantic pruning result, not an automatic rejection: if the current manifest
already satisfies the sandwich, the tool returns \textsc{ReadyWithRestriction}
and a structural seal.  Controller installation remains an external obligation.

\subsection{Constructive negative evidence}

For an unsafe controller product, the compiler chooses a deterministic
physical cover and classifies that cover before assigning a mechanism label.
If the cover contains a cell outside
$\operatorname{supp}(\mathsf{Admitted})$, it emits
\textsc{OutsideSupport} and the exposed cell.
Otherwise, if one selected local choice is already forbidden, it emits
\textsc{LocalOverpermission} with a contained minimal nonface and the
offending controller.
Only when every selected local choice is admitted does the compiler emit
\textsc{CorrelationCut}.
It restricts the choices to an inclusion-minimal controller cover of a
minimal nonface and labels the concrete subtype \textsc{GateClone} when all
contributing anchors declare the same origin, or \textsc{GateCut} otherwise.
These are origin-based diagnostic subtypes of \textsc{CorrelationCut}, not
additional semantic failure classes.
The three causes are exclusive for the selected cover; different covers of
one bad physical configuration need not have a globally unique cause.

Missing required behavior is dual evidence rather than an overpermission:
the witness is one configuration in
$\mathsf{Required}\setminus\mathsf{RawPhysical}$.
When both differences are nonempty, the result retains the unsafe witness and
reports the combined grade.

\subsection{Independent verification and fail-closed limits}

The compiler is an untrusted witness producer.
The verifier does not import it: it parses the original request, independently
reconstructs the finite semantics with a bit-mask representation, recomputes
the complete expected result, and compares canonical JSON.
It rejects duplicate keys, floating-point values, unknown fields, malformed
receipt bindings, phase regressions, undeclared anchor reuse, inconsistent
aliases, and inactive declared controllers.
Canonical request and result digests bind a successful verification seal to
both inputs, including the full $\Gamma$ and its coverage label.  Verification
recomputes the current request; it does not validate or extend a previous
seal.

The main exhaustive-analysis caps are 12 source cells, 12 normalized target
cells, 10 controller anchors, 4,096 expanded configurations, and 200,000
controller-product pair-expansion iterations.
Exceeding a cap is a malformed request, not an optimistic answer.
These limits make the artifact suitable for admission litmus cases and small
runtime contracts; they are not a scalability claim.

Even a valid positive result is only a \emph{history-admission} seal.
The verifier always emits
$\mathsf{effect\_authorizes}=\mathsf{false}$.
Authentic receipts, controller installation and freshness, complete mediation,
atomic redemption, lease revalidation, and
\[
  \mathsf{Required}\subseteq\mathsf{Actual}
  \subseteq\mathsf{RawPhysical}
\]
remain runtime obligations.
The Lean model specifies the finite decision but is not an extraction of the
Python parser or verifier; proof replay, independent reimplementation, and
exhaustive small-model cross-checks are distinct evidence layers.
