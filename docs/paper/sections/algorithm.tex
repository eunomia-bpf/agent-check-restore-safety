\section{Runtime Enforcement}
% 运行时强制执行
\label{sec:enforcement}

The safety checker produces either an impossibility certificate or the largest safe family of completed executions.
% 安全检查器生成不可能性证书或最大的安全完整执行族。
The trusted installation service turns a nonempty family into runtime enforcement in three steps.
% 可信安装服务分三步将非空执行族转化为运行时强制执行。
It builds a monitor for the family's partial executions, binds that monitor to the authenticated source snapshot, and atomically installs it under a new monitor version.
% 它为该执行族的部分执行构造监控器，将监控器绑定到认证源状态快照，并在新的监控器版本下原子安装。
The protocol serializes every overlapping protected call either before or after installation.
% 该协议将每个重叠的受控调用完整地排列在安装之前或之后。
The proof compares this implementation with an ideal machine that installs an accepted specification in one atomic step and admits exactly its resolved prefixes.
% 证明将该实现与一台理想机比较；理想机以一个原子步骤安装被接受的规范，并且只接纳该规范的已解析前缀。
The ideal transition system and the field-level implementation rules appear in \cref{sec:ideal,tab:app-event-matrix}; the main text retains only the monitor construction and the installation boundary.
% 理想转移系统与字段级实现规则见 \cref{sec:ideal,tab:app-event-matrix}；正文只保留监控器构造与安装边界。

\subsection{Canonical Occurrence-Sensitive Monitor}
% 规范的发生项敏感监控器

The greatest realization has the finite, canonically installable projected pair \((W,B)=(W^\dagger_{H,u},B^\dagger_{H,u})\).
% 最大实现具有有限且可规范安装的投影对 \((W,B)=(W^\dagger_{H,u},B^\dagger_{H,u})\)。
For \(L/z=\{v\mid zv\in L\}\), use residual states \(q_z=(W^\dagger/z,B^\dagger/z)\).
% 对于 \(L/z=\{v\mid zv\in L\}\)，使用残余状态 \(q_z=(W^\dagger/z,B^\dagger/z)\)。
\begin{equation}
\label{eq:canonical-program}
\begin{aligned}
 Q_{W,B} &= \{q_z\mid z\in W\},\\
 q^0&=q_\epsilon=(W^\dagger,B^\dagger),\\
 q_z\xrightarrow{a}q_{za}
 &\quad\Longleftrightarrow\quad za\in W .
\end{aligned}
\end{equation}
Call this monitor automaton \(\mathsf{Can}(W,B)\).
% 将该监控器自动机记作 \(\mathsf{Can}(W,B)\)。
Every state is reachable and is marked exactly when \(\epsilon\in B^\dagger/z\).
% 每个状态均可达，并且恰在 \(\epsilon\in B^\dagger/z\) 时被标记。
Each transition symbol \(a\) contains occurrence \(x\), effect identity \(d\), and its \Fresh or \Alias mode, so one call position cannot use another position's monitor entry.
% 每个转移符号 \(a\) 都包含发生项 \(x\)、效果标识 \(d\) 以及 \Fresh/\Alias 模式，因此一个调用位置无法使用另一个位置的监控器入口。

\begin{lemma}[Exact compiled realization]
% 精确的编译实现
\label{lem:compiled-language}
The generated and marked languages of the program in \cref{eq:canonical-program} are exactly \((W^\dagger_{H,u},B^\dagger_{H,u})\).
% \cref{eq:canonical-program} 中程序的生成语言和标记语言恰为 \((W^\dagger_{H,u},B^\dagger_{H,u})\)。
The program is the smallest deterministic marked partial automaton for this pair up to state renaming.
% 在忽略状态重命名的意义下，该程序是实现这对语言的最小确定性标记偏自动机。
\end{lemma}
\begin{proof}
Induction on \(z\) shows that the automaton reaches \((W^\dagger/z,B^\dagger/z)\), enables \(a\) iff \(za\in W^\dagger\), and marks the reached state iff \(z\in B^\dagger\).
% 对 \(z\) 的归纳表明，该自动机到达 \((W^\dagger/z,B^\dagger/z)\)，当且仅当 \(za\in W^\dagger\) 时启用 \(a\)，并且当且仅当 \(z\in B^\dagger\) 时标记所到达的状态。
Distinct states differ on a generated or marked suffix and must remain distinct.
% 不同状态在某个生成后缀或标记后缀上存在差异，因此必须保持不同。
The automaton is the paired-language derivative construction~\cite{brzozowski1964derivatives}.
% 该自动机是成对语言的导数构造~\cite{brzozowski1964derivatives}。
\end{proof}

The checker returns \(\mathsf{Invalid}\) when derivation fails, \(\mathsf{Reject}\) with a ranked impossibility certificate when the fixed point is empty, and \(\mathsf{Installable}\) with the canonical monitor otherwise.
% 当推导失败时，检查器返回 \(\mathsf{Invalid}\)；当不动点为空时，返回带秩不可能性证书的 \(\mathsf{Reject}\)；否则返回携带规范监控器的 \(\mathsf{Installable}\)。
Each answer is bound to the complete authenticated source snapshot.
% 每个答案都绑定完整的认证源状态快照。
\Cref{app:certificate-payloads,app:compiled-transitions} gives the exact payloads and verification rules.
% \Cref{app:certificate-payloads,app:compiled-transitions} 给出精确载荷与验证规则。
The bounded implementation may instead return \(\mathsf{ResourceLimit}(b,n)\), which installs nothing and proves neither safety nor impossibility.
% 有界实现可能改为返回 \(\mathsf{ResourceLimit}(b,n)\)，它不安装任何内容，也不证明安全性或不可能性。

\subsection{Atomic Installation}
% 原子安装

At installation, the service re-derives the edit and recomputes the fixed point from the current authenticated snapshot.
% 安装时，该服务根据当前认证快照重新推导编辑并重新计算不动点。
If any protected call has committed since compilation, the candidate is stale and installs nothing.
% 如果编译之后已有任何受控调用提交，则候选已过期且不会安装任何内容。
Otherwise, one policy-domain transaction closes the old monitor version, activates the canonical monitor, replaces every current occurrence binding and authorization token, and only then exposes the successful edit answer.
% 否则，一个策略域事务会关闭旧监控器版本、激活规范监控器、替换每个当前发生项的绑定与授权令牌，然后才暴露成功编辑答案。
Protected calls verify their occurrence, effect identity, normalized request, authorization token, and current monitor transition in the same transaction that records progress.
% 受控调用在记录进度的同一事务中验证其发生项、效果标识、规范化请求、授权令牌与当前监控器转移。
A \Fresh call creates one authorization record and ordered dispatch item; an \Alias call advances the workflow by linking to the existing record without extending the permission trace.
% \Fresh 调用创建一条授权记录和一个有序派发条目；\Alias 调用通过链接到已有记录推进工作流，而不扩展权限轨迹。
The complete invariant, guarded call rule, installation preconditions, field updates, retries, dispatch, settlement, and crash behavior appear in \cref{app:compiled-transitions,tab:app-event-matrix}.
% 完整不变量、带守卫调用规则、安装前提、字段更新、重试、派发、结算与崩溃行为见 \cref{app:compiled-transitions,tab:app-event-matrix}。

\begin{lemma}[Edit--call serialization]
% 编辑--调用串行化
\label{lem:cut-linearization}
In every reachable well-formed compiled state, a visible edit answer and a protected call in the same policy domain have a unique order at the installation point.
% 在每个可达的良构编译状态中，同一策略域内的一项可见编辑答案与一次受控调用在安装点具有唯一顺序。
If the call commits first, that seal cannot install.
% 若该调用先提交，则该封印无法安装。
If \Install commits first, the old call cannot resolve \Fresh or \Alias.
% 若 \Install 先提交，则旧调用无法解析 \Fresh 或 \Alias。
Steps in independent domains commute by product semantics.
% 独立域中的步骤依据乘积语义可交换。
\end{lemma}
\begin{proof}
Prior \Fresh/\Alias invalidates every old source-snapshot seal, while prior installation closes the old monitor version.
% 先发生的 \Fresh/\Alias 会使每个旧源状态快照封印失效，而先发生的安装会关闭旧监控器版本。
Disjoint-domain steps commute, and the persisted target and certificate restore the invariant.
% 互不相交域中的步骤可交换，持久目标与证书则恢复不变量。
\end{proof}

\subsection{Decidability and trust}
% 可判定性与信任

\Cref{prop:app-output-complexity} proves an output-sensitive \(O(D+n\Lambda+|\mathcal G_{\rm cov}|+V_B\log(2+V_B))\)-time, \(O(D+\Lambda+|\mathcal G_{\rm cov}|)\)-space bound.
% \Cref{prop:app-output-complexity} 证明一种输出敏感的 \(O(D+n\Lambda+|\mathcal G_{\rm cov}|+V_B\log(2+V_B))\) 时间、\(O(D+\Lambda+|\mathcal G_{\rm cov}|)\) 空间界。
Exponential growth occurs only in explicitly emitted linearizations and prefix--required-outcome support pairs.
% 指数增长只出现在显式输出的线性化和前缀--要求实现结果支持对中。
The TCB is the trusted boundary defined in \cref{sec:model}.
% TCB 即 \cref{sec:model} 定义的可信边界。
Search, minimization, and preloading remain untrusted because installation checks them again.
% 搜索、最小化与预加载仍不受信任，因为安装时会再次检查它们。
