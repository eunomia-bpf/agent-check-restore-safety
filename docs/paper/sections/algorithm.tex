\section{Runtime Enforcement}
% 运行时强制执行
\label{sec:enforcement}

The safety checker produces either a rejection proof or the largest safe family of complete executions.
% 安全检查器生成拒绝证明或最大的安全完整执行族。
The trusted controller turns a nonempty family into rules checked before each tool call.
% 可信控制器把非空执行族转化为每次工具调用之前检查的规则。
It builds a finite automaton for the allowed partial executions, records which version of the execution record was checked, and atomically puts the new rules into effect.
% 它为允许的部分执行构造有限自动机，记录检查时使用的执行记录版本，并使新规则原子生效。
The protocol orders every overlapping protected call either before or after the atomic rule update.
% 该协议将每个重叠的受控调用完整地排列在原子规则更新之前或之后。
The proof compares this implementation with an ideal machine that puts an accepted result into effect in one atomic step and admits exactly its resolved prefixes.
% 证明将该实现与一台理想机比较；理想机以一个原子步骤使接受的结果生效，并且只接纳该结果的已解析前缀。
The ideal transition system and the field-level implementation rules appear in \cref{sec:ideal,tab:app-event-matrix}.
% 理想转移系统与字段级实现规则见 \cref{sec:ideal,tab:app-event-matrix}。
This section gives the automaton construction, the invariant after the rules change, and the atomic update used by the main theorem.
% 本节给出主定理所需的自动机构造、规则改变后的不变量以及原子更新。

\subsection{Turning Safe Executions into Runtime Rules}
% 把安全执行转化为运行时规则

Removing outcome labels from the largest safe execution set gives the finite pair \((W,B)=(W^\dagger_{H,u},B^\dagger_{H,u})\).
% 从最大安全执行集合中去掉结果标签，得到有限对 \((W,B)=(W^\dagger_{H,u},B^\dagger_{H,u})\)。
For \(L/z=\{v\mid zv\in L\}\), let \(q_z=(W/z,B/z)\) be the automaton state after prefix \(z\).
% 对于 \(L/z=\{v\mid zv\in L\}\)，令 \(q_z=(W/z,B/z)\) 表示执行前缀 \(z\) 后的自动机状态。
\begin{equation}
\label{eq:canonical-program}
\begin{aligned}
 Q_{W,B} &= \{q_z\mid z\in W\},\\
 q^0&=q_\epsilon=(W,B),\\
 q_z\xrightarrow{a}q_{za}
 &\quad\Longleftrightarrow\quad za\in W .
\end{aligned}
\end{equation}
Call this deterministic automaton \(\mathsf{Can}(W,B)\).
% 将该确定性自动机记作 \(\mathsf{Can}(W,B)\)。
Every state is reachable and is marked exactly when \(\epsilon\in B^\dagger/z\).
% 每个状态均可达，并且恰在 \(\epsilon\in B^\dagger/z\) 时被标记。
Each transition symbol \(a\) contains workflow call \(x\), action \(d\), and its \Fresh or \Alias mode, so one workflow call cannot use another call's rule entry.
% 每个转移符号 \(a\) 都包含工作流调用 \(x\)、动作 \(d\) 以及 \Fresh/\Alias 模式，因此一个工作流调用无法使用另一个调用的规则入口。

\begin{lemma}[Exact finite enforcement]
% 精确的有限执行规则
\label{lem:compiled-language}
The generated and marked languages of the automaton in \cref{eq:canonical-program} are exactly \((W^\dagger_{H,u},B^\dagger_{H,u})\).
% \cref{eq:canonical-program} 中自动机的生成语言和标记语言恰为 \((W^\dagger_{H,u},B^\dagger_{H,u})\)。
The automaton is the smallest deterministic marked partial automaton for this pair up to state renaming.
% 在忽略状态重命名的意义下，该自动机是实现这对语言的最小确定性标记偏自动机。
\end{lemma}
\begin{proof}
Induction on \(z\) shows that the automaton reaches \((W^\dagger/z,B^\dagger/z)\), enables \(a\) iff \(za\in W^\dagger\), and marks the reached state iff \(z\in B^\dagger\).
% 对 \(z\) 的归纳表明，该自动机到达 \((W^\dagger/z,B^\dagger/z)\)，当且仅当 \(za\in W^\dagger\) 时启用 \(a\)，并且当且仅当 \(z\in B^\dagger\) 时标记所到达的状态。
Distinct states differ on a generated or marked suffix and must remain distinct.
% 不同状态在某个生成后缀或标记后缀上存在差异，因此必须保持不同。
The automaton is the paired-language derivative construction~\cite{brzozowski1964derivatives}.
% 该自动机是成对语言的导数构造~\cite{brzozowski1964derivatives}。
\end{proof}

\subsection{Atomic Rule Update}
% 原子规则更新

Before the rules change, the trusted controller re-derives the edit and recomputes the fixed point from the execution record.
% 规则改变之前，可信控制器根据执行记录重新推导编辑并重新计算不动点。
If any protected call has committed since the candidate was computed, the candidate is stale and changes nothing.
% 如果计算候选结果之后已有任何受控调用提交，则该候选结果已过期且不会改变任何内容。
Otherwise, one policy-domain transaction closes the old rule version, activates the new automaton, replaces the rule entry and authorization token for every current workflow call, and only then exposes the successful edit answer.
% 否则，一个策略域事务会关闭旧规则版本、激活新自动机、替换每个当前工作流调用的规则入口与授权令牌，然后才暴露成功编辑答案。
Protected calls verify their workflow call, action, canonical request, authorization token, and enabled automaton transition in the same transaction that records progress.
% 受控调用在记录进度的同一事务中验证其工作流调用、动作、规范请求、授权令牌与已启用的自动机转移。
A \Fresh call creates one authorization record and queues the canonical request.
% \Fresh 调用创建一条授权记录并将规范请求入队。
An \Alias call advances the workflow by linking to the existing record without extending the authorization sequence.
% \Alias 调用通过链接到已有记录推进工作流，而不扩展授权序列。

\paragraph{Invariant after the rule update}
% 规则更新后的不变量
We write \(\mathsf{AgentSec}(S;c,r)\) when five conditions hold: (1) the workflow now in force and its required outcomes come from the checked edit; (2) the stored nonempty execution family is the checker's largest safe family; (3) the workflow, authorization log, queue, and checkpoints match the executed prefix \(r\); (4) the automaton is in exactly the state reached after \(r\); and (5) exactly one rule version is active, with one rule entry and authorization token for every remaining workflow call.
% 当以下五项条件成立时，记作 \(\mathsf{AgentSec}(S;c,r)\)：(1) 当前生效的工作流及其要求实现的结果来自经检查编辑；(2) 已存非空执行族是检查器得到的最大安全执行族；(3) 工作流、授权日志、队列和检查点与已执行前缀 \(r\) 一致；(4) 自动机恰处于执行 \(r\) 后到达的状态；(5) 恰有一个规则版本处于活动状态，并为每个剩余工作流调用提供一个规则入口和授权令牌。
For a submitted tool request, one transaction verifies the workflow call, action, canonical request, authorization token, active rule version, and enabled automaton transition before recording any progress.
% 对于提交的工具请求，一个事务会先验证工作流调用、动作、规范请求、授权令牌、当前规则版本以及已启用的自动机转移，然后才记录任何进展。
The same transaction either creates the authorization record and queues the request, or records reuse of an existing authorization record and its return value.
% 同一事务随后要么创建授权记录并将请求入队，要么记录对已有授权记录及其返回值的复用。

\paragraph{Final check}
% 最终检查
For current state \(S\), write
\(\Theta_S(u)=(\kappa,H,\Delta,\mathsf{out},\mathcal A,u)\)
for the safety-check instance obtained from its current components.
% 对当前状态 \(S\)，将由其当前分量得到的安全检查实例记为
% \(\Theta_S(u)=(\kappa,H,\Delta,\mathsf{out},\mathcal A,u)\)。
Write \(\mathsf{Ready}(S,u,Y)\) when the service re-derives \(u\) from the current execution record, recomputes the same nonempty fixed point and automaton carried by \(Y\), confirms that the record has not changed since \(Y\) was computed, confirms that the old rule version is current, and confirms that the new version is inactive.
% 当服务根据当前执行记录重新推导 \(u\)、重新计算出 \(Y\) 所携带的同一非空不动点与自动机、确认计算 \(Y\) 之后执行记录未发生变化、确认旧规则版本仍为当前版本并确认新版本尚未激活时，记作 \(\mathsf{Ready}(S,u,Y)\)。
If these checks pass, one transaction closes the old version, activates the new automaton, replaces every current rule entry and authorization token, and then exposes the successful edit answer.
% 若这些检查通过，一个事务会关闭旧版本、激活新自动机、替换每个当前规则入口与授权令牌，然后才暴露成功编辑答案。
A changed state makes the candidate stale and forces a new check.
% 状态一旦改变，候选结果即过期，必须重新检查。
The complete state updates, retries, request release, completion updates, and recovery rules appear in \cref{app:compiled-transitions,tab:app-event-matrix}.
% 完整状态更新、重试、请求发出、完成更新与恢复规则见 \cref{app:compiled-transitions,tab:app-event-matrix}。

\begin{lemma}[Edit--call serialization]
% 编辑--调用串行化
\label{lem:cut-linearization}
In every reachable well-formed runtime state, a visible edit answer and a protected call in the same policy domain have a unique order at the atomic rule update.
% 在每个可达的良构运行时状态中，同一策略域内的一项可见编辑答案与一次受控调用在原子规则更新处具有唯一顺序。
If the call commits first, it changes the execution record, so the earlier result cannot take effect.
% 若调用先提交，它会改变执行记录，因此先前的结果无法生效。
If \Install commits first, the old call cannot resolve \Fresh or \Alias.
% 若 \Install 先提交，则旧调用无法解析 \Fresh 或 \Alias。
Steps in independent domains commute by product semantics.
% 独立域中的步骤依据乘积语义可交换。
\end{lemma}
\begin{proof}
If the call commits first, its recorded progress changes the execution record.
% 若调用先提交，其记录的进展会改变执行记录。
If the rule update commits first, it closes the old rule version, so the old authorization token fails.
% 若规则更新先提交，它会关闭旧规则版本，因此旧授权令牌无法通过验证。
Atomicity excludes a partial third outcome.
% 原子性排除了部分完成的第三种结果。
Independent domains commute.
% 独立域中的步骤彼此可交换。
\end{proof}

\subsection{Trust Boundary}
% 信任边界

The TCB is the trusted boundary defined in \cref{sec:model}.
% TCB 即 \cref{sec:model} 定义的可信边界。
Search, minimization, and candidate preparation remain untrusted because the final check recomputes them.
% 搜索、最小化与候选结果准备仍不受信任，因为最终检查会重新计算它们。
The next section states the exactness and runtime guarantees obtained at this boundary.
% 下一节陈述在这一边界上获得的精确性与运行时保证。
