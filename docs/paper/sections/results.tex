\section{Formal Guarantees}
% 形式保证
\label{sec:results}

The theorem connects derivation from the execution record, exact checking, finite enforcement, the atomic rule update, and every later runtime step.
% 该定理连接从执行记录进行的推导、精确检查、有限执行规则、原子规则更新以及此后的每个运行时步骤。
Its central clause says that the checker accepts if and only if a safe runtime implementation exists.
% 其核心条款表明，当且仅当安全运行时实现存在时，检查器才会接受。
The other clauses establish faithful registration, the information required for an exact answer, repeated use, and runtime correctness.
% 其余条款建立忠实注册、精确答案所需的信息、重复使用与运行时正确性。

When defined, write
\(\delta=\mathsf{Derive}(\Theta)
 =(\kappa_u,H_u,\mathcal A_u,\mathcal C_u,\eta^-,\eta^+)\).
% 当推导有定义时，记
% \(\delta=\mathsf{Derive}(\Theta)
%  =(\kappa_u,H_u,\mathcal A_u,\mathcal C_u,\eta^-,\eta^+)\)。
A \emph{safe runtime implementation} is an automaton \(M\) together with complete executions \(\widehat B_M\) labeled by outcome.
% \emph{安全运行时实现}由自动机 \(M\) 和按结果标记的完整执行 \(\widehat B_M\) 组成。
The partial and complete executions of \(M\) must form a safe execution set as defined in \cref{def:safe-implementation}.
% \(M\) 的部分执行与完整执行必须构成 \cref{def:safe-implementation} 定义的安全执行集合。
The atomic rule update activates this automaton at \(\eta^+\), closes \(\eta^-\), and replaces the rule entries and authorization tokens for all target calls.
% 原子规则更新在 \(\eta^+\) 激活该自动机、关闭 \(\eta^-\)，并替换全部目标调用的规则入口与授权令牌。

\paragraph{What the checker must know}
% 检查器必须知道什么
Write \(V=\mathsf{Sec}(S;c,r)
=({\mathbf P},{\mathbf I},{\mathbf E},{\mathbf C})\) for four parts of the checked record: (1) the workflow and its required outcomes, (2) which calls refer to the same action, (3) earlier authorizations and call progress, and (4) which rules govern a call that overlaps the atomic rule update.
% 令 \(V=\mathsf{Sec}(S;c,r)
% =({\mathbf P},{\mathbf I},{\mathbf E},{\mathbf C})\) 表示所检查记录的四个部分：(1) 工作流及其要求实现的结果，(2) 哪些调用指向同一个动作，(3) 先前的授权与调用进展，以及 (4) 哪组规则管理与原子规则更新重叠的调用。
Suppose a checker receives only some function \(f(V)\) of this record.
% 假设检查器只能得到该记录的某个函数 \(f(V)\)。
The function is exact if any two records that it makes indistinguishable always give the same answer to every common decision or rule-update request.
% 如果该函数无法区分的任意两份记录，对每个共同的判定或规则更新请求都给出相同答案，那么该函数是精确的。
Write \(\mathsf{Exact}(f)\) for this property.
% 将这一性质记为 \(\mathsf{Exact}(f)\)。
Internal identifiers may be renamed consistently because their spelling cannot affect the answer.
% 内部标识可以一致重命名，因为它们的具体拼写不能影响答案。
For \(J\subseteq\{\mathbf P,\mathbf I,\mathbf E,\mathbf C\}\), \(\mathsf{Keep}_J\) gives the checker exactly the parts named by \(J\).
% 对于 \(J\subseteq\{\mathbf P,\mathbf I,\mathbf E,\mathbf C\}\)，\(\mathsf{Keep}_J\) 恰好向检查器提供 \(J\) 指明的部分。
\Cref{app:record-information} gives one record pair for each part and a fifth pair for the correspondence between earlier authorizations and actions.
% \Cref{app:record-information} 为每个部分给出一组记录对，并为先前授权与动作之间的对应关系给出第五组记录对。

\paragraph{Required-outcome preservation}
% 要求实现结果的保留
\[
\begin{aligned}
\mathsf{PreservesRequired}(H,u,\widehat B)
&\Longleftrightarrow
\forall a\in\mathsf{StillRequired}_u.\\[-2pt]
&\qquad\exists(t,y)\in\widehat B.\
\mathsf{Covers}_u(t,a).
\end{aligned}
\]
Thus every required source outcome appears in an accepted target outcome.
% 因而，每个要求实现的源结果都出现在某个被接受的目标结果中。

\paragraph{Visible runtime behavior}
% 可见运行时行为
\(\mathcal O_{\rm api}\) includes edit answers tied to the checked record, edits put into effect, protected-call answers, released requests, completion updates, and returned values.
% \(\mathcal O_{\rm api}\) 包括与所检查记录对应的编辑答案、已经生效的编辑、受控调用答案、已发出请求、完成更新和返回值。
It hides internal computation, Save, stale candidates, and restart bookkeeping.
% 它隐藏内部计算、Save、过期候选结果和重启记录工作。
\[
\mathsf{obs}_{\rm api}(\ell)=
\begin{cases}
\ell,&\ell\in\mathcal O_{\rm api};\\
\tau,&\text{otherwise}.
\end{cases}
\]
Write \(S\approx_{\mathcal O_{\rm api}}^{\mathsf{di}}I\) when \(S\) and \(I\) are related by a divergence-insensitive weak bisimulation under \(\mathsf{obs}_{\rm api}\).
% 当 \(S\) 与 \(I\) 在 \(\mathsf{obs}_{\rm api}\) 下由某个发散不敏感弱互模拟关联时，记作 \(S\approx_{\mathcal O_{\rm api}}^{\mathsf{di}}I\)。
\(\mathcal B\) matches ideal and runtime states on \(\mathsf{AgentSec}\) and these visible fields.
% \(\mathcal B\) 在 \(\mathsf{AgentSec}\) 与这些可见字段上匹配理想状态和运行时状态。
\Cref{app:bisimulation} gives the full relation.
% \Cref{app:bisimulation} 给出完整关系。

\begin{theorem}[Faithful Registration]
% 忠实注册
\label{thm:faithful-registration}
For finite-state \(\mathcal W\) and finite \(\mathcal R\),
\(\mathsf{CheckReg}(\mathcal W,\mathcal R)\) accepts iff stored \(\lambda\) witnesses \(\mathcal W\sqsubseteq_\lambda\mathcal R\).
% 当且仅当所存 \(\lambda\) 见证 \(\mathcal W\sqsubseteq_\lambda\mathcal R\) 时，\(\mathsf{CheckReg}(\mathcal W,\mathcal R)\) 才接受。
On acceptance, the source workflow's protected-call traces and \(\mathsf{BRuns}(\mathcal R)\) are order-isomorphic and preserve outcomes, actions, \Fresh/\Alias, the safety answer, and the largest safe execution set.
% 接受时，源工作流的受控调用轨迹与 \(\mathsf{BRuns}(\mathcal R)\) 序同构，并保持结果、动作、\Fresh/\Alias、安全答案与最大安全执行集合。
Malformed registrations fail before startup.
% 不合格的注册在启动前失败。
\end{theorem}

For the remaining results, assume accepted registration, trusted checking of every protected call, and linearizable transactions that remain atomic after a restart within each policy domain.
% 对于其余结果，假设注册已通过、每次受控调用都由可信组件检查，并且每个策略域内的可线性化事务在重启后仍保持原子性。
Let \(\mathsf{Ext}=\{\mathsf{Extend}(\xi)\mid \xi\text{ is verified}\}\).
% 令 \(\mathsf{Ext}=\{\mathsf{Extend}(\xi)\mid \xi\text{ 已通过验证}\}\)。
They hold for every \(u\in\mathsf{Edit}_6\uplus\mathsf{Ext}\) at every finite reachable \(\mathsf{AgentSec}\) state.
% 它们对每个有限可达 \(\mathsf{AgentSec}\) 状态上的每个 \(u\in\mathsf{Edit}_6\uplus\mathsf{Ext}\) 成立。

\begin{theorem}[Exact Edit-Safety]
% 精确编辑安全
\label{thm:exact-history}
The ideal and runtime machines return the same mutually exclusive and exhaustive answer for \(\Theta=\Theta_S(u)\).
% 对于 \(\Theta=\Theta_S(u)\)，理想机与运行时机器返回相同且互斥穷尽的答案。
Undefined derivation gives state-preserving \(\mathsf{Invalid}\).
% 未定义推导给出保持状态的 \(\mathsf{Invalid}\)。
For defined \(\delta=\mathsf{Derive}(\Theta)\), \(\widehat B^\dagger_{H,u}=\varnothing\) gives state-preserving \(\mathsf{Reject}\) with no safe runtime implementation.
% 对有定义的 \(\delta=\mathsf{Derive}(\Theta)\)，\(\widehat B^\dagger_{H,u}=\varnothing\) 给出保持状态的 \(\mathsf{Reject}\)，且不存在安全运行时实现。
Otherwise, for \(Y=\mathsf{Check}(\Theta)\), nonempty \(\widehat B^\dagger_{H,u}\), existence of a safe runtime implementation, \(\mathsf{Ready}(S,u,Y)\), and a successor that puts the edit into effect while preserving \(\mathsf{AgentSec}\) are equivalent.
% 否则，对于 \(Y=\mathsf{Check}(\Theta)\)，\(\widehat B^\dagger_{H,u}\) 非空、安全运行时实现存在、\(\mathsf{Ready}(S,u,Y)\) 成立，以及存在使编辑生效并保持 \(\mathsf{AgentSec}\) 的后继，这四项彼此等价。
The largest execution family satisfies \(\mathsf{PreservesRequired}\), and the derived record identifies every already-satisfied source outcome and every authorized removal.
% 最大执行族满足 \(\mathsf{PreservesRequired}\)，且派生记录标识每个已满足源结果和每项获准移除。
\end{theorem}

\begin{theorem}[Necessary Record Information]
% 必要记录信息
\label{thm:necessary-state}
The full record is sufficient.
% 完整记录是充分的。
If any one of the four parts is omitted, two records become indistinguishable even though the correct answer differs.
% 如果省略这四个部分中的任何一个，两份记录就会变得无法区分，但它们的正确答案不同。
\[
\mathsf{Exact}(\mathsf{Keep}_J)\Longleftrightarrow
J=\{\mathbf P,\mathbf I,\mathbf E,\mathbf C\}.
\]
The four component-labeled rows in \cref{tab:record-pairs} witness omission of \(\mathbf P,\mathbf I,\mathbf E,\mathbf C\).
% \Cref{tab:record-pairs} 中标有四个分量的记录对分别见证省略 \(\mathbf P,\mathbf I,\mathbf E,\mathbf C\) 的后果。
The \(\mathsf{Drop}_{ra}\) row shows that retaining authorization records and actions without recording which ones correspond is also insufficient.
% \(\mathsf{Drop}_{ra}\) 行表明，仅保留授权记录与动作而不记录它们之间的对应关系同样不够。
In particular, a checker is not exact if it forgets which calls or authorization records refer to the same action, or if it sees only the target workflow proposed by the caller.
% 特别地，如果检查器忘记哪些调用或授权记录指向同一个动作，或者只看到调用方提出的目标工作流，它就不是精确的。
Generalized nonblocking can serve as an exact solver only after the trusted controller derives the workflow and outcome-specific completion conditions.
% 只有在可信控制器推导出工作流以及特定于结果的完成条件之后，广义非阻塞才能作为精确求解器。
\end{theorem}

\begin{theorem}[Repeated-Use Safety]
% 重复使用安全
\label{thm:repeated-use}
Every enabled event preserves \(\mathsf{AgentSec}\), so the theorem applies after every finite reachable sequence of edits, registered extensions, protected calls, authorization updates, rule updates, stops, and restarts.
% 每个启用事件都保持 \(\mathsf{AgentSec}\)，因此该定理适用于由编辑、已注册扩展、受控调用、授权更新、规则更新、停止和重启组成的每个有限可达序列。
\end{theorem}

\begin{theorem}[Runtime Correctness]
% 运行时正确性
\label{thm:runtime-correctness}
\(\mathcal B\) is a divergence-insensitive weak bisimulation under \(\mathsf{obs}_{\rm api}\), so every pair related by \(\mathcal B\) satisfies \(S_0\approx_{\mathcal O_{\rm api}}^{\mathsf{di}}I_0\).
% \(\mathcal B\) 在 \(\mathsf{obs}_{\rm api}\) 下是发散不敏感弱互模拟，因此由 \(\mathcal B\) 关联的每对状态均满足 \(S_0\approx_{\mathcal O_{\rm api}}^{\mathsf{di}}I_0\)。
The observation records edit answers tied to the checked record, new authorization data, and returned values.
% 该观测记录与所检查记录对应的编辑答案、新授权数据与返回值。
\end{theorem}

\paragraph{Proof roadmap}
% 证明路线
Registration reflection follows by enumerating the finite protected-call traces and checking their order- and identity-preserving correspondence.
% 注册反射通过枚举有限受控调用轨迹并检查其保持次序与标识的对应关系得到。
The edit-rule checks and greatest-fixed-point argument prove exact checking.
% 编辑规则检查与最大不动点论证证明精确检查。
Every safe execution set is contained in the computed family, and a nonempty computed family yields a safe runtime implementation.
% 每个安全执行集合都包含于计算出的执行族中，而非空的计算执行族会产生安全运行时实现。
Five explicit pairs of execution records prove the information result.
% 五组显式执行记录对证明信息结果。
Induction over the runtime rules proves repeated use.
% 对运行时规则作归纳证明重复使用。
A case analysis over edits, protected calls, races with the rule update, returns, and restarts establishes the weak bisimulation.
% 对编辑、受控调用、与规则更新的竞态、返回与重新启动作分类讨论建立弱互模拟。
The appendix gives the complete case proofs.
% 附录给出完整的分类证明。
