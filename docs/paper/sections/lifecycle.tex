\section{One Agent, Two Histories}
\label{sec:lifecycle}

Consider a procurement Agent authorized to place one order.  It durably
reserves the budget, giving receipt log \(\Delta\) with
\(\mathsf{lab}(\Delta)=r\), and saves checkpoint \(k\) before approval.
Approval then commits as cell \(a\), so
\(\mathsf{lab}(\Delta)=ra\).  The Agent requests a choice Fork between two
suppliers.  Its protected completion contract has exactly two indexed
outcomes:
\[
\begin{split}
 o_A&:\ p_A\prec s_A,\\
 o_B&:\ p_B\prec s_B ,
\end{split}
\tag{1}\label{eq:running-outcomes}
\]
where \(p\) and \(s\) denote payment and shipment occurrences.  The
alternatives are exclusive, but both must have a safe completion at the cut.

Logical occurrence is not effect identity.  The protected-call registry
authenticates
\[
 q_{\rm cell}(s_A)=q_{\rm cell}(s_B)=s.
\]
Both branches copied the same shipment handle, while payments retain
distinct cells \(p_A\) and \(p_B\).  A later Restore of \(k\) will create a
new approval occurrence \(a'\) with \(q_{\rm cell}(a')=a\).  The authority policy
allows prefixes of \(rap_As\) and \(rap_Bs\), but no trace containing both
payments or a payment before \(a\).

\paragraph{The admission calculation}
At this cut each outcome has one causal linearization, resolving to
\[
\begin{aligned}
 z_A&=\Fresh(p_A,p_A)\Fresh(s_A,s),\\
 z_B&=\Fresh(p_B,p_B)\Fresh(s_B,s).
\end{aligned}
\]
Thus \(M_{o_A}=\{z_A\}\), \(M_{o_B}=\{z_B\}\), and
\(B^\star=\{z_A,z_B\}\); \(W\) contains exactly their prefixes.  If the
durable policy residual instead removed \(rap_Bs\), then
\(M_{o_B}=\varnothing\): admitting the Fork and silently pruning supplier
\(B\) would violate the operation's history meaning.  This is the
necessary-and-sufficient boundary generalized below.

\paragraph{The fresh race}
After the shared approval and before either payment, the Agent requests
\(\mathsf{MergeSelect}(A)\).  If the old supplier-\(B\) controller commits
\(p_B\) first, that occurrence durably selects \(B\) and changes the receipt
prefix from \(ra\) to \(rap_B\); selecting \(A\) must therefore be
re-derived and rejected.  If the Merge cut wins, it must close every owner of
the affected choice group before any later \(p_B\) can commit.  Publishing a
new controller without fencing the loser permits both payments.

\paragraph{The alias race}
Now consider the live Restore in \cref{fig:two-histories}.  Cloning \(k\)
creates a fresh logical approval occurrence \(a'\) and gate, but retains
cell \(a\).  Because \(a\) is already receipted, executing \(a'\) is an
\Alias: it advances the restored continuation past approval but leaves
\(\Delta\) unchanged.  A concurrent join or replacement compiled before that
progress is stale even though its receipt comparison still succeeds.  The cut
must therefore compare a logical-occurrence frontier \(\chi\) in addition to
the receipt frontier.

The example exposes the whole problem.  Workspace equality cannot recover
which branch relation is live; receipt equality cannot detect alias progress;
cell equality cannot identify which controller must be closed; and a target
automaton supplied by the Agent cannot certify any of these facts.
\Cref{sec:model} replaces that supplied request with a trusted history
derivation.
