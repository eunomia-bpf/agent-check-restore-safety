\section{History-Transforming Agent Lifecycles}
\label{sec:lifecycle}

\subsection{Running example}

Suppose a user grants an agent authority for one deployment.
The runtime creates an exclusive choice between branches \(b_1\) and \(b_2\).
Each branch builds and tests a candidate and obtains a conditional deployment claim.
Because only one branch may be retained, the two one-unit commitments fit a one-unit grant.

Three variants expose the missing boundary.

\begin{description}[leftmargin=*,style=nextline,itemsep=3pt]
  \item[Durable selection.]
  The runtime durably selects \(b_1\), tombstones \(b_2\), withdraws \(b_2\)'s tentative claim, and releases \(b_1\)'s staged deployment.
  One deployment becomes durable.

  \item[Early escape.]
  Before selection, \(b_1\) sends a deployment-triggering request.
  Even if \(b_2\) later wins, the first request cannot be unsent.
  The escaped claim is no longer conditional on retaining \(b_1\); it must be charged in the \(b_2\) future as well.

  \item[Choice-to-merge.]
  An operator keeps the artifacts and deployment commitments of both alternatives.
  The lifecycle no longer promises exclusivity.
  The two claims must be jointly funded, one withdrawn, or the merge rejected.
\end{description}

These variants may have identical files and model context at a checkpoint.
They differ in durable branch eligibility and effect history, which must not be reconstructed from that checkpoint.

\subsection{Why the state is heterogeneous}

For the aggregate-authority property studied here, the relevant state is not limited to a workspace or database.
At least four classes evolve under different authorities and rollback mechanisms:

\begin{enumerate}[leftmargin=*,itemsep=1pt]
  \item \emph{reconstructable computation}: files, prompts, model context, plans, cached observations, and staged payloads;
  \item \emph{lifecycle control}: branch epochs, parent/child relations, durable selection, tombstones, restore mode, and merge eligibility;
  \item \emph{authorization state}: grant issuance, scope, ownership, conditional reservations, delegation, revocation, and consumption;
  \item \emph{external history}: messages, payments, disclosures, remote mutations, receipts, and dispatches whose outcome may be uncertain.
\end{enumerate}

A filesystem snapshot covers only part of the first class.
A database transaction may cover one external service but not another.
Capability ownership may be local while revocation is remote.
The safe rollback boundary is therefore a property of the composition, not a single storage technology.

This changes the authorization object.
Current-state reference monitors ask whether action \(a\) is allowed now.
Rollback continuity asks whether one restored continuation extends an accepted prefix.
History-transforming execution asks whether all promises in every set of outcomes that may still coexist can be honored.
Intentional branching is the ordinary path rather than only a fault, and the runtime may rewrite the correlation among futures after claims already exist.

\subsection{Attacker and trusted boundary}

We treat model output and agent-controlled state as adversarial.
The adversary may request documented lifecycle operations, retain an old checkpoint, trigger a crash, synthesize new tool arguments after restore, and control an external tool that creates ambiguous failure.
The adversary cannot forge issuer-approved claim bindings or directly modify the monotone ledger.

The trusted runtime components are an issuer/policy, lifecycle controller, durable ledger, and effect gate.
The controller must durably linearize authority-changing selection, restore, and merge.
The gate must account for a claim before dispatch and either ensure once-only delivery or conservatively retain an uncertain consumption.
If a runtime lets the agent assert “these branches are exclusive,” the theorem does not apply.

\subsection{Effect timing}

The model distinguishes staged and escaped effects, not reads and writes.
A prepared payment held behind a trusted outbox is staged.
As Ghost Tool Calls observes, a speculative query can escape at issue time through provider-visible disclosure~\cite{mohammadi2026ghost}; in our model, disclosure or quota use is charged only when represented by a protected claim coordinate.
An abort can delete staged state.
It cannot make an observer forget or decide that an ambiguous network send never arrived.

Once an effect escapes, its claim can no longer be charged only to its originating branch; the controller must promote it and re-admit the remaining family, acquire compatible capacity, or reject it.

\subsection{Search and reinforcement learning}

The calculus contains no reinforcement-learning primitive.
An adapter may model a hermetic choose-one rollout as exclusive only when no protected effect escapes before selection.
If artifacts from several rollouts are retained, the adapter must supply a merge projection and finite-vector demands for the authority being tracked.
The results then apply to those supplied claims; they do not establish reward, policy-update, privacy-accounting, licensing, or provenance correctness.
