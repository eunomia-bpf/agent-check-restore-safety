This appendix instantiates the proof objects used by \cref{thm:exact-history} over finite registered call models and atomic policy-domain rule versions.

Independent domains retain the product interpretation stated in the paper.

\subsection{The Declarative Definition and the Computed Result}
% 声明式定义与计算结果
\label{app:spec-bridge}

Fix a well-formed safety-check instance \(\Theta=(\kappa,H,\Delta,\mathsf{out},\mathcal A,u)\) for which the edit derivation yields \(\delta=(\kappa_u,H_u,\mathcal A_u,\mathcal C_u,\eta^-,\eta^+)\).
% 固定一个良构的安全检查实例 \(\Theta=(\kappa,H,\Delta,\mathsf{out},\mathcal A,u)\)，其编辑推导给出 \(\delta=(\kappa_u,H_u,\mathcal A_u,\mathcal C_u,\eta^-,\eta^+)\)。
All sets in this subsection retain outcome labels, so two equal resolved words belonging to different outcomes remain different elements.
% 本小节中的所有集合都保留结果标签，因此属于不同结果的两个相同已解析词仍是不同元素。
\begin{definition}[Required source outcomes]
% 要求实现的源结果
\label{def:source-outcomes}
Write \(\mathsf{kind}(u)\) for the constructor of \(u\).
% 以 \(\mathsf{kind}(u)\) 表示 \(u\) 的构造器。
Call either Fork constructor a Fork and either Restore constructor a Restore.
% 将两个 Fork 构造器统称为 Fork，将两个 Restore 构造器统称为 Restore。
For the matching source row in \cref{tab:history-rules}, define
% 对 \cref{tab:history-rules} 中匹配的源规则，定义
\[
\begin{array}{c|c}
u&\mathsf{SrcReg}(H,u)\\ \hline
\text{Fork}&\{(L,\mathcal C),(R,\mathcal C)\}\\
\text{Restore}&\{(\mathsf{cur},\mathcal C),(k,\mathcal C_k)\}\\
\mathsf{MergeSelect}(g,w,\sigma)&
 \{(w,\sem{T_w}),(\bar w,\sem{T_{\bar w}})\}\\
\mathsf{MergeJoin}(g,\sigma)&
 \{(L,\sem{T_L}),(R,\sem{T_R})\}
\end{array}
\]
The full set of source outcomes is
% 完整的源结果集合为
\[
\begin{aligned}
\mathsf{RequiredBefore}(H,u)
={}&(\{\mathsf{ctx}\}\times O_{\rm unchanged})\\
&\uplus
\biguplus_{\substack{(r,\mathcal D)\\
\in\mathsf{SrcReg}(H,u)}}(\{r\}\times O_{\mathcal D}).
\end{aligned}
\]
Write \(\mathsf{Done}_H(r,o)\) when the recorded progress for region \(r\) shows that every event in outcome \(o\)'s pomset has completed.
% 当区域 \(r\) 的进展记录表明结果 \(o\) 的偏序事件集中每个事件都已完成时，记作 \(\mathsf{Done}_H(r,o)\)。
Only \(\mathsf{RestoreReplace}\) treats completed current outcomes as finished:
% 只有 \(\mathsf{RestoreReplace}\) 会把已经完成的当前结果视为已经处理：
\[
\mathsf{DoneCur}_H=
\{(\mathsf{cur},o)\mid
o\in O_{\mathcal C}\land\mathsf{Done}_H(\mathsf{cur},o)\},
\]
\[
\begin{array}{c|c}
u&\mathsf{Satisfied}_{H,u}\\ \hline
\mathsf{RestoreReplace}(b,k,\sigma)&\mathsf{DoneCur}_H\\
\text{otherwise}&\varnothing
\end{array}
\]
Completion observability makes this current-role set either all of \(\{\mathsf{cur}\}\times O_{\mathcal C}\) or empty.
% 完成可观测性使这一当前角色集合要么等于整个 \(\{\mathsf{cur}\}\times O_{\mathcal C}\)，要么为空。
The only sets eligible for signed removal are
% 唯一可以经签名移除的集合为
\[
\mathsf{CurOut}=\{\mathsf{cur}\}\times O_{\mathcal C},
\qquad
\mathsf{Other}_w=\{\bar w\}\times O_{\sem{T_{\bar w}}},
\]
\[
\begin{array}{c|c}
u&\mathsf{CanRemove}(H,u)\\ \hline
\mathsf{RestoreReplace}(b,k,\sigma)&
 \mathsf{CurOut}\setminus\mathsf{Satisfied}_{H,u}\\
\mathsf{MergeSelect}(g,w,\sigma)&\mathsf{Other}_w\\
\text{otherwise}&\varnothing
\end{array}
\]
\(\mathsf{reqauth}_H(a)\) follows \(a\)'s source region to the unique signed authority record in \(G\), or to the stored copy in \(K\) when \(a\) comes from a checkpoint.
% \(\mathsf{reqauth}_H(a)\) 沿 \(a\) 的来源区域找到 \(G\) 中唯一的签名权限记录；若 \(a\) 来自检查点，则找到 \(K\) 中存储的副本。
Context identity, carry, and clone preserve that record, while every source region introduced by an edit rule receives the authority that signed the rule and policy version.
% 上下文恒等映射、携带和克隆都会保持该记录，而编辑规则引入的每个来源区域都会获得为该规则与策略版本签名的权限方。
Thus \(\mathsf{reqauth}_H\) is total and immutable on \(\mathsf{RequiredBefore}(H,u)\), including Fork-created \(L/R\) copies.
% 因此，\(\mathsf{reqauth}_H\) 在 \(\mathsf{RequiredBefore}(H,u)\) 上全定义且不可变，其中包括 Fork 创建的 \(L/R\) 副本。
For every \(a\in\mathsf{CanRemove}(H,u)\), the removal request must contain a signature by \(\mathsf{reqauth}_H(a)\) over
% 对每个 \(a\in\mathsf{CanRemove}(H,u)\)，移除请求必须包含由 \(\mathsf{reqauth}_H(a)\) 对下列内容签发的签名：
\[
\begin{aligned}
\mathsf{rmmsg}(H,u)=(
&\omega,\kappa,\zeta,\sigma,H,\\
&\mathsf{CanRemove}(H,u),\\
&\mathsf{origin}(\mathsf{CanRemove}(H,u))).
\end{aligned}
\]
Without all required signatures, the edit has no derivation.
% 如果缺少任何必需签名，则该编辑没有推导。
With them, \(\mathsf{AuthorizedRemoval}_{H,u}=\mathsf{CanRemove}(H,u)\).
% 如果签名完整，则 \(\mathsf{AuthorizedRemoval}_{H,u}=\mathsf{CanRemove}(H,u)\)。
Write \(\mathsf{Sat}_u=\mathsf{Satisfied}_{H,u}\) and
\(\mathsf{Rm}_u=\mathsf{AuthorizedRemoval}_{H,u}\).
% 记 \(\mathsf{Sat}_u=\mathsf{Satisfied}_{H,u}\)，并记
% \(\mathsf{Rm}_u=\mathsf{AuthorizedRemoval}_{H,u}\)。
The checker requires
% 检查器要求
{\small
\[
\begin{aligned}
\mathsf{StillRequired}_u
 &=\mathsf{RequiredBefore}(H,u)
   \setminus(\mathsf{Sat}_u\uplus\mathsf{Rm}_u),\\
\mathsf{RequiredBefore}(H,u)
 &=\mathsf{StillRequired}_u
   \uplus\mathsf{Sat}_u\uplus\mathsf{Rm}_u.
\end{aligned}
\]
}
\end{definition}

\begin{definition}[Required-outcome preservation]
% 要求实现结果的保留
\label{app:spc}
\[
\begin{aligned}
\mathsf{PreservesRequired}(H,u,\widehat B)
&\Longleftrightarrow
\forall a\in\mathsf{StillRequired}_u.\\[-2pt]
&\qquad\exists(t,y)\in\widehat B.\
\mathsf{Covers}_u(t,a).
\end{aligned}
\]
Here \(\mathsf{AuthorizedRemoval}_{H,u}\) contains the typed unselected-arm outcomes for \(\mathsf{MergeSelect}\) or the current-role outcomes of an authorized \(\mathsf{RestoreReplace}\).
% 此处 \(\mathsf{AuthorizedRemoval}_{H,u}\) 包含 \(\mathsf{MergeSelect}\) 中未被选择分支的类型化结果，或已获授权的 \(\mathsf{RestoreReplace}\) 的当前角色结果。
\(\mathsf{Satisfied}_{H,u}\) contains the completed current role of \(\mathsf{RestoreReplace}\).
% \(\mathsf{Satisfied}_{H,u}\) 包含 \(\mathsf{RestoreReplace}\) 已完成的当前角色。
Both sets are empty for every other row and for a registered extension.
% 对于其余各行和已注册扩展，这两个集合均为空。
Thus \(\mathsf{StillRequired}_u=\mathsf{RequiredBefore}(H,u)\setminus(\mathsf{Satisfied}_{H,u}\uplus\mathsf{AuthorizedRemoval}_{H,u})\), so \(\mathsf{PreservesRequired}\) covers exactly the source outcomes that are neither completed nor authorized for removal.
% 因此 \(\mathsf{StillRequired}_u=\mathsf{RequiredBefore}(H,u)\setminus(\mathsf{Satisfied}_{H,u}\uplus\mathsf{AuthorizedRemoval}_{H,u})\)，所以 \(\mathsf{PreservesRequired}\) 恰好覆盖既未完成、也未获授权移除的源结果。
\end{definition}
Let \(\mathfrak R_\Theta\) be the finite set of safe execution sets from \cref{def:safe-implementation}, ordered componentwise by
% 令 \(\mathfrak R_\Theta\) 为 \cref{def:safe-implementation} 中有限的安全执行集合，并按如下分量关系排序：
\[
 (L_1,\widehat B_1)\sqsubseteq(L_2,\widehat B_2)
 \quad\Longleftrightarrow\quad
 L_1\subseteq L_2\ \land\ \widehat B_1\subseteq\widehat B_2 .
\]

\begin{lemma}[The computed result is exact]
% 计算结果是精确的
\label{lem:app-spec-bridge}
The declarative predicate \(\mathsf{MaxSafe}(\Theta;L,\widehat B)\) holds for some pair if and only if \(\widehat B^\dagger_{H,u}\ne\varnothing\).
% 当且仅当 \(\widehat B^\dagger_{H,u}\ne\varnothing\) 时，声明式谓词 \(\mathsf{MaxSafe}(\Theta;L,\widehat B)\) 才对某个二元组成立。
When such a pair exists, it is unique and equals \((W^\dagger_{H,u},\widehat B^\dagger_{H,u})\).
% 当这样的二元组存在时，它是唯一的，并且等于 \((W^\dagger_{H,u},\widehat B^\dagger_{H,u})\)。
This equality is a theorem relating two independently stated objects, rather than the definition of the ideal machine.
% 这一等式是联系两个独立陈述对象的定理，而不是理想机的定义。
\end{lemma}

\begin{proof}
Let \((L,\widehat B)\in\mathfrak R_\Theta\).
% 令 \((L,\widehat B)\in\mathfrak R_\Theta\)。
The workflow, outcome, and policy requirements give \(\widehat B\subseteq\widehat B_0\).
% 工作流、结果与策略要求给出 \(\widehat B\subseteq\widehat B_0\)。
For every \((o,y)\in\widehat B\), every prefix \(z\preceq_{\rm pref}y\) belongs to \(L=\Pref(\pi_2\widehat B)\).
% 对每个 \((o,y)\in\widehat B\)，每个前缀 \(z\preceq_{\rm pref}y\) 都属于 \(L=\Pref(\pi_2\widehat B)\)。
Persistent outcome coverage therefore supplies, for every \(o'\in\mathsf{Compat}(z)\), a pair \((o',y')\in\widehat B\) extending \(z\).
% 因而，持续结果覆盖为每个 \(o'\in\mathsf{Compat}(z)\) 提供一个扩展 \(z\) 的二元组 \((o',y')\in\widehat B\)。
Thus \(\widehat B\subseteq\widehat\Phi(\widehat B)\).
% 因此 \(\widehat B\subseteq\widehat\Phi(\widehat B)\)。
By monotonicity on the finite lattice \(2^{\widehat B_0}\), every post-fixed set is contained in the greatest fixed point, so \(\widehat B\subseteq\widehat B^\dagger\).
% 由于有限格 \(2^{\widehat B_0}\) 上的单调性，每个后不动点集合都包含于最大不动点，因此 \(\widehat B\subseteq\widehat B^\dagger\)。
Taking projected prefixes yields \(L\subseteq W^\dagger\).
% 对投影取前缀可得 \(L\subseteq W^\dagger\)。

Conversely, suppose \(\widehat B^\dagger\ne\varnothing\).
% 反之，假设 \(\widehat B^\dagger\ne\varnothing\)。
The fixed-point equality keeps every compatible outcome completable and, at \(\epsilon\), combines with the checked preservation maps to establish \(\mathsf{PreservesRequired}\).
% 不动点等式保证每个兼容结果仍可完成，并在 \(\epsilon\) 处与经检查的保持映射组合以建立 \(\mathsf{PreservesRequired}\)。
Inclusion in \(\widehat B_0\) ensures that complete executions follow the target workflow and policy.
% 包含于 \(\widehat B_0\) 保证完整执行遵守目标工作流与策略。
Prefix closure of \(\mathcal A_u\) makes every generated prefix safe, and \(W^\dagger=\Pref(\pi_2\widehat B^\dagger)\) gives a completion after every prefix.
% \(\mathcal A_u\) 的前缀闭包使每个生成前缀安全，而 \(W^\dagger=\Pref(\pi_2\widehat B^\dagger)\) 为每个前缀提供完成方式。
Hence \((W^\dagger,\widehat B^\dagger)\in\mathfrak R_\Theta\), and the preceding containment makes it greatest.
% 因此 \((W^\dagger,\widehat B^\dagger)\in\mathfrak R_\Theta\)，并且前述包含关系使其成为最大元素。
If two greatest elements existed, each would contain the other componentwise, so they would be equal.
% 如果存在两个最大元素，则它们按分量彼此包含，因此必然相等。
If \(\widehat B^\dagger=\varnothing\), the first half places every hypothetical safe execution set inside the empty set, contradicting its required nonemptiness.
% 如果 \(\widehat B^\dagger=\varnothing\)，证明的前半部分会把每个假想安全执行集合包含于空集，这与其必须非空相矛盾。
\end{proof}

\begin{corollary}[Exact checking]
% 精确检查
\label{cor:app-exact-boundary}
The ideal edit transition is enabled by the declarative \(\mathsf{SafeBehavior}(\Theta)\) exactly when the checker returns a nonempty fixed point.
% 理想编辑转移由声明式 \(\mathsf{SafeBehavior}(\Theta)\) 启用，当且仅当检查器返回非空不动点。
On that edge, the ideal language \(L^*\) equals the generated language of \(\mathsf{Can}(W^\dagger,B^\dagger)\).
% 在该边上，理想语言 \(L^*\) 等于 \(\mathsf{Can}(W^\dagger,B^\dagger)\) 的生成语言。
\end{corollary}

\begin{proof}
The first statement is \cref{lem:app-spec-bridge}.
% 第一项陈述即为 \cref{lem:app-spec-bridge}。
The second combines that lemma with \cref{lem:compiled-language}.
% 第二项陈述由该引理与 \cref{lem:compiled-language} 共同得到。
\end{proof}

\begin{proposition}[Output-sensitive checking]
% 输出敏感检查
\label{prop:app-output-complexity}
Fix the unit-cost symbolic-checker model with constant-time finite-map lookup and policy-automaton transitions.
% 固定单位代价的符号检查器模型，其中有限映射查询与策略自动机转移均为常数时间。
Let
% 令
\[
\begin{aligned}
D&=\lvert\Theta\rvert_{\rm chk},&
n&=\max_o\lvert X_{p_o}\rvert,\\
\Lambda&=\sum_o\sum_{w\in\Lin(p_o)}(\lvert w\rvert+1),&
N_B&=\lvert\widehat B_0\rvert,\\
V_B&=\sum_{(o,y)\in\widehat B_0}(\lvert y\rvert+1).
\end{aligned}
\]
\[
\mathcal G_{\rm cov}
=\left\{((o,y),z,o')\ \middle|\
\begin{aligned}
&(o,y)\in\widehat B_0,\ z\preceq y,\\[-2pt]
&o'\in\mathsf{Compat}(z)
\end{aligned}\right\}.
\]
Here \(D\) is the checked input size, \(\Lambda\) is the total size of the emitted linearizations, and \(\mathcal G_{\rm cov}\) contains the candidate, prefix, and required-outcome triples examined by the checker.
% 其中 \(D\) 是所检查输入的大小，\(\Lambda\) 是输出线性化的总大小，而 \(\mathcal G_{\rm cov}\) 包含检查器检查的候选执行、前缀和要求结果三元组。
The checker runs in \(O(D+n\Lambda+|\mathcal G_{\rm cov}|+V_B\log(2+V_B))\) time and \(O(D+\Lambda+|\mathcal G_{\rm cov}|)\) space, including the data it returns.
% 检查器在 \(O(D+n\Lambda+|\mathcal G_{\rm cov}|+V_B\log(2+V_B))\) 时间和 \(O(D+\Lambda+|\mathcal G_{\rm cov}|)\) 空间内运行，其中包括它返回的数据。
Moreover, \(N_B\leq\sum_o|\Lin(p_o)|\), \(|\mathcal G_{\rm cov}|\leq N_B(n+1)|O_{\mathcal C_u}|\), and the number of nonempty strict-removal ranks is at most \(N_B\).
% 此外，\(N_B\leq\sum_o|\Lin(p_o)|\)、\(|\mathcal G_{\rm cov}|\leq N_B(n+1)|O_{\mathcal C_u}|\)，且非空严格移除秩的数量至多为 \(N_B\)。
\end{proposition}

\begin{proof}
A backtracking topological-order enumerator emits all indexed linearizations in \(O(n\Lambda)\) time, while resolution, policy simulation, and construction of raw and resolved prefix tries are linear in emitted volume.
% 回溯式拓扑序枚举器在 \(O(n\Lambda)\) 时间内发出全部带索引线性化，而解析、策略模拟以及原始与已解析前缀字典树的构造关于输出体积均为线性。
For every support key \((z,o')\), maintain the number of remaining pairs \((o',y')\) extending \(z\), initially enqueue candidates having a required outcome with zero support, and remove candidates in synchronous batches.
% 对每个支撑键 \((z,o')\)，维护扩展 \(z\) 的剩余二元组 \((o',y')\) 数量，初始时将某项要求实现结果支持数为零的候选入队，并按同步批次删除候选。
When removal makes a support count zero, enqueue exactly the candidates that depend on that requirement for the next batch.
% 当删除使一个支撑计数变为零时，恰将依赖该要求的候选放入下一批次。
Each candidate and each triple in \(\mathcal G_{\rm cov}\) is processed at most once, and the batches are exactly \(\widehat B_i\setminus\widehat B_{i+1}\).
% 每个候选以及 \(\mathcal G_{\rm cov}\) 中的每个三元组至多处理一次，并且这些批次恰为 \(\widehat B_i\setminus\widehat B_{i+1}\)。
Store one rank and cause per removed candidate rather than copied sets, and construct \(\mathsf{Can}(W,B)\) by bottom-up sorting of finite-trie derivative signatures in \(O(V_B\log(2+V_B))\) time.
% 对每个被删除候选只存储一项秩与原因而不复制集合，并通过自底向上排序有限字典树的导数签名，在 \(O(V_B\log(2+V_B))\) 时间内构造 \(\mathsf{Can}(W,B)\)。
\end{proof}

\subsection{Ordered Rejection Proofs}
% 有序拒绝证明
\label{app:rejection-certificate}

For an empty fixed point, the returned proof is
% 对于空不动点，返回的证明为
\[
C_{\rm fp}=(\widehat B_0,E_0,\ldots,E_k),
\qquad
E_i\subseteq
\widehat B_i\times\Pref(\pi_2\widehat B_i)
\times O_{H,u}.
\]
The verifier first recomputes the canonical \(\widehat B_0(\Theta)\) and requires equality with the serialized first component.
% 验证器首先重新计算规范的 \(\widehat B_0(\Theta)\)，并要求它与序列化的第一分量相等。
An entry \(((o,y),z,o')\in E_i\) verifies exactly when \(z\preceq y\), \(o'\in\mathsf{Compat}(z)\), and no \((o',y')\in\widehat B_i\) extends \(z\).
% 当且仅当 \(z\preceq y\)、\(o'\in\mathsf{Compat}(z)\)，且 \(\widehat B_i\) 中不存在扩展 \(z\) 的 \((o',y')\) 时，条目 \(((o,y),z,o')\in E_i\) 才通过验证。
The verifier requires the set of first components in \(E_i\) to equal \(\widehat B_i\setminus\widehat\Phi(\widehat B_i)\), sets \(\widehat B_{i+1}=\widehat B_i\setminus\pi_1(E_i)\), and accepts only when \(\widehat B_{k+1}=\varnothing\).
% 验证器要求 \(E_i\) 中第一分量的集合恰好等于 \(\widehat B_i\setminus\widehat\Phi(\widehat B_i)\)，令 \(\widehat B_{i+1}=\widehat B_i\setminus\pi_1(E_i)\)，并且只在 \(\widehat B_{k+1}=\varnothing\) 时接受。
All sets, prefixes, and compatibility checks are finite and use the canonical order fixed by the checker.
% 所有集合、前缀与兼容性检查都是有限的，并使用检查器固定的规范次序。

\begin{lemma}[The rejection proof is sound and complete]
% 拒绝证明的可靠性与完备性
The verifier accepts \(C_{\rm fp}\) iff the descending fixed-point computation reaches \(\widehat B^\dagger=\varnothing\).
% 当且仅当下降不动点计算到达 \(\widehat B^\dagger=\varnothing\) 时，验证器才接受 \(C_{\rm fp}\)。
In that case no safe execution set exists.
% 在这种情况下不存在安全执行集合。
\end{lemma}
\begin{proof}
The initial equality check ties the proof to \(\Theta\), and every verified round is exactly \(\widehat B_{i+1}=\widehat\Phi(\widehat B_i)\), so canonical iteration supplies completeness.
% 初始相等性检查把证明与 \(\Theta\) 对应起来，且每个通过验证的轮次都恰为 \(\widehat B_{i+1}=\widehat\Phi(\widehat B_i)\)，因此规范迭代给出完备性。
For soundness, induction places every post-fixed family inside every \(\widehat B_i\), so an empty final family excludes every nonempty safe execution set.
% 对于可靠性，归纳把每个后不动点族包含于每个 \(\widehat B_i\) 中，因此最终族为空会排除每个非空安全执行集合。
\end{proof}

\subsection{Exact Returned Proof Data}
% 精确返回的证明数据
\label{app:certificate-payloads}

Let \(\mathsf{enc}\) be canonical and length-delimited, with \(\kappa\) authenticating \(\mathcal A\).
% 令 \(\mathsf{enc}\) 为规范且带长度分隔的编码，并由 \(\kappa\) 认证 \(\mathcal A\)。
The symbolic LTS uses domain-separated injective authenticated digests \(\mathsf{Digest}_{\rm rules}\) and \(\mathsf{Digest}_{\rm record}\), so equal digests have equal encoded inputs.
% 符号 LTS 使用域分离、单射且经认证的摘要 \(\mathsf{Digest}_{\rm rules}\) 和 \(\mathsf{Digest}_{\rm record}\)，因此相同摘要具有相同的编码输入。
For \(\Theta=(\kappa,H,\Delta,\mathsf{out},\mathcal A,u)\), define
% 对于 \(\Theta=(\kappa,H,\Delta,\mathsf{out},\mathcal A,u)\)，定义
\[
\gamma(\Theta)
 =\mathsf{Digest}_{\rm record}(
   \mathsf{enc}(\mathsf{request},\omega,\zeta,\kappa,
   H,\Delta,\mathsf{out},\mathcal A,u)).
\]
When \(\mathsf{Derive}(\Theta)\) is defined, also define
% 当 \(\mathsf{Derive}(\Theta)\) 有定义时，另定义
\[
\begin{aligned}
\mathsf{aut}_Z
 &=\mathsf{Can}(W^\dagger_{H,u},B^\dagger_{H,u}),\\
H_{\mathsf{aut}}
 &=\mathsf{Digest}_{\rm rules}(
   \mathsf{enc}(\mathsf{aut}_Z,\widehat B^\dagger_{H,u})).
\end{aligned}
\]
The digest checked before the rules change is
% 规则改变前检查的摘要为
\begin{equation}
\label{eq:cut-seal}
\begin{split}
 \mathsf{cut}_Z=
 \mathsf{Digest}_{\rm record}(\mathsf{enc}(&\omega,\zeta,\kappa,H,\Delta,
     \mathsf{out},u,\mathcal C_{H,u},\\[-2pt]
     &H_{\mathsf{aut}},\eta^-,\eta^+)).
\end{split}
\end{equation}
Because \(H\) contains \(\chi,\mathsf{ver},\rho,\beta\), the digest covers workflow progress, record version, registry contents, active rule entries and versions, the authorization log, and the request queue.
% 由于 \(H\) 包含 \(\chi,\mathsf{ver},\rho,\beta\)，该摘要覆盖工作流进展、记录版本、注册表内容、当前规则入口与版本、授权日志和请求队列。
The verifier re-derives the edit-rule judgment and complete fixed point labeled by outcome, reconstructs \((W^\dagger,B^\dagger)\), verifies both digests, and checks the full automaton isomorphism
% 验证器重新推导编辑规则判定与按结果标记的完整不动点，重建 \((W^\dagger,B^\dagger)\)，验证两个摘要，并检查下列完整自动机同构：
\[
 \mathsf{aut}_Z\cong\mathsf{Can}(W^\dagger,B^\dagger),
\]
including its initial state, marking, and every labeled transition.
% 该同构包括初始状态、标记及每个带标签转移。

\begin{proof}[Full proof of \cref{lem:residual-coherence}]
% \cref{lem:residual-coherence} 的完整证明
Because \(z\) prefixes a projected member of \(\widehat B^\dagger\), raw recoverability and streaming in \cref{lem:resolution} give the recoverability and authorization-log equalities.
% 因为 \(z\) 是 \(\widehat B^\dagger\) 某个投影成员的前缀，\cref{lem:resolution} 中的原始词可恢复性和流式性质给出可恢复性等式与授权日志等式。

% 从按结果标记的执行中移除已执行前缀会保留每个兼容结果，并给出
\[
 \mathsf{Compat}_{\mathcal C/\mathsf{raw}(z)}(s)
 =\mathsf{Compat}_{\mathcal C}(zs).
\]
Together with authorization-sequence concatenation, streaming resolution yields
% 结合授权序列串接，流式解析给出
\[
 \widehat B_0(\mathcal C,\Delta)/z
 =\widehat B_0(\mathcal C/\mathsf{raw}(z),\Delta_z),
\]
with the same retained outcome identities, policy, and target registry.
% 且保留的结果标识、策略和目标注册表均相同。

% 因此，\(\widehat B^\dagger/z\) 是残余算子的后不动点，并包含于其最大不动点 \(Y\)。

Greatestness gives \(zY\subseteq\widehat B^\dagger\), hence \(Y=\widehat B^\dagger/z\).
% 最大性给出 \(zY\subseteq\widehat B^\dagger\)，因此 \(Y=\widehat B^\dagger/z\)。
Finally, \(\Pref(B)/z=\Pref(B/z)\) yields the generated-language equality.
% 最后，\(\Pref(B)/z=\Pref(B/z)\) 给出生成语言等式。
\end{proof}

\subsection{Why All Four Parts of the Record Are Necessary}
% 为什么执行记录的四个部分都不可缺少
\label{app:evidence}

We prove that every exact checker needs all four parts of the execution record.
% 我们证明，每个精确检查器都需要执行记录的全部四个部分。
For each omitted part, we construct two valid records that become indistinguishable even though their correct answers are different.
% 对于每个被省略的部分，我们都构造两条有效记录；省略该部分后它们无法区分，但正确答案不同。

Let \(\mathcal Q_{\rm sec}\) pair every valid checked record \(V=\mathsf{Sec}(S;c,r)\) with a well-typed request \(q::=\mathsf{Decide}(u)\mid\mathsf{TryUpdate}(u,Y)\).
% 令 \(\mathcal Q_{\rm sec}\) 将每条有效的经检查记录 \(V=\mathsf{Sec}(S;c,r)\) 与一个良好定型的请求 \(q::=\mathsf{Decide}(u)\mid\mathsf{TryUpdate}(u,Y)\) 配对。
For such a record, let \(\Theta_V(u)=\Theta_S(u)\) and \(\mathsf{Ready}_V(u,Y)=\mathsf{Ready}(S,u,Y)\).
% 对于这样的记录，令 \(\Theta_V(u)=\Theta_S(u)\) 且 \(\mathsf{Ready}_V(u,Y)=\mathsf{Ready}(S,u,Y)\)。
For \(\mathsf{Decide}\), \(\mathsf{Ans}\) returns \(\mathsf{Check}(\Theta_V(u))\).
% 对于 \(\mathsf{Decide}\)，\(\mathsf{Ans}\) 返回 \(\mathsf{Check}(\Theta_V(u))\)。
For \(\mathsf{TryUpdate}\), it returns the updated runtime state exactly when \(\mathsf{Ready}_V(u,Y)\) holds, and returns \(\mathsf{NoCommit}\) otherwise.
% 对于 \(\mathsf{TryUpdate}\)，它恰在 \(\mathsf{Ready}_V(u,Y)\) 成立时返回更新后的运行时状态，否则返回 \(\mathsf{NoCommit}\)。

Internal identifiers may be renamed consistently, while public identifiers remain fixed.
% 内部标识符可以一致重命名，而公开标识符保持不变。
We write \((V,q)\cong(V',q')\) when one type-preserving renaming maps the entire record and request to the other.
% 若一个保持类型的重命名能够把整条记录及请求映射到另一条记录及请求，我们记作 \((V,q)\cong(V',q')\)。
An input function \(f\) is exact when indistinguishable reduced inputs always have the same correct answer up to such a renaming:
% 如果无法区分的缩减输入在这种重命名意义下总具有相同的正确答案，则输入函数 \(f\) 是精确的：
\[
\begin{aligned}
\mathsf{Exact}(f)\Longleftrightarrow {}&
\forall (V_0,q_0)\in\mathcal Q_{\rm sec}.\\[-2pt]
&\forall (V_1,q_1)\in\mathcal Q_{\rm sec}.\\[-2pt]
&(f(V_0),q_0)\cong(f(V_1),q_1)\\[-2pt]
&\Longrightarrow
\mathsf{Ans}(V_0,q_0)\cong\mathsf{Ans}(V_1,q_1).
\end{aligned}
\]

The four parts of the record are as follows.
% 执行记录包含以下四个部分。
\(\mathbf P\) contains the workflow, checkpoints, edit rules, required outcomes, authorized removals, and the authority for each outcome.
% \(\mathbf P\) 包含工作流、检查点、编辑规则、要求实现的结果、获准移除的结果以及每个结果的权限方。
\(\mathbf I\) records which workflow calls refer to the same protected action, together with each action's request, policy label, scope, source region, current rule entry, and authorization data.
% \(\mathbf I\) 记录哪些工作流调用指向同一个受控动作，以及每个动作的请求、策略标签、作用域、来源区域、当前规则入口和授权数据。
\(\mathbf E\) records processed calls, current and saved progress, prior authorizations, retries, returned values, queued requests, and the current policy state.
% \(\mathbf E\) 记录已经处理的调用、当前与已保存进展、先前授权、重试、返回值、排队请求和当前策略状态。
\(\mathbf C\) records the policy version, edit-rule version, execution record version, and active rule version, together with the internal namespace and the digest checked before new rules take effect.
% \(\mathbf C\) 记录策略版本、编辑规则版本、执行记录版本、当前规则版本、内部命名空间以及新规则生效前检查的摘要。
Encodings, digests, authorization sequences, and returned proof data are computed from these four parts rather than treated as additional facts.
% 编码、摘要、授权序列和返回的证明数据都由这四个部分计算得出，而不是额外的事实。

For \(J\subseteq\{\mathbf P,\mathbf I,\mathbf E,\mathbf C\}\), \(\pi_J(V)\) retains the facts in \(J\).
% 对 \(J\subseteq\{\mathbf P,\mathbf I,\mathbf E,\mathbf C\}\)，\(\pi_J(V)\) 保留 \(J\) 中的事实。
It also removes every stored reference to an omitted fact and every computed value that depends on an omitted fact.
% 它还会删除每个指向被省略事实的存储引用，以及每个依赖被省略事实的计算值。
This recursive deletion has a unique result because computed values depend acyclically on the four recorded parts.
% 这种递归删除具有唯一结果，因为计算值对执行记录四个部分的依赖是无环的。
\(\pi_{\neg oc}(V)\) removes only the correspondence between workflow calls and protected actions, together with all data that could reconstruct it.
% \(\pi_{\neg oc}(V)\) 只删除工作流调用与受控动作之间的对应关系，以及所有能够重建该关系的数据。
\(\pi_{\neg ar}(V)\) similarly removes only the correspondence between prior authorization records and protected actions.
% \(\pi_{\neg ar}(V)\) 类似地只删除先前授权记录与受控动作之间的对应关系。

\begin{lemma}[Omitting information is well defined]
% 省略信息是良定义的
\label{lem:app-projection}
Consistent renaming commutes with \(\pi_J\), \(\pi_{\neg oc}\), and \(\pi_{\neg ar}\).
% 一致重命名与 \(\pi_J\)、\(\pi_{\neg oc}\) 和 \(\pi_{\neg ar}\) 可交换。
Their results therefore do not depend on the spelling of internal identifiers or the byte encoding of computed data.
% 因此，它们的结果不依赖内部标识符的拼写或计算数据的字节编码。
\end{lemma}

\begin{proof}
A type-preserving renaming preserves references and dependencies.
% 保持类型的重命名会保持引用与依赖关系。
It therefore maps every deletion step to the corresponding step in the renamed record.
% 因此，它会把每个删除步骤映射到重命名记录中的对应步骤。
Induction over the finite acyclic dependency order proves the result.
% 对有限无环依赖次序作归纳即可证明该结论。
\end{proof}

\begin{lemma}[Opposite answers require distinguishable records]
% 相反答案要求记录可区分
\label{lem:app-observational-separation}
If \(\mathsf{Ans}(V_0,q_0)\not\cong\mathsf{Ans}(V_1,q_1)\), then every exact \(f\) satisfies \((f(V_0),q_0)\not\cong(f(V_1),q_1)\).
% 若 \(\mathsf{Ans}(V_0,q_0)\not\cong\mathsf{Ans}(V_1,q_1)\)，则每个精确的 \(f\) 都满足 \((f(V_0),q_0)\not\cong(f(V_1),q_1)\)。
\end{lemma}

\begin{proof}
The result is the contrapositive of the definition of \(\mathsf{Exact}(f)\).
% 该结论是 \(\mathsf{Exact}(f)\) 定义的逆否命题。
\end{proof}

\subsection{A Common Initial State and Five Record Pairs}
% 一个共同初始状态与五组记录对
\label{app:boot-pairs}

\begin{definition}[Checked registration]
% 经检查的注册
\label{def:registration-refinement}
A boundary-finite typed Agent workflow \(\mathcal W\) is a finite-state outcome-labeled LTS whose complete paths end at outcome terminals and yield finitely many protected-call traces after internal \(\tau\)-steps are erased.
% 边界有限的类型化 Agent 工作流 \(\mathcal W\) 是带结果标签的有限状态 LTS；其完整路径终止于结果终点，并且擦除内部 \(\tau\) 步后只产生有限条受控调用轨迹。
\(\mathsf{CheckReg}\) rejects any reachable strongly connected component that can still reach an outcome and contains a protected-call edge, permits erased \(\tau\)-cycles, and then enumerates the finite classes.
% \(\mathsf{CheckReg}\) 拒绝任何可达、仍可到达结果且包含受控调用边的强连通分量，允许被擦除的 \(\tau\) 环，随后枚举有限等价类。
\(\mathcal R\) stores a candidate map \(\lambda\), and \(\mathsf{BRuns}(\mathcal R)\) is the finite outcome-indexed language obtained by linearizing its registered root pomsets and labeling every workflow call by its protected \Use.
% \(\mathcal R\) 存储候选映射 \(\lambda\)，而 \(\mathsf{BRuns}(\mathcal R)\) 是通过线性化其已注册根偏序事件集，并以受控 \Use 标记每个工作流调用而得到的有限结果索引语言。
\(\mathcal W\sqsubseteq_\lambda\mathcal R\) means that \(\lambda\) gives a bijection from these traces to \(\mathsf{BRuns}(\mathcal R)\) that preserves outcomes, call order, which calls refer to which protected actions, and the signed policy authority for each source region.
% \(\mathcal W\sqsubseteq_\lambda\mathcal R\) 表示 \(\lambda\) 给出从这些轨迹到 \(\mathsf{BRuns}(\mathcal R)\) 的双射，并保持结果、调用次序、哪些调用指向哪些受控动作，以及每个来源区域的签名策略权限方。
For source executions \(e,e'\), write \(e\equiv_\partial e'\) when erasing internal \(\tau\)-steps yields the same outcome-labeled protected-call trace.
% 对于源执行 \(e,e'\)，若擦除内部 \(\tau\) 步后得到相同的带结果标签受控调用轨迹，则记 \(e\equiv_\partial e'\)。
The check requires every protected action to have one certified canonical request and requires every reuse of that action to retain the same request.
% 该检查要求每个受控动作具有唯一经认证的规范请求，并要求每次复用该动作时保持同一个请求。
It also requires \(\lambda\) to be total, unique, and free of unregistered instructions, while preserving prior authorizations and every required outcome.
% 它还要求 \(\lambda\) 全定义、唯一且不含未注册指令，同时保持先前授权和每个要求实现的结果。
\end{definition}

Every pair below starts from a checked initial state and differs in one part of the execution record.
% 下述每组记录对都从经检查的初始状态出发，并且只在执行记录的一个部分上不同。
After that part is omitted, the checker receives indistinguishable inputs even though the correct answers are opposite.
% 省略该部分后，检查器收到无法区分的输入，但正确答案相反。

We construct the finite pairs from one empty initial state \(\mathsf S_\emptyset\).
% 我们从一个空初始状态 \(\mathsf S_\emptyset\) 构造这些有限记录对。
A registered call model \(\mathcal R\) contains finite contracts, edit rules, policy, the checked registration map, and authenticated entries for outcomes, workflow calls, protected actions, canonical requests, source regions, scopes, and labels.
% 已注册调用模型 \(\mathcal R\) 包含有限契约、编辑规则、策略、经检查的注册映射，以及结果、工作流调用、受控动作、规范请求、来源区域、作用域和标签的认证条目。
Before the root rules take effect, it contains no prior authorization, execution progress, queued request, rule version, returned value, or automaton state.
% 根规则生效之前，它不包含先前授权、执行进展、排队请求、规则版本、返回值或自动机状态。
The registration relation has a step \(\mathsf S_\emptyset\xrightarrow{\mathsf{register}(\mathcal W,\mathcal R,n)}\mathsf{Reg}(\mathcal R,n)\) exactly when \(\mathsf{CheckReg}(\mathcal W,\mathcal R)\) accepts and \(n\) is a fresh private namespace.
% 当且仅当 \(\mathsf{CheckReg}(\mathcal W,\mathcal R)\) 接受且 \(n\) 是新的私有命名空间时，注册关系才包含步骤 \(\mathsf S_\emptyset\xrightarrow{\mathsf{register}(\mathcal W,\mathcal R,n)}\mathsf{Reg}(\mathcal R,n)\)。
A checked root update then initializes empty progress and request state, activates one rule version and the canonical automaton, and authenticates every current rule entry and root outcome authority.
% 随后，经检查的根更新初始化空的进展与请求状态，激活一个规则版本及规范自动机，并认证每个当前规则入口和根结果权限方。

\begin{lemma}[Registration reflection]
% 注册反射
\label{lem:registration-reflection}
For finite-state \(\mathcal W\) and finite \(\mathcal R\), \(\mathsf{CheckReg}(\mathcal W,\mathcal R)\) accepts iff the registered \(\lambda\) witnesses \(\mathcal W\sqsubseteq_\lambda\mathcal R\) in \cref{def:registration-refinement}.
% 对于有限状态的 \(\mathcal W\) 与有限的 \(\mathcal R\)，当且仅当已注册的 \(\lambda\) 见证 \cref{def:registration-refinement} 中的 \(\mathcal W\sqsubseteq_\lambda\mathcal R\) 时，\(\mathsf{CheckReg}(\mathcal W,\mathcal R)\) 才接受。
On acceptance, the \(\lambda\)-lowerings of source executions modulo \(\equiv_\partial\) correspond bijectively to \(\mathsf{BRuns}(\mathcal R)\).
% 接受时，模 \(\equiv_\partial\) 的源执行经 \(\lambda\) 降低后与 \(\mathsf{BRuns}(\mathcal R)\) 双射对应。
The correspondence preserves outcome identity, causal order, canonical requests, prior authorizations, and the safety-check answer.
% 该对应保持结果身份、因果次序、规范请求、先前授权和安全检查答案。
\end{lemma}
\begin{proof}
The SCC check terminates because the state graph is finite.
% 强连通分量检查因状态图有限而终止。
A reachable SCC that can still reach an outcome and contains a protected-call edge can be repeated before that outcome, producing projected words of unbounded length.
% 一个可达、仍可到达结果且包含受控调用边的强连通分量可以在该结果之前被反复遍历，从而产生长度无界的投影词。
Conversely, if no such SCC contains a protected-call edge, contracting the SCCs yields a DAG with a finite, enumerable projected language.
% 反之，若此类强连通分量都不含受控调用边，则收缩这些分量会得到具有有限且可枚举投影语言的 DAG。
The checker compares that language with \(\mathsf{BRuns}(\mathcal R)\) and checks outcomes, call order, call-to-action correspondence, protected-action authentication, total unique registration, exclusion of unregistered calls, and prior authorizations after every prefix.
% 检查器将该语言与 \(\mathsf{BRuns}(\mathcal R)\) 比较，并检查结果、调用次序、调用到动作的对应关系、受控动作认证、全定义唯一注册、未注册调用排除，以及每个前缀之后的先前授权。
It therefore accepts exactly when \(\mathcal W\sqsubseteq_\lambda\mathcal R\) holds.
% 因此，它恰在 \(\mathcal W\sqsubseteq_\lambda\mathcal R\) 成立时接受。
Erasing internal steps gives a bijection between matching protected-call traces.
% 擦除内部步骤会在相匹配的受控调用轨迹之间给出一个双射。
Canonical-request equality and deterministic \(\Resolve\) preserve prior authorizations at every prefix.
% 规范请求相等性和确定性的 \(\Resolve\) 会在每个前缀处保持先前授权。
The safe execution sets are therefore order-isomorphic, so the fixed-point operator preserves the safety decision, greatestness, and corresponding automaton.
% 因而，安全执行集合彼此序同构，所以不动点算子保持安全判定、最大性和对应的自动机。
\end{proof}

\begin{lemma}[Checked initial state]
% 经检查的初始状态
\label{lem:app-boot}
If \(\mathsf{CheckReg}(\mathcal W,\mathcal R)\) accepts and the registered root contract and policy have a nonempty greatest safe execution set, the checked root update reaches a finite state \(S_{\mathcal R}\) with \(\mathsf{AgentSec}(S_{\mathcal R};c_{\mathcal R},\epsilon)\).
% 若 \(\mathsf{CheckReg}(\mathcal W,\mathcal R)\) 接受，且已注册根契约与策略具有非空的最大安全执行集合，则经检查的根更新会到达满足 \(\mathsf{AgentSec}(S_{\mathcal R};c_{\mathcal R},\epsilon)\) 的有限状态 \(S_{\mathcal R}\)。
The execution record stores the checked root derivation, and every later rule update stores its checked execution edit or registered extension.
% 执行记录保存经检查的根推导，而此后的每次规则更新都保存其经检查的执行编辑或已注册扩展。
\end{lemma}

\begin{proof}
Registration contributes only the checked \(\mathcal R\) and \(n\), and deterministic allocation constructs every runtime identifier from them.
% 注册只提供经检查的 \(\mathcal R\) 和 \(n\)，而确定性分配据此构造每个运行时标识。
The root judgment and checked lifts establish core/schema coherence, and the recomputed nonempty fixed point establishes required-outcome coherence.
% 根判定与经检查的提升建立核心/模式一致性，而重新计算的非空不动点建立要求实现结果的一致性。
Empty runtime progress establishes execution coherence, the canonical automaton at \(q_\epsilon\) establishes automaton coherence, and the atomic rule-entry assignments establish rule-version coherence.
% 空运行时进展建立执行一致性，位于 \(q_\epsilon\) 的规范自动机建立自动机一致性，而原子的规则入口赋值建立规则版本一致性。
Only the initial rule update creates a root origin, and every successful later update stores its checked execution-edit or registered-extension derivation.
% 只有初始规则更新会创建根来源，而此后的每次成功更新都保存其经检查的执行编辑或已注册扩展推导。
\end{proof}

The following finite pairs use private names except for each displayed request and authorization label.
% 下列有限记录对除所显示的请求和授权标签外均使用私有名称。
Each state is reached from \(\mathsf S_\emptyset\) by the stated registration, initial rule update, Save, protected-call, and edit steps.
% 每个状态都从 \(\mathsf S_\emptyset\) 经由所述注册、初始规则更新、Save、受控调用和编辑步骤到达。

\paragraph{\(\mathbf P\): workflow structure}
% \(\mathbf P\)：工作流结构
Let \(X\) and \(Y\) be singleton contracts with distinct workflow calls \(x\) and \(y\), a shared protected action, and a universal residual policy.
% 令 \(X\) 和 \(Y\) 为具有不同工作流调用 \(x\) 与 \(y\)、共享受控动作和全称残余策略的单元素契约。
From the same registered singleton root, a checked initial rule update followed by \(\mathsf{ForkChoice}\) reaches \(V_{\mathbf P}^0\) with private group \(g_0\), while the corresponding \(\mathsf{ForkParallel}\) trace reaches \(V_{\mathbf P}^1\) with private group \(g_1\).
% 从同一个已注册单元素根出发，经检查的初始规则更新随后执行 \(\mathsf{ForkChoice}\) 会到达具有私有组 \(g_0\) 的 \(V_{\mathbf P}^0\)，而对应的 \(\mathsf{ForkParallel}\) 轨迹会到达具有私有组 \(g_1\) 的 \(V_{\mathbf P}^1\)。
The two records differ only in
% 两条记录仅在下式中不同：
\[
 V_{\mathbf P}^0.T=b_L{:}X\oplus_{g_0}^{\mathsf{open}}b_R{:}Y,
 \qquad
 V_{\mathbf P}^1.T=b_L{:}X\parallel_{g_1} b_R{:}Y .
\]
Use the same registered \(\mathsf{MergeSelect}\) schema with \(q_{\mathbf P}^i=\mathsf{Decide}(\mathsf{MergeSelect}(g_i,L,\sigma))\).
% 使用同一个已注册 \(\mathsf{MergeSelect}\) 模式，并令 \(q_{\mathbf P}^i=\mathsf{Decide}(\mathsf{MergeSelect}(g_i,L,\sigma))\)。
The choice record has a unique edit derivation and a nonempty one-step safe execution set.
% 选择记录具有唯一的编辑推导和非空的一步安全执行集合。
The parallel record has no \(\mathsf{MergeSelect}\) derivation because its group mode is wrong.
% 并行记录由于组模式错误而没有 \(\mathsf{MergeSelect}\) 推导。
Omitting \(\mathbf P\) removes the constructor tag and all computed authentication data that depends on it.
% 省略 \(\mathbf P\) 会删除构造器标签以及依赖该标签的全部计算认证数据。
The private renaming \(g_0\mapsto g_1\) then makes the remaining record-request pairs indistinguishable.
% 此时，私有重命名 \(g_0\mapsto g_1\) 会使剩余的记录与请求对无法区分。

\paragraph{Common start for the correspondence pairs}
% 对应关系记录对的共同起点
Let \(\mathbf 1\) be the singleton-outcome contract whose unique pomset is empty.
% 令 \(\mathbf 1\) 为唯一偏序事件集为空的单结果契约。
Its completion \(\epsilon\) gives a nonempty greatest safe execution set under \(\mathcal A=\Pref\{a\}\).
% 其完成路径 \(\epsilon\) 在 \(\mathcal A=\Pref\{a\}\) 下给出非空的最大安全执行集合。
Both pairs below put these safe root rules into effect and then apply a checked \(\mathsf{ForkChoice}\).
% 下述两组记录对都先让这些安全根规则生效，再应用一次经检查的 \(\mathsf{ForkChoice}\)。
Any inactive edit-rule entry needed to equalize the individual protected actions is identical in both records and never becomes active.
% 为使各个受控动作相同而需要的任何非活动编辑规则条目，在两条记录中都相同且永不生效。

\paragraph{\(\mathbf I\): which calls refer to the same action}
% \(\mathbf I\)：哪些调用指向同一个动作
Let \(X,Y\) be singleton contracts with workflow calls \(x,y\), and let \(d_0,d_1\) be protected actions without authorization records, both labeled \(a\).
% 令 \(X,Y\) 为分别具有工作流调用 \(x,y\) 的单元素契约，并令 \(d_0,d_1\) 为尚无授权记录且标签均为 \(a\) 的受控动作。
Two checked call models contain the same workflow and the same individual calls and actions, but the calls refer to the actions differently:
% 两个经检查的调用模型包含相同的工作流以及相同的各个调用与动作，但调用指向动作的方式不同：
\[
\begin{array}{c|cc}
 &q_{\rm act}(x)&q_{\rm act}(y)\\ \hline
 V_{\mathbf I}^0&d_0&d_0\\
 V_{\mathbf I}^1&d_0&d_1 .
\end{array}
\]
From the \(\mathbf 1\) root now in force, the common Fork rule derives \(b_L{:}X\oplus_g^{\mathsf{open}}b_R{:}Y\).
% 从已经生效的 \(\mathbf 1\) 根出发，公共 Fork 规则派生 \(b_L{:}X\oplus_g^{\mathsf{open}}b_R{:}Y\)。
Each outcome uses one protected action, so both Fork updates are safe under \(\Pref\{a\}\).
% 每个结果使用一个受控动作，所以两次 Fork 更新在 \(\Pref\{a\}\) 下都是安全的。
Save \(b_R\) before progress and issue the common query \(q_{\mathbf I}=\mathsf{Decide}(\mathsf{RestoreLive}(b_L,k,\sigma_{\mathbf I}))\).
% 在取得进展前保存 \(b_R\)，再发出公共查询 \(q_{\mathbf I}=\mathsf{Decide}(\mathsf{RestoreLive}(b_L,k,\sigma_{\mathbf I}))\)。
Up to clone renaming, the target is \((X\otimes Y_k)\oplus Y\).
% 在克隆重命名意义下，目标为 \((X\otimes Y_k)\oplus Y\)。
In \(V_{\mathbf I}^0\), the left outcome uses one \Fresh and one \Alias on \(d_0\), while the bypass outcome uses one \Fresh, so every outcome has authorization sequence \(a\).
% 在 \(V_{\mathbf I}^0\) 中，左侧结果在 \(d_0\) 上使用一次 \Fresh 与一次 \Alias，而绕过结果使用一次 \Fresh，所以每个结果的授权序列都是 \(a\)。
In \(V_{\mathbf I}^1\), every left-outcome linearization uses \Fresh on both \(d_0,d_1\), so its word is \(aa\notin\mathcal A\).
% 在 \(V_{\mathbf I}^1\) 中，左侧结果的每条线性化都在 \(d_0,d_1\) 上使用 \Fresh，所以其权限词为 \(aa\notin\mathcal A\)。
The left outcome is compatible with \(\epsilon\), so the first \(\widehat\Phi\) round also removes the otherwise safe bypass completion and leaves the greatest fixed point empty.
% 左侧结果与 \(\epsilon\) 兼容，因此第一轮 \(\widehat\Phi\) 也会移除本来安全的绕过完成路径，并使最大不动点为空。
Applying \(\pi_{\neg oc}\) makes the remaining records indistinguishable because their individual calls and actions were already identical.
% 应用 \(\pi_{\neg oc}\) 后，剩余记录无法区分，因为它们各自的调用和动作原本就完全相同。

\paragraph{\(\mathbf E\): authorization and execution progress}
% \(\mathbf E\)：授权与执行进展
Let \(C,X\) be singleton contracts with workflow calls \(c,x\), let \(q_{\rm act}(c)=q_{\rm act}(x)=d\), and label \(d\) by \(a\).
% 令 \(C,X\) 为分别具有工作流调用 \(c,x\) 的单元素契约，令 \(q_{\rm act}(c)=q_{\rm act}(x)=d\)，并以 \(a\) 标记 \(d\)。
From the safe \(\mathbf 1\) root, a checked Fork update puts \(b_L{:}C\oplus_g^{\mathsf{open}}b_R{:}X\) into effect.
% 从安全的 \(\mathbf 1\) 根出发，一次经检查的 Fork 更新使 \(b_L{:}C\oplus_g^{\mathsf{open}}b_R{:}X\) 生效。
Save \(b_R\), then use \(c\) to complete the left arm, create authorization record \(p\), and queue its protected request.
% 保存 \(b_R\)，再使用 \(c\) 完成左侧分支、创建授权记录 \(p\)，并将其受控请求加入队列。
At the resulting \(V_{\mathbf E}^0\), check \(u_{\mathbf E}=\mathsf{RestoreReplace}(b_L,k,\sigma_{\mathbf E})\) to obtain \(Y_0\).
% 在所得 \(V_{\mathbf E}^0\) 处，检查 \(u_{\mathbf E}=\mathsf{RestoreReplace}(b_L,k,\sigma_{\mathbf E})\) 并得到 \(Y_0\)。
Its clone of \(x\) reuses \(d\), so the update is safe under \(\mathcal A=\Pref\{a\}\).
% 其 \(x\) 的克隆复用 \(d\)，所以该更新在 \(\mathcal A=\Pref\{a\}\) 下是安全的。
Let \(V_{\mathbf E}^0\xrightarrow{\Dispatch(d)}V_{\mathbf E}^1\), which changes only whether the queued request has been released and leaves \(\mathbf P,\mathbf I,\mathbf C\) unchanged.
% 令 \(V_{\mathbf E}^0\xrightarrow{\Dispatch(d)}V_{\mathbf E}^1\)；该步骤只改变排队请求是否已经发出，并保持 \(\mathbf P,\mathbf I,\mathbf C\) 不变。
For the same request \(q_{\mathbf E}=\mathsf{TryUpdate}(u_{\mathbf E},Y_0)\), the rules take effect at \(V_{\mathbf E}^0\), while \(V_{\mathbf E}^1\) returns \(\mathsf{NoCommit}\) because the digest of the checked record has changed.
% 对于同一个请求 \(q_{\mathbf E}=\mathsf{TryUpdate}(u_{\mathbf E},Y_0)\)，规则在 \(V_{\mathbf E}^0\) 处生效，而 \(V_{\mathbf E}^1\) 因经检查记录的摘要已经改变而返回 \(\mathsf{NoCommit}\)。

\paragraph{\(\pi_{\neg ar}\): which action a prior authorization names}
% \(\pi_{\neg ar}\)：先前授权指向哪个动作
For a separate pair, keep the common active row \(q_{\rm act}(x)=d\), creator \(c\), authorization record \(p\), and protected actions \(d,e\) labeled \(a\), but set \(q_{\rm act}(c)=d\) and \(p\mapsto d\) in \(V_{\neg ar}^0\), versus \(q_{\rm act}(c)=e\) and \(p\mapsto e\) in \(V_{\neg ar}^1\).
% 对于另一对状态，保持共同的当前记录 \(q_{\rm act}(x)=d\)、创建者 \(c\)、授权记录 \(p\) 以及以 \(a\) 标记的受控动作 \(d,e\)，但在 \(V_{\neg ar}^0\) 中令 \(q_{\rm act}(c)=d\) 且 \(p\mapsto d\)，在 \(V_{\neg ar}^1\) 中令 \(q_{\rm act}(c)=e\) 且 \(p\mapsto e\)。
Both states follow the same safe empty-root/ForkChoice/Save/\Fresh shape above, have authorization sequence \(a\), and use the common query \(q_{\neg ar}=\mathsf{Decide}(\mathsf{RestoreReplace}(b_L,k,\sigma_{\neg ar}))\).
% 两个状态都遵循上述安全的空根/ForkChoice/Save/\Fresh 形状，具有授权序列 \(a\)，并使用共同查询 \(q_{\neg ar}=\mathsf{Decide}(\mathsf{RestoreReplace}(b_L,k,\sigma_{\neg ar}))\)。
The cloned \(x_k\) is \(\Alias(x_k,d)\) in \(V_{\neg ar}^0\), but \(\Fresh(x_k,d)\) produces forbidden word \(aa\) in \(V_{\neg ar}^1\).
% 克隆的 \(x_k\) 在 \(V_{\neg ar}^0\) 中为 \(\Alias(x_k,d)\)，而在 \(V_{\neg ar}^1\) 中，\(\Fresh(x_k,d)\) 会产生被禁止的权限词 \(aa\)。
The two records contain the same creator, authorization record, workflow call, and protected actions, and both retain \(x\mapsto d\).
% 两条记录包含相同的创建者、授权记录、工作流调用和受控动作，并且都保留 \(x\mapsto d\)。
\(\pi_{\neg ar}\) removes the only differing correspondence and every value that could reconstruct it, so the remaining records are indistinguishable.
% \(\pi_{\neg ar}\) 删除唯一不同的对应关系以及每个能够重建该关系的值，所以剩余记录无法区分。
This pair proves that an exact checker must know which protected action each prior authorization names.
% 该记录对证明，精确检查器必须知道每项先前授权指向哪个受控动作。

\paragraph{\(\mathbf C\): the active rule version}
% \(\mathbf C\)：当前规则版本
Let a bootstrap namespace be a family \(n=(n_s)_{s\in\mathsf{Sort}}\) of injective, per-sort fresh supplies.
% 令引导命名空间为一族 \(n=(n_s)_{s\in\mathsf{Sort}}\)；其中每个类型的供给均为单射且新鲜。
From the same empty initial state, register the same public call model \(\mathcal R\) with supplies \(n^0,n^1\) that agree on every type except the rule-version type.
% 从同一个空初始状态出发，使用供给 \(n^0,n^1\) 注册同一个公开调用模型 \(\mathcal R\)；二者除规则版本类型外在每个类型上都相同。
The checked root updates create distinct active versions \(\eta_0\ne\eta_1\).
% 经检查的根更新创建不同的当前版本 \(\eta_0\ne\eta_1\)。
The resulting \(V_{\mathbf C}^0,V_{\mathbf C}^1\) have identical \(\mathbf P,\mathbf I,\mathbf E\), while their active rule versions and dependent digests differ.
% 得到的 \(V_{\mathbf C}^0,V_{\mathbf C}^1\) 具有相同的 \(\mathbf P,\mathbf I,\mathbf E\)，但当前规则版本及其依赖摘要不同。
Check the same registered edit \(u_0\) at \(V_{\mathbf C}^0\) to obtain \(Y_0=\mathsf{Accepted}(\delta_0,W_0,\widehat B_0,Z_0)\), then submit \(q_{\mathbf C}=\mathsf{TryUpdate}(u_0,Y_0)\) to both records.
% 在 \(V_{\mathbf C}^0\) 处检查同一个已注册编辑 \(u_0\) 并得到 \(Y_0=\mathsf{Accepted}(\delta_0,W_0,\widehat B_0,Z_0)\)，随后向两条记录提交 \(q_{\mathbf C}=\mathsf{TryUpdate}(u_0,Y_0)\)。
At \(V_{\mathbf C}^0\), the final check reproduces \(\mathsf{cut}_{Z_0}\), so the rules take effect.
% 在 \(V_{\mathbf C}^0\) 处，最终检查重现 \(\mathsf{cut}_{Z_0}\)，所以规则生效。
At \(V_{\mathbf C}^1\), the active version is \(\eta_1\) rather than the \(\eta_0\) recorded in \(Z_0\), so the update returns \(\mathsf{NoCommit}\).
% 在 \(V_{\mathbf C}^1\) 处，当前版本是 \(\eta_1\)，而不是 \(Z_0\) 中记录的 \(\eta_0\)，所以该更新返回 \(\mathsf{NoCommit}\)。
Omitting \(\mathbf C\) also removes dependent rule entries, authorization data, and digests, leaving the record-request pairs indistinguishable.
% 省略 \(\mathbf C\) 还会删除依赖它的规则入口、授权数据和摘要，从而使记录与请求对无法区分。

\begin{proposition}[Four necessary record parts]
% 执行记录的四个必要部分
\label{prop:app-explicit-pairs}
Every pair above consists of finite runtime states reached from the common empty initial state and satisfying \(\mathsf{AgentSec}\).
% 上述每组记录对均由从共同空初始状态到达且满足 \(\mathsf{AgentSec}\) 的有限运行时状态组成。
After the corresponding information is omitted, each pair becomes indistinguishable even though the correct answers are opposite.
% 省略对应信息后，每组记录对都无法区分，但正确答案相反。
Therefore every \(\pi_J\) with \(J\subsetneq\{\mathbf P,\mathbf I,\mathbf E,\mathbf C\}\), as well as \(\pi_{\neg oc}\) and \(\pi_{\neg ar}\), is inexact.
% 因此，每个满足 \(J\subsetneq\{\mathbf P,\mathbf I,\mathbf E,\mathbf C\}\) 的 \(\pi_J\)，以及 \(\pi_{\neg oc}\) 和 \(\pi_{\neg ar}\)，都是不精确的。
Every exact checker input must distinguish all five pairs.
% 每种精确检查器输入都必须区分这五组记录对。
\end{proposition}

\begin{proof}
\Cref{lem:app-boot} gives the common initial state, and the traces above use only modeled Save, protected-call, execution-edit, and rule-update steps.
% \Cref{lem:app-boot} 给出共同初始状态，而上述轨迹只使用已建模的 Save、受控调用、执行编辑和规则更新步骤。
For the two correspondence pairs, the empty root completes with \(\epsilon\), and each Fork arm has a one-\Fresh completion labeled \(a\).
% 对于两组对应关系记录对，空根以 \(\epsilon\) 完成，并且每个 Fork 分支都具有一条标签为 \(a\) 的单次 \Fresh 完成路径。
Hence every displayed state before its request is reachable under \(\Pref\{a\}\).
% 因此，每个显示的请求前状态在 \(\Pref\{a\}\) 下均可达。
Open choice enables the Save steps, and the active automata enable each stated left-arm \Fresh before that arm becomes a completed, still-addressable continuation.
% 开放选择启用这些 Save 步骤，而已生效自动机会在左侧分支成为已完成但仍可寻址的延续之前启用各个所述左侧分支 \Fresh。
For the \(\mathbf E\) pair, \(\Dispatch\) preserves \(\mathbf P,\mathbf I,\mathbf C\) but changes the checked record, giving a successful update versus \(\mathsf{NoCommit}\).
% 对于 \(\mathbf E\) 记录对，\(\Dispatch\) 保持 \(\mathbf P,\mathbf I,\mathbf C\)，但改变经检查的记录，从而分别得到成功更新与 \(\mathsf{NoCommit}\)。
The displayed edit-rule and resolution calculations give the other opposite answers.
% 所显示的编辑规则与解析计算给出其余相反答案。
\Cref{lem:app-projection} and the stated private renamings make the reduced inputs indistinguishable.
% \Cref{lem:app-projection} 与所述私有重命名使缩减后的输入无法区分。
Each omission collapses its corresponding pair, so \cref{lem:app-observational-separation} proves inexactness.
% 每种省略都会合并对应的记录对，因此 \cref{lem:app-observational-separation} 证明其不精确。
\end{proof}

Giving the \(\mathbf P\) pair the same caller-proposed target system and completion conditions leaves their opposite answers unchanged.
% 为 \(\mathbf P\) 记录对提供相同的调用方目标系统和完成条件，仍不会改变它们相反的答案。
The target alone is therefore insufficient.
% 因此，仅有目标是不够的。
A generalized nonblocking solver becomes applicable only after the trusted controller has derived the edited workflow, preserved outcome identities, and outcome-specific completion conditions.
% 只有在可信控制器推导出编辑后的工作流、保留的结果身份以及各结果的完成条件之后，广义非阻塞求解器才适用。

\subsection{Ideal Atomic Execution Machine}
% 理想原子执行机
\label{sec:ideal}

An ideal state \(I=(\kappa,H,\Delta,\mathsf{out},\mathcal A,c,r)\), with \(c=(H_c,u,L^*,\widehat B^*)\), contains the execution record, current rule version and entries, checked safe execution set, and current partial execution.
% 理想状态 \(I=(\kappa,H,\Delta,\mathsf{out},\mathcal A,c,r)\)，其中 \(c=(H_c,u,L^*,\widehat B^*)\)，包含执行记录、当前规则版本与入口、经检查的安全执行集合和当前部分执行。
Write \(\Theta_I(u)=(\kappa,H,\Delta,\mathsf{out},\mathcal A,u)\).
% 记 \(\Theta_I(u)=(\kappa,H,\Delta,\mathsf{out},\mathcal A,u)\)。
The runtime state additionally represents the automaton, transaction phase, authentication data, and a prepared rule update.
% 运行时状态还表示自动机、事务阶段、认证数据和一项已准备的规则更新。

\paragraph{Edit transition}
% 编辑转移
For current \(\Theta_I(u)\), an undefined derivation gives state-preserving \(\mathsf{Invalid}\), while a defined derivation with no \(\mathsf{MaxSafe}\) witness gives state-preserving \(\mathsf{Reject}\).
% 对当前 \(\Theta_I(u)\)，未定义推导给出保持状态的 \(\mathsf{Invalid}\)，而存在推导但没有 \(\mathsf{MaxSafe}\) 见证时给出保持状态的 \(\mathsf{Reject}\)。
Otherwise \(\mathsf{Derive}(\Theta_I(u))\) supplies the target and rule version, and independently defined \(\mathsf{SafeBehavior}(\Theta_I(u))=(L^*,\widehat B^*)\) enables one atomic \(\mathsf{Edge}(u,[\mathcal H_u^+]_{\cong})\) that makes them current and resets \(r\) to \(\epsilon\).
% 否则，\(\mathsf{Derive}(\Theta_I(u))\) 给出目标和规则版本，而独立定义的 \(\mathsf{SafeBehavior}(\Theta_I(u))=(L^*,\widehat B^*)\) 启用一个原子 \(\mathsf{Edge}(u,[\mathcal H_u^+]_{\cong})\)，使二者成为当前值并将 \(r\) 重置为 \(\epsilon\)。
All three answers are computed from the same current execution record and are mutually exclusive and exhaustive.
% 三类答案都由同一条当前执行记录计算得出，并且彼此互斥且穷尽。

\paragraph{Protected call}
% 受控调用
For submitted tool request \(m\), an enabled \(x\) passes the ideal automaton exactly when its current rule entry and authorization data identify protected action \(d\), \(\mathsf{canon}_\kappa(m)=\mathsf{inv}_\rho(d)\), and \(ra\in L^*\).
% 对于提交的工具请求 \(m\)，当且仅当已启用的 \(x\) 的当前规则入口与授权数据指向受控动作 \(d\)、\(\mathsf{canon}_\kappa(m)=\mathsf{inv}_\rho(d)\) 且 \(ra\in L^*\) 时，它才通过理想自动机。
Here \(a=\Fresh(x,d)\) if \(d\) has no authorization record, and \(a=\Alias(x,d)\) otherwise.
% 若 \(d\) 尚无授权记录，则 \(a=\Fresh(x,d)\)；否则 \(a=\Alias(x,d)\)。
One atomic transition applies \(\mathsf{HStep}\), appends \(a\) to \(\chi\), advances \(\mathsf{ver}\), removes \(x\)'s current rule entry, and sets \(r:=ra\).
% 一个原子转移应用 \(\mathsf{HStep}\)、将 \(a\) 追加到 \(\chi\)、推进 \(\mathsf{ver}\)、移除 \(x\) 的当前规则入口并令 \(r:=ra\)。
\Fresh also creates the labeled authorization record and queues the canonical request, while \Alias links to the existing return record.
% \Fresh 还会创建带标签授权记录并将规范请求入队，而 \Alias 会链接到已有返回记录。
Any failed premise returns \(\mathsf{deny}(x)\) without changing state or inventing a return value.
% 任一前提失败都会返回 \(\mathsf{deny}(x)\)，且既不改变状态也不虚构返回值。

\paragraph{Checkpoint, retry, release, and restart}
% 检查点、重试、发出请求与重新启动
\(\mathsf{Save}\), authenticated retry, \(\Dispatch\), completion updates, and restart after a stop have the state changes in \cref{tab:app-event-matrix}.
% \(\mathsf{Save}\)、经认证重试、\(\Dispatch\)、完成状态更新以及停止后的重新启动具有 \cref{tab:app-event-matrix} 中给出的状态变更。
This least-generated LTS represents post-\(\Dispatch\) external-network completion as environmental behavior.
% 这一最小生成的 LTS 把 \(\Dispatch\) 之后的外部网络完成表示为环境行为。

By \cref{lem:most-permissive}, every reachable partial execution of the ideal machine retains a policy-safe completion until the next edit transition changes the workflow contract.
% 根据 \cref{lem:most-permissive}，理想机的每段可达部分执行都会保留一条策略安全完成路径，直到下一次编辑转移改变工作流契约。
The runtime implements this machine without enumerating the full completion set at every call.
% 运行时实现该机器，而无需在每次调用时枚举完整完成路径集合。

\subsection{Runtime State and Atomic Transitions}
% 运行时状态与原子转移
\label{app:compiled-transitions}

For \(\Theta=(\kappa,H,\Delta,\mathsf{out},\mathcal A,u)\), let \(C_{\rm der}(\Theta)\) be the canonical failed-derivation transcript.
% 对于 \(\Theta=(\kappa,H,\Delta,\mathsf{out},\mathcal A,u)\)，检查器恰好返回下列一种结果：
\[
\mathsf{Check}(\Theta)=
\begin{cases}
\mathsf{Invalid}([\gamma(\Theta),C_{\rm der}(\Theta)]_{\cong}),
 &\mathsf{Derive}(\Theta)\text{ undefined};\\
\mathsf{Reject}([\gamma(\Theta),C_{\rm fp}]_{\cong}),
 &\mathsf{Derive}(\Theta)\text{ defined},\
  \widehat B^\dagger_{H,u}=\varnothing.
\end{cases}
\]
When \(\mathsf{Derive}(\Theta)\) is defined and
\(\widehat B^\dagger_{H,u}\ne\varnothing\),
\[
\mathsf{Check}(\Theta)=
\mathsf{Accepted}(\delta,W^\dagger_{H,u},
 \widehat B^\dagger_{H,u},Z).
\]
where
% 其中
\[
 Z=(\omega,\zeta,\kappa_Z,\mathsf{cut}_Z,u,
    H_{\mathsf{aut}},\eta^-,\eta^+).
\]
\(\mathsf{Invalid}\) carries the failed derivation, \(\mathsf{Reject}\) carries the complete ordered rejection proof, and \(\mathsf{Accepted}\) carries the unique derivation, coverage proof, canonical automaton, and \(Z\).
% \(\mathsf{Invalid}\) 携带失败的推导，\(\mathsf{Reject}\) 携带完整的有序拒绝证明，而 \(\mathsf{Accepted}\) 携带唯一推导、覆盖证明、规范自动机和 \(Z\)。
\(Z\) authenticates the checked execution record, derived target, automaton, and both old and new rule versions.
% \(Z\) 认证经检查的执行记录、派生目标、自动机以及新旧规则版本。

The runtime state for one policy domain is
% 一个策略域的运行时状态为
\[
S=(\kappa,H,\Delta,\mathsf{out},\mathcal A,
    \mathsf{phase},\mathsf{entry},\mathsf{aut},\mathsf q,\mathsf{checked}),
\]
where \(\mathsf{phase}\) records whether each rule version \(\eta\) is unallocated (\(\bot\)), inactive, active, or closed.
% 其中 \(\mathsf{phase}\) 记录每个规则版本 \(\eta\) 是未分配（\(\bot\)）、非活动、活动还是已关闭。
The bootstrap rule runs only after \(\mathsf{CheckReg}(\mathcal W,\mathcal R)\) accepts, and its exact construction appears in \cref{app:boot-pairs}.
% 引导规则只在 \(\mathsf{CheckReg}(\mathcal W,\mathcal R)\) 接受后运行，其精确构造见 \cref{app:boot-pairs}。
Each active version stores \(c=(\mathsf{record}_c,H_c^+,u,W,\widehat B,Z)\), which contains the checked execution record, derived target, edit, safe prefixes, outcome-labeled complete executions, and data needed for the final recheck.
% 每个当前版本都保存 \(c=(\mathsf{record}_c,H_c^+,u,W,\widehat B,Z)\)，其中包含经检查的执行记录、派生目标、编辑、安全前缀、按结果标记的完整执行，以及最终重新检查所需的数据。

\begin{definition}[Agent runtime invariant]
% Agent 运行时不变量
\label{def:agent-sec}
For \(c=(\mathsf{record}_c,H_c^+,u,W,\widehat B,Z)\), \(\mathsf{record}_c=(\kappa_c,H_c,\Delta_c,\mathsf{out}_c,\mathcal A_c)\), and resolved \(r\), \(\mathsf{AgentSec}(S;c,r)\) holds exactly when the following clauses hold.
% 对 \(c=(\mathsf{record}_c,H_c^+,u,W,\widehat B,Z)\)、\(\mathsf{record}_c=(\kappa_c,H_c,\Delta_c,\mathsf{out}_c,\mathcal A_c)\) 和已解析词 \(r\)，当且仅当下列条款成立时，\(\mathsf{AgentSec}(S;c,r)\) 成立。
\begin{enumerate}[leftmargin=*,itemsep=0pt,topsep=1pt]
\item \emph{Record and edit-rule coherence.}
% 记录与编辑规则一致性。
The state is well formed, \(c=\mathsf{checked}(H.\eta)\), its origin derives the target now in force, and every required outcome has one authenticated authority and a checked \(\mathsf{Covers}_u\) proof.
% 状态良构，\(c=\mathsf{checked}(H.\eta)\)，其来源推导出当前生效的目标，且每个要求实现的结果都有唯一经认证的权限方和经检查的 \(\mathsf{Covers}_u\) 证明。
\item \emph{Required-outcome coherence.}
% 要求实现结果的一致性。
\(\widehat B=\widehat B^\dagger_{H_c,u}\ne\varnothing\), \(W=\Pref(\pi_2\widehat B)\), and \(Z\) verifies both against \(\mathsf{record}_c\).
% \(\widehat B=\widehat B^\dagger_{H_c,u}\ne\varnothing\)、\(W=\Pref(\pi_2\widehat B)\)，且 \(Z\) 根据 \(\mathsf{record}_c\) 验证二者。
\item \emph{Execution coherence.}
% 执行一致性。
\((H.G,H.T)=\mathsf{HRes}((H_c^+.G,H_c^+.T),r)\), \(H.\chi=H_c^+.\chi r\), and authorization records, queue entries, return links, and checkpoints match \(r\) and advance only monotonically.
% \((H.G,H.T)=\mathsf{HRes}((H_c^+.G,H_c^+.T),r)\)、\(H.\chi=H_c^+.\chi r\)，且授权记录、队列条目、返回链接和检查点都与 \(r\) 一致并仅单调推进。
\item \emph{Automaton coherence.}
% 自动机一致性。
\(\mathsf{aut}(H.\eta)\cong\mathsf{Can}(W,\pi_2\widehat B)\), and \(\mathsf q(H.\eta)\) is its derivative after \(r\).
% \(\mathsf{aut}(H.\eta)\cong\mathsf{Can}(W,\pi_2\widehat B)\)，且 \(\mathsf q(H.\eta)\) 是其在 \(r\) 之后的导数。
\item \emph{Rule-version coherence.}
% 规则版本一致性。
Only \(H.\eta\) is active, \(\mathsf{entry}|_{X_{\sem H.T}}=H.\beta\), and it provides exactly one authenticated rule entry for each current workflow call, while inactive or closed versions provide none.
% 只有 \(H.\eta\) 处于活动状态，\(\mathsf{entry}|_{X_{\sem H.T}}=H.\beta\)，且它为每个当前工作流调用提供唯一认证规则入口，而非活动或已关闭版本不提供任何入口。
\end{enumerate}
\end{definition}

\paragraph{Atomic protected call}
% 原子受控调用
For submitted tool request \(m\), set \(m^\circ=\mathsf{canon}_\kappa(m)\).
% 对于提交的工具请求 \(m\)，令 \(m^\circ=\mathsf{canon}_\kappa(m)\)。
For a call \(x\) with current rule entry \(j\) in version \(\eta\), \(\mathsf{VerifyToken}(h,\rho(x),j,d,m^\circ)\) verifies the call authorization service, scope, rule entry, protected action, source region, and signed digest and requires \(m^\circ=\mathsf{inv}_\rho(d)\).
% 对于在版本 \(\eta\) 中具有当前规则入口 \(j\) 的调用 \(x\)，\(\mathsf{VerifyToken}(h,\rho(x),j,d,m^\circ)\) 验证调用授权服务、作用域、规则入口、受控动作、来源区域和签名摘要，并要求 \(m^\circ=\mathsf{inv}_\rho(d)\)。
Set \(a=\Fresh(x,d)\) if \(d\notin D_\Delta\), otherwise \(a=\Alias(x,d)\), and let \(\Use_x(m)=\mathsf{Use}(x,j,h,m)\).
% 若 \(d\notin D_\Delta\)，则令 \(a=\Fresh(x,d)\)，否则令 \(a=\Alias(x,d)\)，并令 \(\Use_x(m)=\mathsf{Use}(x,j,h,m)\)。
Its sole state-changing transition is
% 其唯一改变状态的转移为
\begin{equation}
\label{eq:use-rule}
\frac{
\begin{gathered}
 x\text{ enabled in }T\quad
 \mathsf{entry}(x)=(j,\eta)\\[-2pt]
 \eta=H.\eta\quad
 \mathsf{phase}(\eta)=\mathsf{active}\\[-2pt]
 \mathsf{VerifyToken}(h,\rho(x),j,d,m^\circ)\quad
 \mathsf q(\eta)\xrightarrow{a}_{\mathsf{aut}(\eta)}q'
\end{gathered}}
{S\xrightarrow{\Use_x(m)/a}S'} .
\end{equation}
The paired update \(\mathsf{HStep}((G,T),a)\) removes \(x\), records any choice, preserves the other workflow constructors, and appends \(a\) to its branch progress.
% 成对更新 \(\mathsf{HStep}((G,T),a)\) 移除 \(x\)、记录任何选择、保留其他工作流构造器，并将 \(a\) 追加到其分支进展。
\(\mathsf{Advance}(S,x,a,q')\) changes exactly
% \(\mathsf{Advance}(S,x,a,q')\) 仅修改
\[
\begin{aligned}
 (H.G,H.T)&:=\mathsf{HStep}((G,T),a),&
 H.\chi&:=\chi a,\\
 H.\mathsf{ver}&:=\mathsf{ver}+1,& H.\beta&:=\beta\setminus\{x\},\\
 \mathsf{entry}&:=\mathsf{entry}\setminus\{x\},&
 \mathsf q(\eta)&:=q'.
\end{aligned}
\]
In addition, \Fresh appends the immutable labeled authorization record and queues the canonical request \((d,\mathsf{inv}_\rho(d))\), never an unchecked caller request.
% 此外，\Fresh 追加不可变的带标签授权记录，并将规范请求 \((d,\mathsf{inv}_\rho(d))\) 加入队列，绝不存储未经检查的调用方请求。
\Alias records the protected action's stored return link without changing \(\Delta\), and all other fields remain unchanged.
% \Alias 记录该受控动作的已存返回链接且不改变 \(\Delta\)，其余字段保持不变。
An authenticated \Retry follows the archived link from \(\chi\) to the authorization record for the same canonical request and returns any stable value without changing state.
% 经认证的 \Retry 沿 \(\chi\) 到同一规范请求授权记录的归档链接执行，并在不改变状态的情况下返回任何稳定值。

\paragraph{Final check and atomic rule update}
% 最终检查与原子规则更新
At the atomic update point, the trusted controller ignores any caller-supplied replacement workflow or rule version, sets \(\Theta_S(u)=(\kappa,H,\Delta,\mathsf{out},\mathcal A,u)\), and re-runs \(\mathsf{Derive}(\Theta_S(u))\) from the current execution record.
% 在原子更新点，可信控制器忽略调用方提供的任何替代工作流或规则版本，令 \(\Theta_S(u)=(\kappa,H,\Delta,\mathsf{out},\mathcal A,u)\)，并根据当前执行记录重新执行 \(\mathsf{Derive}(\Theta_S(u))\)。
For a positive derivation, \(\mathsf{ReCut}(S,u,Z)\) recomputes the right-hand side of \cref{eq:cut-seal}, while \(\mathsf{Verify}_Z\) recomputes the fixed point, coverage proof, canonical automaton, and both digests.
% 对于正面推导，\(\mathsf{ReCut}(S,u,Z)\) 重新计算 \cref{eq:cut-seal} 的右侧，而 \(\mathsf{Verify}_Z\) 重新计算不动点、覆盖证明、规范自动机和两个摘要。
The rules may take effect only if
% 只有满足下列条件，规则才能生效：
\begin{equation}
\label{eq:install-premise}
\begin{gathered}
 \kappa=\kappa_Z,\qquad
 \mathsf{ReCut}(S,u,Z)=\mathsf{cut}_Z,\\
 \mathsf{Verify}_Z(W^\dagger_{H,u},B^\dagger_{H,u},
    \widehat B^\dagger_{H,u}),\\
 H.\eta=\eta^-,\qquad
 \mathsf{phase}(\eta^+)\in\{\bot,\mathsf{inactive}\}.
\end{gathered}
\end{equation}
\(\mathsf{Ready}(S,u,Y)\) holds when \(Y=\mathsf{Accepted}(\delta,W^\dagger,\widehat B^\dagger,Z)\), the current derivation is \(\delta\), and all state-dependent premises of \cref{eq:install-premise} hold.
% 当 \(Y=\mathsf{Accepted}(\delta,W^\dagger,\widehat B^\dagger,Z)\)、当前推导为 \(\delta\) 且 \cref{eq:install-premise} 的全部状态相关前提成立时，\(\mathsf{Ready}(S,u,Y)\) 成立。
The committing domain transaction makes \((\kappa_u,H_u,\mathcal A_u)\) current, closes \(\eta^-\), activates \(\eta^+\), assigns a rule entry to every target workflow call, starts the canonical automaton at \(q^0\), and stores the checked result.
% 提交的域事务使 \((\kappa_u,H_u,\mathcal A_u)\) 成为当前值、关闭 \(\eta^-\)、激活 \(\eta^+\)、为每个目标工作流调用分配规则入口、在 \(q^0\) 处启动规范自动机，并保存经检查的结果。
For this successor, write
\[
c_\delta^+=
(\mathsf{state}(\Theta_S(u)),H_u,u,
 W^\dagger_{H,u},\widehat B^\dagger_{H,u},Z).
\]
% 对这一后继，使用上述 \(c_\delta^+\) 记号。
Only after activation does it expose \(\mathcal H_u^+\) and emit \(\mathsf{Edge}(u,[\mathcal H_u^+]_{\cong})\).
% 只有激活之后，它才暴露 \(\mathcal H_u^+\) 并发出 \(\mathsf{Edge}(u,[\mathcal H_u^+]_{\cong})\)。
Old authorization data then fails, while \Retry still follows its archived authorization-record link.
% 此后旧授权数据失效，而 \Retry 仍沿其归档授权记录链接执行。
A stale result returns \(\mathsf{NoCommit}\) and must be recomputed from the current execution record.
% 过期结果返回 \(\mathsf{NoCommit}\)，并且必须根据当前执行记录重新计算。

\subsection{Atomic Events Preserve the Invariant}
% 原子事件保持不变量
\label{app:event-preservation}

Write \(A_1,\ldots,A_5\) for the five clauses of \(\mathsf{AgentSec}\) in their stated order.
% 依照陈述顺序，用 \(A_1,\ldots,A_5\) 表示 \(\mathsf{AgentSec}\) 的五个条款。

\begin{lemma}[Atomic events are well defined]
% 原子事件是良定义的
\label{lem:app-event-derivative}
The atomic update induces a partial function \(\partial\) on runtime-state and event pairs modulo consistent renaming, written \(\langle V,e\rangle_{\cong}\).
% 原子更新在按一致重命名等价的运行时状态与事件对上诱导偏函数 \(\partial\)，记作 \(\langle V,e\rangle_{\cong}\)。
If \(\mathsf{AgentSec}(S;c,r)\) and \(S\xrightarrow eS'\), the witness in \cref{tab:app-event-matrix} satisfies \(\mathsf{AgentSec}(S';c',r')\) and
% 若 \(\mathsf{AgentSec}(S;c,r)\) 且 \(S\xrightarrow eS'\)，则 \cref{tab:app-event-matrix} 中的见证满足 \(\mathsf{AgentSec}(S';c',r')\)，并且
\[
 [\mathsf{Sec}(S';c',r')]_{\cong}
 =\partial(\langle\mathsf{Sec}(S;c,r),e\rangle_{\cong}).
\]
\end{lemma}

\begin{proof}
All transition rules use typed equality, membership, order, canonical constructors, and authenticated-data equality.
% 所有转移规则只使用类型化相等性、成员关系、次序、规范构造器和认证数据相等性。
These operations are unchanged by consistently renaming private identifiers in the state and event.
% 在状态与事件中一致重命名私有标识符不会改变这些操作。
For an event \(e\), let \(G_e(V)\) be its precondition and \(\mathsf U_e(V)\) its successor update when that precondition holds.
% 对于事件 \(e\)，令 \(G_e(V)\) 为其前提，并令 \(\mathsf U_e(V)\) 为该前提成立时的后继更新。
For every such renaming \(\pi\), \(G_e(V)\Longleftrightarrow G_{\pi e}(\pi V)\) and \(\mathsf U_{\pi e}(\pi V)=\pi\mathsf U_e(V)\).
% 对每个这样的重命名 \(\pi\)，都有 \(G_e(V)\Longleftrightarrow G_{\pi e}(\pi V)\) 且 \(\mathsf U_{\pi e}(\pi V)=\pi\mathsf U_e(V)\)。
Thus consistently renamed inputs have the same definedness and consistently renamed successors.
% 因此，一致重命名的输入具有相同的有定义性和一致重命名的后继。
This proves that \(\partial\) is well defined.
% 这证明 \(\partial\) 是良定义的。

For \Fresh and \Alias, \cref{lem:resolution,lem:residual-coherence,lem:compiled-language} establish the first two rows of the matrix.
% 对于 \Fresh 与 \Alias，\cref{lem:resolution,lem:residual-coherence,lem:compiled-language} 建立表中的前两行。
If \(x\) lies at \(b\), \(\mathsf{HStep}\) appends \(a\) to \(b\)'s progress, while the same atomic protected-call update appends \(a\) to the global resolved-call trace \(\chi\).
% 若 \(x\) 位于 \(b\)，\(\mathsf{HStep}\) 会把 \(a\) 追加到 \(b\) 的进展，而同一个原子受控调用更新会把 \(a\) 追加到全局已解析调用轨迹 \(\chi\)。
Associativity of language quotients gives
% 语言商的结合律给出
\[
 (\Gamma_b/\mathsf{raw}(\chi_b))/x
 =\Gamma_b/\mathsf{raw}(\chi_ba).
\]
Thus the updated leaf and any later Save remain synchronized with \(G\).
% 因此，更新后的叶节点以及此后的任何 Save 都与 \(G\) 保持同步。
For a successful edit transition, \cref{lem:history-derivation,lem:live-extension,lem:app-spec-bridge,lem:compiled-language,lem:cut-linearization} establish the third row for all six edit rules and registered extension.
% 对于成功编辑转移，\cref{lem:history-derivation,lem:live-extension,lem:app-spec-bridge,lem:compiled-language,lem:cut-linearization} 为六条编辑规则与已注册扩展建立表中的第三行。
Each remaining rule changes only the fields shown in the matrix, and its row checks every invariant clause whose fields change.
% 其余每条规则只改变表中显示的字段，而对应行会检查字段发生变化的每个不变量条款。
Thus every successor has the displayed new state and preserves \(\mathsf{AgentSec}\).
% 因此，每个后继都具有所显示的新状态并保持 \(\mathsf{AgentSec}\)。
\end{proof}

\begin{corollary}[Finite-prefix closure]
% 有限前缀闭包
\label{cor:app-prefix-closure}
Starting from any valid bootstrap, every finite prefix of any sequence of the event classes in \cref{tab:app-event-matrix} ends in a state satisfying \(\mathsf{AgentSec}\).
% 从任意有效引导状态出发，\cref{tab:app-event-matrix} 中事件类别所组成任意序列的每个有限前缀都终止于满足 \(\mathsf{AgentSec}\) 的状态。
The sequence length is unbounded, although every individual safety-check instance and event payload is finite.
% 序列长度不受固定上界限制，但每个单独的安全检查实例与事件载荷都是有限的。
For a finite word \(\bar e\), the iterated update is defined on \(\langle V,\bar e\rangle_{\cong}\), where one renaming acts on the initial state and the whole word.
% 对于有限词 \(\bar e\)，迭代更新定义在 \(\langle V,\bar e\rangle_{\cong}\) 上，其中同一次重命名作用于初始状态与整个事件词。
\end{corollary}

\begin{proof}
The base case is \cref{lem:app-boot}, and \cref{lem:app-event-derivative} supplies the invariant-preserving inductive step and consistency under renaming the remaining event suffix.
% 基础情形由 \cref{lem:app-boot} 给出，而 \cref{lem:app-event-derivative} 给出保持不变量的归纳步骤，以及重命名剩余事件后缀时的一致性。
\end{proof}

\subsection{Events Outside the Agent's Control and Restarts}
% Agent 无法控制的事件与重新启动
\label{app:crash}

The resolved alphabet contains only protected calls checked by the runtime automaton.
% 已解析字母表只包含由运行时自动机检查的受控调用。
Agent request arrival, scheduling, completion, delivery, and stop or restart events do not append a \Fresh or \Alias symbol.
% Agent 请求到达、调度、完成、交付以及停止或重新启动事件都不会追加 \Fresh 或 \Alias 符号。
Request arrival and scheduler choice do not change committed runtime state.
% 请求到达与调度器选择不会改变已提交的运行时状态。
Completion updates and delivery emit modeled API observations but leave the checked partial execution unchanged.
% 完成状态更新与交付会发出已建模 API 观测，但保持经检查的部分执行不变。
\(\Dispatch\) is observable only when the oldest queued request is recorded as released, and it also leaves the resolved prefix unchanged.
% 只有在最早排队请求被记录为已发出时，\(\Dispatch\) 才可观测；它同样保持已解析前缀不变。
Therefore none of these events advances the automaton for protected calls.
% 因此，这些事件都不会推进受控调用自动机。

\begin{lemma}[Other events preserve the checked prefix]
% 其他事件保持经检查的前缀
\label{lem:app-uncontrollable}
If \(\mathsf{AgentSec}(S;c,r)\), \(e\) is one of the modeled events above, and \(S\xrightarrow eS'\), then the resolved prefix and canonical automaton state are unchanged and \(\mathsf{AgentSec}(S';c,r)\) holds.
% 若 \(\mathsf{AgentSec}(S;c,r)\)、\(e\) 是上述已建模事件之一且 \(S\xrightarrow eS'\)，则已解析前缀和规范自动机状态保持不变，并且 \(\mathsf{AgentSec}(S';c,r)\) 成立。
\end{lemma}

\begin{proof}
Request arrival and scheduling do not change committed state, while denial, retry, retrieval, delivery, and restart preserve the checked runtime state.
% 请求到达与调度不会改变已提交状态，而拒绝、重试、取回、交付和重新启动会保持经检查的运行时状态。
Request release and completion updates change only the queued-request status, authorization-record status, or stored return record permitted by execution coherence.
% 请求发出与完成状态更新只改变执行一致性所允许的排队请求状态、授权记录状态或已存返回记录。
None changes \(H.T\), \(H.\chi\), the authorization sequence derived from \(\Delta\), \(r\), or \(\mathsf q(\eta)\), and the corresponding row of \cref{tab:app-event-matrix} preserves every other invariant clause.
% 这些事件都不改变 \(H.T\)、\(H.\chi\)、由 \(\Delta\) 推导的授权序列、\(r\) 或 \(\mathsf q(\eta)\)，并且 \cref{tab:app-event-matrix} 中的对应行保持其他每项不变量条款。
\end{proof}

The restart theorem instantiates the storage interface of \cref{sec:model} with linearizable atomic domain transactions.
% 重新启动定理使用可线性化的原子域事务实例化 \cref{sec:model} 的存储接口。
Let \(D\) be the committed runtime state, \(v\) the unfinished in-memory state, and \(\bar t=t_1\cdots t_n\) the finite set of domain transactions overlapping a stop, ordered by their linearization points.
% 令 \(D\) 为已提交的运行时状态，\(v\) 为尚未完成的内存状态，并令 \(\bar t=t_1\cdots t_n\) 为与一次停止重叠的有限域事务集合，按其线性化点排序。
Atomicity selects a prefix \(\bar t_{\leq k}\) containing exactly the transactions that committed before the stop and gives
% 原子性选择前缀 \(\bar t_{\leq k}\)，其中恰好包含停止前已经提交的事务，并给出
\[
\mathsf{Recover}(D,v,\bar t)
 =\mathsf{commit}_{t_k}\circ\cdots\circ
   \mathsf{commit}_{t_1}(D),
\]
with the empty prefix interpreted as \(D\).
% 空前缀解释为 \(D\)。
No state reached after restart contains only part of one modeled atomic update.
% 重新启动后到达的任何状态都不会只包含某项建模原子更新的一部分。
In particular, a \Fresh transaction cannot expose an authorization record without its global trace, branch progress, and queued request.
% 特别地，\Fresh 事务不可能在缺少其全局轨迹、分支进展和排队请求时暴露授权记录。
A rule update cannot activate a new version without closing the old version and assigning every target rule entry.
% 规则更新不可能在未关闭旧版本且未分配全部目标规则入口时激活新版本。

\begin{lemma}[Restart preserves an atomic prefix]
% 重新启动保持原子前缀
\label{lem:app-crash}
Let \(S_0\to S_1\to\cdots\to S_n\) be the modeled path whose atomic transitions correspond to \(t_1,\ldots,t_n\) in the order above.
% 令 \(S_0\to S_1\to\cdots\to S_n\) 为建模路径，其中原子转移依次对应上述顺序中的 \(t_1,\ldots,t_n\)。
If committed state \(D\) refines \(S_0\), then restart after the committed prefix \(t_1\cdots t_k\) yields a state refining \(S_k\).
% 若已提交状态 \(D\) 精化 \(S_0\)，则在已提交前缀 \(t_1\cdots t_k\) 之后重新启动会得到一个精化 \(S_k\) 的状态。
At committed-state boundaries, stopping and restarting without another commit is consequently a \(\tau\) self-loop.
% 在已提交状态边界上，若没有新的提交，停止并重新启动因而是一个 \(\tau\) 自环。
\end{lemma}

\begin{proof}
Induction on \(k\) starts from \(D\) refining \(S_0\).
% 对 \(k\) 作归纳，基础情形由 \(D\) 精化 \(S_0\) 给出。
At each step, the complete atomic update \(\mathsf{commit}_{t_i}\) is the update in the corresponding row of \cref{tab:app-event-matrix}, so it maps a concrete state refining \(S_{i-1}\) to one refining \(S_i\).
% 在每一步中，完整原子更新 \(\mathsf{commit}_{t_i}\) 都是 \cref{tab:app-event-matrix} 对应行中的更新，因此它把精化 \(S_{i-1}\) 的具体状态映射到精化 \(S_i\) 的具体状态。
The recovery equation applies exactly the first \(k\) updates and no partial update, yielding the claim.
% 恢复等式恰好应用前 \(k\) 个更新且不应用任何部分更新，因此得到结论。
Once the LTS records the restarted state, stopping again changes only unfinished memory and is therefore a self-loop.
% 一旦 LTS 记录重新启动后的状态，再次停止只会改变尚未完成的内存，因此是一个自环。
\end{proof}

\subsection{Agent-API Weak Bisimulation After Restart}
% 重新启动后的 Agent API 弱互模拟
\label{app:bisimulation}

We now prove \cref{thm:runtime-correctness} by exhausting the observable and silent cases.
% 现在，我们通过穷尽可观测与静默情形来证明 \cref{thm:runtime-correctness}。
For runtime state \(S=(\kappa,H,\Delta,\mathsf{out},\mathcal A,\ldots)\), define \(\mathsf{Core}(S)=(\kappa,H,\Delta,\mathsf{out},\mathcal A)\) and \(\mathsf{Current}(H)=X_{\sem{H.T}}\).
% 对运行时状态 \(S=(\kappa,H,\Delta,\mathsf{out},\mathcal A,\ldots)\)，定义 \(\mathsf{Core}(S)=(\kappa,H,\Delta,\mathsf{out},\mathcal A)\) 和 \(\mathsf{Current}(H)=X_{\sem{H.T}}\)。
For \(c=(\mathsf{record}_c,H_c^+,u,W,\widehat B,Z)\), define \(\mathsf{icut}(c)=(H_c^+,u,W,\widehat B)\).
% 对 \(c=(\mathsf{record}_c,H_c^+,u,W,\widehat B,Z)\)，定义 \(\mathsf{icut}(c)=(H_c^+,u,W,\widehat B)\)。
For \(I=(K_I,c_I,r_I)\) with \(K_I=(\kappa_I,H_I,\Delta_I,\mathsf{out}_I,\mathcal A_I)\), let
\[
\begin{aligned}
\alpha_I(I)&=(K_I,c_I,r_I,H_I.\eta,H_I.\beta),\\
\alpha_S(S;c,r)&=(\mathsf{Core}(S),\mathsf{icut}(c),r,
 H.\eta,\mathsf{entry}|_{\mathsf{Current}(H)}).

Define \(I\,\mathcal B\,S\) iff some \(c,r\) satisfy \(\mathsf{AgentSec}(S;c,r)\) and \(\alpha_I(I)=\alpha_S(S;c,r)\); write \(\xRightarrow{\ell}=\tau^*\ell\tau^*\) and \(\xRightarrow{\tau}=\tau^*\).
% 定义 \(I\,\mathcal B\,S\) 当且仅当存在 \(c,r\) 满足 \(\mathsf{AgentSec}(S;c,r)\) 与 \(\alpha_I(I)=\alpha_S(S;c,r)\)；记 \(\xRightarrow{\ell}=\tau^*\ell\tau^*\) 且 \(\xRightarrow{\tau}=\tau^*\)。
Fix \(I\,\mathcal B\,S\) with witness \((c,r)\).
% 固定一个以 \((c,r)\) 为见证的 \(I\,\mathcal B\,S\)。
Equality of \(\alpha_I(I)\) and \(\alpha_S(S;c,r)\) gives both machines the same \(\kappa\), current policy, execution record, authorization log, request queue, stored return records, checked safe execution set, current partial execution, rule version, and current rule entries.

\paragraph{Edit transitions}
% 编辑转移
The equality makes both machines form the same current \(\Theta_I(u)\) and record digest \(\gamma(\Theta_I(u))\).
% 该相等关系使两台机器形成相同的当前 \(\Theta_I(u)\) 与记录摘要 \(\gamma(\Theta_I(u))\)。
If derivation is undefined, both sides return the same canonical \(\mathsf{Invalid}\) result and leave their states unchanged.

If derivation exists but no safe execution set exists, \cref{lem:app-spec-bridge} and deterministic fixed-point checking make both sides return the same canonical \(\mathsf{Reject}\) result and leave their states unchanged.
% 若推导存在但不存在安全执行集合，则 \cref{lem:app-spec-bridge} 与确定性不动点检查使两侧返回相同的规范 \(\mathsf{Reject}\) 结果，并保持各自状态不变。
Otherwise the ideal machine enables its edit transition and, by \cref{lem:app-spec-bridge}, the runtime checker accepts the same edit and computes the same largest safe prefix set.
% 否则，理想机启用其编辑转移，并且根据 \cref{lem:app-spec-bridge}，运行时检查器接受同一次编辑并计算相同的最大安全前缀集合。

The ideal side takes its single atomic edge, and both successors have the same \((\kappa_u,H_u,\mathcal A_u)\), checked safe execution set, empty prefix, active rule version, and target rule entries.

Conversely, every successful runtime rule update has passed the edit-rule, fixed-point, and record-digest checks, so \cref{lem:app-spec-bridge} enables the matching ideal edge.

\paragraph{Protected calls and submitted requests}
% 受控调用与提交的请求
For a submitted tool request \(m\), both automata compute the same \(m^\circ=\mathsf{canon}_\kappa(m)\).
% 对于提交的工具请求 \(m\)，两个自动机都会计算相同的 \(m^\circ=\mathsf{canon}_\kappa(m)\)。

% 理想自动机要求相同的规则入口、受控动作和请求相等性。
Both sides then inspect the same set \(D_\Delta\) of protected actions with authorization records, so they choose the same \(a\in\{\Fresh(x,d),\Alias(x,d)\}\).
% 随后，两侧检查相同的已有授权记录受控动作集合 \(D_\Delta\)，因此选择相同的 \(a\in\{\Fresh(x,d),\Alias(x,d)\}\)。
By \cref{cor:app-exact-boundary,lem:compiled-language}, the runtime automaton enables \(a\) after \(r\) exactly when \(ra\in L^*\) in the ideal machine.
% 根据 \cref{cor:app-exact-boundary,lem:compiled-language}，当且仅当理想机中 \(ra\in L^*\) 时，运行时自动机才在 \(r\) 之后启用 \(a\)。

In the \Fresh case, both successors apply the same workflow update, append the same symbol to the global trace and branch progress, advance \(\mathsf{ver}\), create the same authorization record, and queue the same canonical request.
% 在 \Fresh 情形中，两个后继都应用相同的工作流更新、把同一符号追加到全局轨迹与分支进展、推进 \(\mathsf{ver}\)、创建相同的授权记录，并将相同的规范请求加入队列。
The runtime request queue stores \((d,\mathsf{inv}_\rho(d))\), while the ideal queue stores \((d,m^\circ)\).
% 运行时请求队列存储 \((d,\mathsf{inv}_\rho(d))\)，而理想队列存储 \((d,m^\circ)\)。
The verified request equality makes these entries identical.
% 经验证的请求相等性使这些条目完全相同。
In the \Alias case, both successors apply the same workflow update, append the same symbol to the global trace and branch progress, and link the workflow call to the same stored return record without changing \(\Delta\) or the request queue.
% 在 \Alias 情形中，两个后继都应用相同的工作流更新、把同一个符号追加到全局轨迹与分支进展，并将该工作流调用链接到同一已存返回记录，而不改变 \(\Delta\) 或请求队列。
Both successors remove \(x\)'s current rule entry.
% 两个后继都移除 \(x\) 的当前规则入口。
Because the remaining workflow no longer contains \(x\), their current-rule-entry components remain equal.
% 由于剩余工作流不再包含 \(x\)，它们的当前规则入口分量仍然相等。
In either case, \cref{lem:app-event-derivative} re-establishes \(\mathcal B\) with witness \((c,ra)\).
% 在任一情形中，\cref{lem:app-event-derivative} 都以 \((c,ra)\) 为见证重新建立 \(\mathcal B\)。

If any workflow call, rule entry, authorization datum, canonical request, rule version, branch, or automaton transition check fails, both automata fail.
% 如果任何工作流调用、规则入口、授权数据、规范请求、规则版本、分支或自动机转移检查失败，则两个自动机都会失败。
Both machines emit \(\mathsf{deny}(x)\), preserve state, and remain related.
% 两台机器都会发出 \(\mathsf{deny}(x)\)、保持状态并维持相关关系。

\paragraph{Races between a protected call and a rule update}
% 受控调用与规则更新之间的竞态
Protected calls and rule updates serialize on the same execution record and active rule version.
% 受控调用与规则更新会在同一执行记录和当前规则版本上串行化。
If a \Fresh use commits first, it changes \((G,T,\Delta,\chi,\mathsf{ver},\mathsf{out})\), all of which are covered by the digest of the checked record, so the prepared rule update becomes stale.
% 如果 \Fresh 使用先提交，它会改变 \((G,T,\Delta,\chi,\mathsf{ver},\mathsf{out})\)，这些字段都由经检查记录的摘要覆盖，因此已准备的规则更新会过期。
If an \Alias use commits first, it changes \((G,T,\chi,\mathsf{ver})\) even though \(\Delta\) and the request queue are unchanged, so the prepared rule update again becomes stale.
% 如果 \Alias 使用先提交，即使 \(\Delta\) 和请求队列不变，它仍会改变 \((G,T,\chi,\mathsf{ver})\)，因此已准备的规则更新同样会过期。
If the rule update commits first, it atomically closes \(\eta^-\), activates \(\eta^+\), refreshes every current rule entry and its authorization data, and exposes the new authorization data only after activation.
% 如果规则更新先提交，它会原子关闭 \(\eta^-\)、激活 \(\eta^+\)、刷新每个当前规则入口及其授权数据，并且只在激活之后暴露新授权数据。
The old \Fresh or \Alias use then fails the current-rule-version automaton and is denied without progress.
% 此时，旧的 \Fresh 或 \Alias 使用无法通过当前规则版本自动机，并在不产生进度的情况下被拒绝。
The ideal atomic order has exactly the same two cases, so neither side admits a third race outcome.
% 理想原子顺序恰好具有相同的两种情形，因此任一侧都不会接纳第三种竞态结果。

\paragraph{Replies, releases, and silent steps}
% 回复、释放与静默步骤
An authenticated retry, authorization-data retrieval, or result delivery leaves the runtime state unchanged and follows the same authenticated link on both sides to expose \(\mathsf{Return}(t,[v]_{\cong})\).
% 经认证重试、授权数据取回或结果交付不改变运行时状态，并在两侧沿相同认证链接暴露 \(\mathsf{Return}(t,[v]_{\cong})\)。
\(\Dispatch(d)\) is enabled for the same oldest queued request and makes the same observable release update.
% \(\Dispatch(d)\) 对相同的最早排队请求启用，并产生相同的可观测发出更新。
\(\mathsf{Settle}(d,[v]_{\cong})\) is enabled for the same authorization record and produces the same stable result and normalized update.
% \(\mathsf{Settle}(d,[v]_{\cong})\) 对相同授权记录启用，并产生相同的稳定结果与规范化更新。
\(\mathsf{Save}\) takes matching \(\tau\)-steps.
% \(\mathsf{Save}\) 执行匹配的 \(\tau\) 步。
Runtime preload and internal \(\mathsf{NoCommit}\) results are \(\tau\)-steps matched by zero ideal steps because \(\alpha_S\) omits inactive prepared data and \(\mathsf{obs}_{\rm api}\) hides internal controller results.
% 运行时预加载与内部 \(\mathsf{NoCommit}\) 结果是由零个理想步骤匹配的 \(\tau\) 步，因为 \(\alpha_S\) 忽略非活动的准备数据，而 \(\mathsf{obs}_{\rm api}\) 隐藏内部控制器结果。
Stopping and restarting is matched by a \(\tau\) self-loop on each committed-state machine by \cref{lem:app-crash}.
% 根据 \cref{lem:app-crash}，停止并重新启动在每台已提交状态机上都由一个 \(\tau\) 自环匹配。

\begin{theorem}[Agent-API weak bisimulation after restart, detailed]
% 重新启动后的 Agent API 弱互模拟，详细形式
\label{thm:app-bisimulation}
\(\mathcal B\) is a divergence-insensitive weak bisimulation under \(\mathsf{obs}_{\rm api}\).
% \(\mathcal B\) 在 \(\mathsf{obs}_{\rm api}\) 下是发散不敏感弱互模拟。
\end{theorem}

\begin{proof}
The least-generated rule sets in \cref{sec:ideal,sec:enforcement} and \cref{tab:app-event-matrix} make the preceding cases exhaustive.
% \cref{sec:ideal,sec:enforcement} 中的最小生成规则集与 \cref{tab:app-event-matrix} 使前述情形具有穷尽性。
For every step from either side, the corresponding case constructs a path with observation \(\mathsf{obs}_{\rm api}(\ell)\) and a successor related by the witness in that matrix.
% 对任一侧的每一步，对应情形都会构造一条观测为 \(\mathsf{obs}_{\rm api}(\ell)\) 的路径，以及一个通过该表中见证相关的后继。
The construction is symmetric because the ideal and runtime automata accept the same protected calls, while runtime-only steps preserve their common visible state.
% 该构造是对称的，因为理想自动机与运行时自动机接受相同的受控调用，而仅属于运行时的步骤保持二者共同的可见状态。
Arbitrary repetition of silent preload, internal \(\mathsf{NoCommit}\), Save, or restart steps is ignored, which is precisely divergence-insensitive weak matching.
% 任意重复的静默预加载、内部 \(\mathsf{NoCommit}\)、Save 或重新启动步骤均被忽略，这恰是发散不敏感弱匹配。
\end{proof}
