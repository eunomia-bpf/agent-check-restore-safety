\section{Introduction}
% 引言
\label{sec:introduction}

Tool-using Agent runtimes no longer follow only one linear plan.
% 使用工具的 Agent 运行时不再只遵循一条线性计划。
They let an Agent Fork an execution into alternatives, Restore an earlier checkpoint, and Merge branches~\cite{codexappserver,claudesessions,claudecheckpoint,wang2026fork,wu2026crab,zhang2026agentlibos}.
% 它们允许 Agent 将一次执行 Fork 为多个备选方案、Restore 到较早的检查点，并 Merge 多个分支~\cite{codexappserver,claudesessions,claudecheckpoint,wang2026fork,wu2026crab,zhang2026agentlibos}。
These operations support exploration, recovery, and reuse without restarting the task.
% 这些操作支持探索、恢复与复用，而无需重新开始任务。
We call them \emph{execution edits} because they change which parts of the workflow will run next.
% 我们把它们称为\emph{执行编辑}，因为它们会改变工作流接下来执行哪些部分。

An execution edit does not undo earlier tool calls.
% 执行编辑不会撤销先前的工具调用。
Suppose an Agent saves checkpoint \(k\) before a protected approval.
% 设一个 Agent 在受控审批前保存检查点 \(k\)。
The approval is later authorized once, creating an authorization record that Restore does not delete.
% 审批随后只获得一次授权，并创建一条 Restore 不会删除的授权记录。
Restoring \(k\) creates another approval call in the workflow, but it must not authorize the same approval again.
% Restore 到 \(k\) 会在工作流中创建另一个审批调用，但不得再次授权同一审批。
A concurrent Merge can cause a similar error by selecting supplier \(L\) after a supplier-\(R\) payment has already been authorized.
% 并发的 Merge 也会造成类似错误，例如在供应商 \(R\) 的付款已经获得授权后再选择供应商 \(L\)。
An edit can therefore restore the saved program state yet violate authorization or release order; the remote service reports physical completion separately through an authenticated completion record.
% 因此，一次编辑即使恢复了保存的程序状态，仍可能违反授权或发出顺序；远端服务通过单独的认证完成记录报告物理完成。

The problem is that a checkpoint contains only part of the information needed to decide whether an edit is safe.
% 问题在于，检查点只包含决定一次编辑是否安全所需的部分信息。
The controller must also know four things: which outcomes remain required, which call positions refer to the same protected action, which actions have already been authorized, and which runtime version governs a call that overlaps the edit.
% 控制器还必须知道四件事：哪些结果仍然是要求、哪些调用位置指向同一个受控动作、哪些动作已经获得授权，以及哪个运行时版本管理与编辑重叠的调用。
Each can change the correct answer.
% 每一项都可能改变正确答案。
The controller cannot recover all four from equal workspaces, an execution trace alone, an authorization log alone, or a replacement workflow proposed by the Agent.
% 控制器无法仅从相同工作区、单独的执行轨迹、单独的授权日志，或 Agent 提出的替代工作流中恢复全部四项信息。

Existing approaches cover parts of this problem but do not derive its complete safety condition.
% 现有方法覆盖了该问题的部分环节，却没有推导其完整安全条件。
Agent systems provide branching, staged effects, transactions, or recovery checks~\cite{yu2026shepherd,li2025agentgit,langchain2026timetravel,patil2024goex,chang2025sagallm,mohammadi2026atomix,chen2026cordon,yang2026dart}.
% Agent 系统提供分支、分阶段效果、事务或恢复检查~\cite{yu2026shepherd,li2025agentgit,langchain2026timetravel,patil2024goex,chang2025sagallm,mohammadi2026atomix,chen2026cordon,yang2026dart}。
Control and synthesis choose behavior after a model of possible executions and desired final states has been supplied~\cite{dequeiroz2005multitasking,malik2008generalised,finkbeiner2022live,aceto2018suppressions}.
% 控制与综合方法则在可能执行及期望最终状态的模型已经给定后选择行为~\cite{dequeiroz2005multitasking,malik2008generalised,finkbeiner2022live,aceto2018suppressions}。
Neither line of work derives from a recorded execution everything that a particular edit must preserve before it takes effect.
% 这两类工作都不会从已有执行记录中推导出某次具体编辑在生效前必须保留的全部内容。

Our key idea is that an execution edit must preserve both past actions and still-required outcomes.
% 我们的关键思想是：执行编辑必须同时保留过去的动作和仍然要求实现的结果。
Every outcome required before the edit must remain required, already be satisfied by the recorded execution, or be explicitly removed by the same authority that required it.
% 编辑前要求实现的每个结果都必须继续作为要求、已经由所记录的执行满足，或由提出该要求的同一权限方明确移除。
The Agent selects only a registered edit.
% Agent 只能选择一项已注册编辑。
The platform authenticates the registered workflow, and the trusted controller derives the edited workflow and inherited requirements from that record rather than from Agent text.
% 平台认证已注册工作流，可信控制器根据该记录而非 Agent 文本推导编辑后的工作流及其继承的要求。
The Agent therefore cannot obtain a favorable answer by submitting a replacement workflow that hides inconvenient facts.
% 因此，Agent 无法通过提交一个隐藏不利事实的替代工作流来获得有利答案。

This idea creates three technical problems.
% 这一思想带来三个技术问题。
First, calls copied by Fork or Restore may refer to the same protected action, so the controller must distinguish a new action from reuse of an earlier call and return value.
% 第一，由 Fork 或 Restore 复制的调用可能指向同一个受控动作，因此控制器必须区分新动作与对先前调用及返回值的复用。
Second, after every allowed partial execution, every outcome that is still required and still possible must retain a safe way to finish.
% 第二，在每段允许的部分执行之后，每个仍被要求且仍有可能实现的结果都必须保留安全完成方式。
The checker must enforce this condition without forbidding additional safe behavior.
% 检查器必须执行这一条件，同时不能额外禁止安全行为。
Third, the answer must take effect atomically with calls that overlap the edit and remain valid if the runtime or machine stops unexpectedly and later recovers.
% 第三，该答案必须与重叠编辑的调用原子排序，并在运行时或机器意外停止后恢复时继续有效。

We give an exact checker for execution edits: it accepts exactly when a safe implementation exists under the model defined in \cref{sec:model}.
% 我们给出一个针对执行编辑的精确检查器：在 \cref{sec:model} 定义的模型下，它当且仅当安全实现存在时才接受。
For a requested edit, the controller uses the registered workflow and current authenticated state to construct every allowed completed execution.
% 对于一次编辑请求，控制器使用已注册工作流和当前认证状态构造所有允许的完整执行。
It removes an execution whenever one of its partial executions would leave a still-required outcome with no safe completion.
% 如果某个完整执行的部分过程会让仍然要求实现的结果失去安全完成方式，检查器就删除该完整执行。
If no execution remains, the controller returns an independently checkable rejection explanation.
% 如果没有完整执行留下，控制器返回一份可独立检查的拒绝说明。
Otherwise, the remaining executions define the most permissive safe monitor.
% 否则，剩余执行定义限制最少的安全监控器。
Before the edit takes effect, the runtime checks the current authenticated state again and atomically replaces the old monitor.
% 编辑生效之前，运行时再次检查当前认证状态并原子替换旧监控器。
Every overlapping call is therefore governed entirely by either the old monitor or the new one.
% 因此，每个重叠调用都完全由旧监控器或新监控器管理。
\Cref{sec:lifecycle} derives this process for a protected approval workflow containing Fork, Merge, both installation races, and Restore.
% \Cref{sec:lifecycle} 针对一个包含 Fork、Merge、两类安装竞态与 Restore 的受控审批工作流推导这一过程。
After Restore, the repeated approval call reuses the earlier authorization record instead of authorizing the approval again.
% Restore 之后，重复的审批调用复用先前的授权记录，而不会再次授权该审批。

\paragraph{Contributions}
% 贡献
We contribute one end-to-end theorem connecting the original Agent workflow, the requested execution edit, the exact checker, and the installed runtime.
% 我们贡献一个端到端定理，将原始 Agent 工作流、请求的执行编辑、精确检查器与已安装运行时连接起来。
For all six registered execution edits and registered extensions, a safe implementation exists exactly when the checker leaves a nonempty set of executions, its monitor can be installed, and an ideal atomic machine permits the same edit.
% 对全部六种已注册执行编辑和已注册扩展，当且仅当检查器留下非空执行集合、其监控器能够安装且理想原子机器允许同一次编辑时，安全实现才存在。
The theorem also proves that an exact checker cannot discard workflow structure, the mapping from call positions to protected actions, prior authorization state, or the current monitor version, and that the concrete runtime has the same visible behavior as the ideal machine (\cref{sec:model,sec:admission,sec:enforcement,sec:results}).
% 该定理还证明，精确检查器不能丢弃工作流结构、调用位置到受控动作的映射、既有授权状态或当前监控器版本，并证明具体运行时与理想机器具有相同的可见行为（\cref{sec:model,sec:admission,sec:enforcement,sec:results}）。
Every supported event preserves the security invariant, so the theorem applies again after every finite reachable execution.
% 每个受支持事件都保持安全不变量，因此该定理能在每个有限可达执行之后再次应用。
Six Lean modules mechanize the central theorem chain; 19 paper-specific executable tests and measurements over 2--128 outcomes exercise the checker and edit-installation races.
% 六个 Lean 模块机械化核心定理链；19 项论文专用可执行测试与覆盖 2--128 个结果的测量检验检查器及编辑安装竞态。
