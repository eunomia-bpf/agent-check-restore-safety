\section{Introduction}
% 引言
\label{sec:introduction}

Tool-using Agents no longer execute only one linear plan.
% 使用工具的 Agent 不再只执行一条线性计划。
Modern runtimes let an Agent Fork live continuations, Restore a checkpoint, and Merge descendants~\cite{codexappserver,claudesessions,claudecheckpoint,wang2026fork,wu2026crab,zhang2026agentlibos}.
% 现代运行时允许 Agent Fork 活跃延续、Restore 检查点并 Merge 后代~\cite{codexappserver,claudesessions,claudecheckpoint,wang2026fork,wu2026crab,zhang2026agentlibos}。
These operations support exploration, recovery, and reuse without restarting the whole task.
% 这些操作支持探索、恢复与复用，而无需重新开始整个任务。
Consequently, an Agent's logical execution history becomes mutable runtime state.
% 因此，Agent 的逻辑执行历史成为可变的运行时状态。

However, the world does not rewind with that history.
% 然而，现实世界不会随这段历史一起倒转。
In our running procurement example, the Agent saves checkpoint \(k\) before approval, the approval later commits, and a Restore of \(k\) creates a new logical approval occurrence while the old receipt remains.
% 在贯穿全文的采购例子中，Agent 在审批前保存检查点 \(k\)，审批随后提交，而对 \(k\) 的 Restore 会创建一个新的逻辑审批发生项，同时旧回执仍然存在。
Treating that occurrence as new can repeat the approval, while selecting supplier \(L\) in a Merge as an old supplier-\(R\) payment commits can authorize both branches.
% 将该发生项视为全新调用可能重复审批，而在旧供应商 \(R\) 的付款提交时通过 Merge 选择供应商 \(L\)，则可能同时授权两个分支。
A checkpoint-correct edit can therefore be security-wrong.
% 因此，一次对检查点而言正确的编辑，在安全性上仍可能错误。

The root cause is that a checkpoint records only part of the facts that determine whether an edit is safe.
% 根因在于，检查点只记录了决定一次编辑是否安全的部分事实。
The controller must also know which results the old execution still promises, which logical calls refer to the same irreversible action, which effects have already advanced, and the exact moment at which the edit takes effect.
% 控制器还必须知道旧执行仍然承诺哪些结果、哪些逻辑调用指向同一个不可逆动作、哪些效果已经推进，以及编辑生效的精确时刻。
Each fact can change the correct decision.
% 每项事实都可能改变正确判定。
None can be reconstructed from workspace equality, a trace or receipt ledger alone, or a new target proposed by the caller.
% 这些事实都无法仅从工作区相等性、单独的轨迹或回执账本，或者调用方提出的新目标中恢复。

Existing approaches cover pieces of this problem but do not derive its end-to-end admission boundary.
% 现有方法覆盖了该问题的部分环节，却没有推导其端到端准入边界。
Agent systems provide branching, staged effects, transactions, or recovery checks~\cite{yu2026shepherd,li2025agentgit,langchain2026timetravel,patil2024goex,chang2025sagallm,mohammadi2026atomix,chen2026cordon,yang2026dart}.
% Agent 系统提供分支、分阶段效果、事务或恢复检查~\cite{yu2026shepherd,li2025agentgit,langchain2026timetravel,patil2024goex,chang2025sagallm,mohammadi2026atomix,chen2026cordon,yang2026dart}。
Control and synthesis choose behavior after a model of possible executions and desired final states has been supplied~\cite{dequeiroz2005multitasking,malik2008generalised,finkbeiner2022live,aceto2018suppressions}.
% 控制与综合方法则在可能执行及期望最终状态的模型已经给定后选择行为~\cite{dequeiroz2005multitasking,malik2008generalised,finkbeiner2022live,aceto2018suppressions}。
Neither line of work by itself derives, from an authenticated editable history, everything that a particular edit must preserve before that edit can be installed.
% 这两类工作本身都不会从经认证的可编辑历史中推导出某次具体编辑在安装前必须保留的全部内容。

Our key idea is that a history edit must not make old facts or unfinished promises disappear.
% 我们的关键思想是：历史编辑不能让旧事实或尚未完成的承诺消失。
After an edit, every old promise must still be required, have durable evidence that it was completed, or have been explicitly canceled by the authority that created it.
% 编辑之后，每项旧承诺都必须继续有效、已有持久证据证明其完成，或已由创建它的权限方明确取消。
The Agent chooses only a registered operation; the trusted controller determines which promises and past effects carry into the result.
% Agent 只能选择一项已注册操作；可信控制器决定哪些承诺与既往效果必须带入结果。
The Agent therefore cannot obtain a favorable answer by proposing a weaker version of its own past.
% 因此，Agent 无法通过提出一个更弱的自身过去来获得有利判定。

Realizing this insight requires solving three coupled problems.
% 实现这一洞见需要解决三个相互耦合的问题。
First, calls copied by Fork or Restore may still refer to the same real-world action, so the controller must distinguish a genuinely new effect from reuse of an earlier result.
% 第一，由 Fork 或 Restore 复制的调用仍可能指向同一个现实动作，因此控制器必须区分真正的新效果与对旧结果的复用。
Second, at every allowed partial execution, each result that is still possible must retain a safe way to finish, without forbidding more behavior than safety requires.
% 第二，在每段允许的部分执行处，每个仍然可能的结果都必须保留一条安全完成路径，同时不能禁止超出安全所需的行为。
Third, the answer must take effect atomically with respect to old calls, including calls that race the edit or survive a crash.
% 第三，该判定必须相对于旧调用原子生效，包括与编辑竞态或跨越崩溃存活的调用。

We develop \sys, an exact decision procedure for this boundary.
% 我们提出 Agent 历史准入，即针对这一边界的精确判定过程。
For a requested edit, the controller takes the checked workflow, authenticated history, receipts, pending effects, policy, and current runtime version, and derives all legal completed executions.
% 对于一次编辑请求，控制器接收经检查的工作流、经认证历史、回执、待处理效果、策略与当前运行时版本，并推导所有合法完整执行。
It repeatedly removes any execution having a prefix after which one still-possible promised result can no longer finish safely.
% 它反复删除这样的执行：在该执行的某个前缀之后，某个仍可能且已承诺的结果再也无法安全完成。
If no execution remains, the controller returns a finite proof that every implementation must fail; otherwise, the survivors define the most permissive safe monitor.
% 如果没有执行留下，控制器返回一份有限证明，说明所有实现都必然失败；否则，留下的执行定义最宽松的安全监控器。
Before installation, the runtime recomputes the answer from the current history and atomically replaces the old monitor, forcing every racing call to occur either before or after the edit.
% 安装之前，运行时根据当前历史重新计算判定并原子替换旧监控器，迫使每个竞态调用发生在编辑之前或之后。
\Cref{sec:lifecycle} applies this process to one procurement history across Fork, Merge, two races, and Restore; the restored approval reuses its earlier receipt rather than producing a second effect.
% \Cref{sec:lifecycle} 将这一过程应用于一段依次经历 Fork、Merge、两类竞态与 Restore 的采购历史；恢复后的审批复用先前回执，而不会产生第二个效果。

\paragraph{Contributions}
% 贡献
We contribute one end-to-end theorem connecting the original Agent workflow, the requested history edit, the exact decision procedure, and the installed runtime.
% 我们贡献一个端到端定理，将原始 Agent 工作流、请求的历史编辑、精确判定过程与已安装运行时连接起来。
For all six registered history operations and authenticated additive extensions, a safe implementation exists exactly when the procedure leaves a nonempty set of executions, exactly when its monitor can be installed, and exactly when an ideal atomic machine permits the same edit.
% 对全部六种已注册历史操作和经认证的仅追加扩展，当且仅当该过程留下非空执行集合、其监控器能够安装且理想原子机器允许同一次编辑时，安全实现才存在。
The theorem also proves that every category of history information used by the procedure is necessary, that the result remains valid after every finite sequence of operations, and that the concrete runtime has the same visible behavior as the ideal machine (\cref{sec:model,sec:admission,sec:kernel,sec:results}).
% 该定理还证明，判定过程使用的每类历史信息都不可缺少，结果在操作组成的每个有限序列之后仍然成立，并且具体运行时与理想机器具有相同的可见行为（\cref{sec:model,sec:admission,sec:kernel,sec:results}）。
Five kernel-checked Lean modules, 81 executable tests, and a bounded scaling study validate the finite checked core, critical examples, and explicit decision procedure.
% 五个经内核检查的 Lean 模块、81 项可执行测试与一项有界扩展性研究验证了有限检查核心、关键例子和显式判定过程。
