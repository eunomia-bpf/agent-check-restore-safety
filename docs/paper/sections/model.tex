\section{Model and Security Objective}
% 模型与安全目标
\label{sec:model}

The model separates unrestricted internal Agent reasoning from tool calls whose effects pass through a trusted runtime monitor.
% 该模型将不受限制的 Agent 内部推理与效果必须经过可信运行时监控器的工具调用分开。
Such a call must identify its registered position in the workflow, present an authorization token, and submit a concrete tool request.
% 这类调用必须标明它在工作流中的已注册位置、提供授权令牌，并提交具体工具请求。
The monitor decides whether the call may use a new authorization, reuse an authorization already recorded in the log, or make no progress.
% 监控器决定该调用能否使用新的授权、复用日志中已经记录的授权，或不得推进。
Each modeled state covers one \emph{policy domain}: the protected actions governed by one policy, one authorization log, and one atomically replaced monitor.
% 每个建模状态涵盖一个\emph{策略域}：由一项策略、一份授权日志和一个原子替换的监控器共同管理的受控动作。
Domains with disjoint protected actions, authorization logs, and policies compose by product.
% 受控动作、授权日志和策略彼此不相交的域通过乘积组合。
Every individual state is finite, while the theory covers executions of arbitrary finite length.
% 每个单独状态都是有限的，而该理论覆盖任意有限长度的执行。
The definitions below describe the required outcomes and the authenticated state that preserves them across edits.
% 下文定义要求实现的结果，以及在编辑过程中保留这些结果的认证状态。

\subsection{Workflow outcomes and call order}
% 工作流结果与调用次序

\paragraph{Basic objects}
% 基本对象
We capitalize \emph{Agent} for the untrusted principal requesting execution edits.
% 我们将请求执行编辑的不受信任主体称为 \emph{Agent}。
An \emph{call position} \(x\) identifies one position for a protected tool call in the workflow.
% \emph{调用位置} \(x\) 标识工作流中一次受控工具调用的位置。
An \emph{action ID} \(d\) groups the call positions that share one protected action and one authorization record.
% \emph{动作标识} \(d\) 将共享同一受控动作和同一授权记录的调用位置归为一组。
The first authorized use creates that record; positions copied by Fork or Restore later reuse it.
% 第一次获授权使用会创建该记录；Fork 或 Restore 随后复制出的调用位置会复用它。
The authenticated state also records the certified origin of each workflow region copied by an edit.
% 认证状态还记录编辑所复制的每个工作流区域的认证来源。
\(T,\Delta,\chi\) denote the current workflow, authorization log, and ordered record of processed call positions.
% \(T,\Delta,\chi\) 分别表示当前工作流、授权日志和已处理调用位置的有序记录。

A pomset \(p=(X_p,\prec_p)\) is a finite set of call positions with a strict partial order.
% 偏序事件集 \(p=(X_p,\prec_p)\) 是带有严格偏序的有限调用位置集合。
Its linearizations \(\Lin(p)\) are the words containing each member of \(X_p\) once and respecting \(\prec_p\).
% 它的线性化 \(\Lin(p)\) 是各包含 \(X_p\) 中每个成员一次且遵循 \(\prec_p\) 的序列。
A \emph{workflow contract} \(\mathcal C=(O,\{p_o\}_{o\in O})\) assigns one pomset to each member of a finite nonempty outcome set \(O\).
% \emph{工作流契约} \(\mathcal C=(O,\{p_o\}_{o\in O})\) 为有限非空结果集 \(O\) 中的每个成员分配一个偏序事件集。
Each index \(o\) names one allowed completion outcome.
% 每个索引 \(o\) 命名一种允许的完成结果。
Two outcomes remain distinct even if the calls still required for them later become identical.
% 即使两个结果后来仍需执行的调用变得相同，它们仍保持不同。
Write \(X_{\mathcal C}=\bigcup_{o\in O}X_{p_o}\) and \(\mathsf{CL}(\mathcal C)=\bigcup_{o\in O}\Lin(p_o)\).
% 记 \(X_{\mathcal C}=\bigcup_{o\in O}X_{p_o}\) 且 \(\mathsf{CL}(\mathcal C)=\bigcup_{o\in O}\Lin(p_o)\)。
We require the runtime to distinguish completion from continuation.
% 我们要求运行时能够区分完成与继续执行。
\[
 v,w\in\mathsf{CL}(\mathcal C)\ \land\
 v\preceq_{\rm pref}w \quad\Longrightarrow\quad v=w .
\]
This condition permits incomparable traces and different outcomes with the same trace, so it does not require deterministic outcomes.
% 该条件允许不可比较的轨迹以及共享同一轨迹的不同结果，因此并不要求结果具有确定性。
It requires a registered call position whenever continuing after a shared partial execution performs more work.
% 如果在一段共享的部分执行之后继续会执行更多工作，该条件要求存在一个已注册调用位置来表示继续。
The interface represents a choice between stopping and continuing by an authenticated terminal call position handled by the controller.
% 该接口通过由控制器处理的认证终止调用位置表示停止与继续之间的选择。

Contracts use the three partial constructors below.
% 契约使用下列三个偏构造器。
Each constructor requires operands with disjoint call positions and preserves the condition that no complete call sequence is a strict prefix of another.
% 每个构造器都要求操作数的调用位置互不相交，并保持“任何完整调用序列都不是另一完整调用序列真前缀”这一条件。
\begin{equation}
\label{eq:contract-algebra}
\begin{aligned}
 O_{\mathcal C\oplus\mathcal D}
  &= (\{L\}\mathbin{\times}O_{\mathcal C})
     \uplus(\{R\}\mathbin{\times}O_{\mathcal D}),\\
 p_{(L,o)}&=p_o,\qquad p_{(R,v)}=p_v,\\
 O_{\mathcal C\otimes\mathcal D}
  &=O_{\mathcal C}\mathbin{\times}O_{\mathcal D},\\
 p_{(o,v)}&=p_o\uplus p_v,\\
 O_{\mathcal C\triangleright\mathcal D}
  &=O_{\mathcal C}\mathbin{\times}O_{\mathcal D},\\
 p_{(o,v)}&=p_o\triangleright p_v.
\end{aligned}
\end{equation}
Before adding a registered or copied operand, the controller deterministically assigns fresh call-position IDs and extends \(\rho\) while retaining the authenticated action IDs.
% 在加入已注册或复制的操作数之前，控制器确定性地分配新的调用位置标识并扩展 \(\rho\)，同时保留认证动作标识。
Well-formedness already makes carried operands disjoint.
% 良构性已经保证被携带的操作数互不相交。
In \cref{eq:contract-algebra}, \(\uplus\) adds no cross-order and \(\triangleright\) orders every event of \(p\) before every event of \(q\), while choice uses a tagged union of outcome indices and parallel and sequence use Cartesian products.
% 在 \cref{eq:contract-algebra} 中，\(\uplus\) 不添加跨操作数次序，\(\triangleright\) 将 \(p\) 的每个事件置于 \(q\) 的每个事件之前，而选择使用带标签的结果索引不交并，并行和顺序则使用笛卡尔积。
Consequently, choice retains each arm's full indexed family, parallel pairs outcomes while permitting every causal linearization, and sequence adds a barrier.
% 因此，选择保留每个分支的完整带索引结果族，并行对结果配对并允许每种因果线性化，而顺序添加一道屏障。
After call prefix \(w\), \(\mathcal C/w\) retains each outcome whose pomset has a linearization prefixed by \(w\), then removes the call positions in \(w\) and their order edges.
% 在调用前缀 \(w\) 之后，\(\mathcal C/w\) 保留其偏序事件集存在以 \(w\) 为前缀的线性化的每个结果，再移除 \(w\) 中的调用位置及其次序边。
The expression is undefined if no outcome remains.
% 若没有索引保留，则其无定义。
This operational ``remaining contract'' preserves outcome and call position identity.
% 这一“剩余契约”的操作定义会保留结果标识和调用位置标识。

\begin{lemma}[Completion remains unambiguous]
% 完成状态保持无歧义
\label{lem:observable-completion}
For every defined \(\mathcal C/w\), no complete sequence is a strict prefix of another, and either every retained pomset is empty or none is empty.
% 对于每个有定义的 \(\mathcal C/w\)，任何完整序列都不是另一完整序列的真前缀，并且保留的偏序事件集要么全为空，要么全都非空。
\end{lemma}
\begin{proof}
If a remaining suffix \(v\) strictly prefixes \(v'\), then \(wv\) strictly prefixes \(wv'\) in \(\mathsf{CL}(\mathcal C)\).
% 如果剩余后缀 \(v\) 是 \(v'\) 的真前缀，那么在 \(\mathsf{CL}(\mathcal C)\) 中，\(wv\) 是 \(wv'\) 的真前缀。
If one retained pomset is empty and another is nonempty, choose a nonempty linearization \(v\) of the latter.
% 如果一个保留的偏序事件集为空而另一个非空，则选择后者的一条非空线性化 \(v\)。
Then \(w\) strictly prefixes \(wv\).
% 此时 \(w\) 是 \(wv\) 的真前缀。
Both contradict the condition that no complete sequence strictly prefixes another.
% 两种情况都与“任何完整序列都不是真前缀”这一条件矛盾。
\end{proof}

\subsection{Authenticated State}
% 认证状态

\subsubsection{Recorded structure and current workflow}
% 已记录结构与当前工作流

The authenticated state is
% 认证状态为
\begin{equation}
\label{eq:history-state}
 H=(\omega,G,T,K,\Sigma_\zeta,\rho,\beta,\chi,\nu,\eta).
\end{equation}
\(\omega\) identifies the policy domain, and \(\eta\) identifies its current monitor version.
% \(\omega\) 标识策略域，\(\eta\) 标识其当前监控器版本。
\(G\) is a finite append-only record of workflow versions.
% \(G\) 是工作流版本的有限仅追加记录。
Its node IDs, base contracts, signed outcome authorities, and typed edit records never change.
% 其中的节点标识、基础契约、经签名的结果权限及类型化编辑记录永不改变。
Each branch node \(b\) carries an immutable registered base contract \(\Gamma_b\).
% 每个分支节点 \(b\) 携带一个不可变的已注册基础契约 \(\Gamma_b\)。
Its ordered progress record \(\chi_b\) lists the call positions already processed on that branch.
% 其有序进展记录 \(\chi_b\) 列出该分支上已经处理的调用位置。
The immutable records form a directed acyclic graph (DAG) whose edges record typed Fork, Restore, and Merge operations.
% 这些不可变记录形成一个有向无环图（DAG），其边记录类型化的 Fork、Restore 和 Merge 操作。
\(T\) is the current workflow.
% \(T\) 是当前工作流。
\[
 T ::= b{:}\mathcal C
     \mid T\oplus_g^s T
     \mid T\parallel_g T
     \mid \mathsf{join}(T,T)
     \mid T;T .
\]
\(s\in\{\mathsf{open},L,R\}\) records an unresolved choice or the arm that made recorded progress, and \(g\) groups exclusive or jointly active siblings.
% \(s\in\{\mathsf{open},L,R\}\) 记录尚未解决的选择或已记录进展的分支，\(g\) 则将互斥或共同活动的同级项分组。
\(\sem{T}\) uses both arms of an open choice and only the selected arm thereafter.
% \(\sem{T}\) 对开放选择使用两个分支，此后仅使用选中的分支。
It interprets parallel and \(\mathsf{join}\) with \(\otimes\), and sequence with \(\triangleright\).
% 它用 \(\otimes\) 解释并行和 \(\mathsf{join}\)，并用 \(\triangleright\) 解释顺序。
The \(\mathsf{join}\) marker records a completed Merge and prevents the same group from being merged again.
% \(\mathsf{join}\) 标记记录已经完成的 Merge，并防止同一组再次被 Merge。

\(T\) is \(\mathsf{complete}\) when every pomset in \(\sem{T}\) is empty.
% 当 \(\sem{T}\) 中的每个偏序事件集都为空时，\(T\) 为 \(\mathsf{complete}\)。
\Cref{lem:observable-completion} ensures that the remaining workflow cannot contain both empty and nonempty pomsets.
% \Cref{lem:observable-completion} 保证剩余工作流不会同时包含空与非空偏序事件集。
Set \(\mathsf{heads}(b{:}\mathcal C)=\{b\}\).
% 令 \(\mathsf{heads}(b{:}\mathcal C)=\{b\}\)。
An open choice makes both arms current, a selected choice makes its winner current, parallel and \(\mathsf{join}\) make both arms current, and sequence makes its left operand current until completion and then its right.
% 开放选择使两个分支均为当前分支，已选选择使胜出分支成为当前分支，并行和 \(\mathsf{join}\) 使两个分支均为当前分支，而顺序先使左操作数成为当前部分直至其完成，再切换到右操作数。
Completing a call position updates the work remaining at its leaf without deleting the recorded structure.
% 完成一个调用位置会更新其叶节点仍需执行的工作，但不会删除已记录结构。
Because sequence checks \(\mathsf{complete}\), it retains completed outcomes from its left operand, so an isolated completed leaf remains available for a later Fork or Restore.
% 由于顺序检查 \(\mathsf{complete}\)，它会保留左操作数中的已完成结果，因此孤立的已完成叶节点仍可供后续 Fork 或 Restore 使用。
Joining removes \(g\) immediately but keeps its continuation behind a barrier until both arms complete.
% Join 会立即移除 \(g\)，但在两个分支都完成之前，将其延续保持在屏障之后。
A call position is enabled when it is minimal in some pomset of \(\sem{T}\).
% 当一个调用位置在 \(\sem{T}\) 的某个偏序事件集中为极小元时，它即被启用。
Disjoint call positions and unique context decomposition give every enabled \(x\) a unique current leaf \(\mathsf{leaf}_T(x)=b\).
% 调用位置互不重叠以及上下文分解的唯一性，使每个已启用的 \(x\) 都具有唯一的当前叶节点 \(\mathsf{leaf}_T(x)=b\)。
For \(a\in\{\Fresh(x,d),\Alias(x,d)\}\), define the paired execution update
% 对于 \(a\in\{\Fresh(x,d),\Alias(x,d)\}\)，定义成对执行更新
\[
 \mathsf{HStep}((G,T),a)=
 \bigl(G\mathbin{\|}(b,a),\,T/(x,a)\bigr),
 \qquad b=\mathsf{leaf}_T(x),
\]
where \(G\mathbin{\|}(b,a)\) appends progress record \((b,a)\), and \(T/(x,a)\) removes the processed call from the current leaf and records any selected choice.
% 其中 \(G\mathbin{\|}(b,a)\) 追加进展记录 \((b,a)\)，而 \(T/(x,a)\) 从当前叶节点移除已处理调用并记录任何已选分支。
Write \(\mathsf{HRes}((G,T),r)\) for iterating this update over a resolved word \(r\).
% 用 \(\mathsf{HRes}((G,T),r)\) 表示沿已解析词 \(r\) 迭代这一更新。

\(\mathsf{addr}(T)\) is the set of branch and group IDs that an edit may currently name.
% \(\mathsf{addr}(T)\) 是编辑当前可以指明的分支和组标识集合。
It includes each current group and the current part of a sequence.
% 它包括每个当前组以及顺序结构中的当前部分。

\(K\) maps checkpoint IDs to immutable earlier branch records.
% \(K\) 将检查点标识映射到不可变的先前分支记录。
Write \(\mathcal C_k=\mathsf{contract}(K(k))\) for the remaining contract stored by checkpoint \(k\).
% 将检查点 \(k\) 存储的剩余契约记为 \(\mathcal C_k=\mathsf{contract}(K(k))\)。
\(\Sigma_\zeta\) is an immutable, versioned registry of typed edit rules.
% \(\Sigma_\zeta\) 是不可变且带版本的类型化编辑规则注册表。
\(\rho\) records, for each call position, its monitor entry, action ID, authorization token, certified origin, scope, canonical tool request, and request digest.
% \(\rho\) 为每个调用位置记录其监控器入口、动作标识、授权令牌、认证来源、作用域、规范工具请求和请求摘要。
For each current call position \(x\), binding \(\beta(x)=(j,\eta)\) names its monitor entry and version.
% 对于每个当前调用位置 \(x\)，绑定 \(\beta(x)=(j,\eta)\) 指明其监控器入口和版本。
\(\chi\) records processed call positions in order, including whether each created or reused an authorization record, and \(\nu\) is the state version.
% \(\chi\) 按顺序记录已处理的调用位置，包括每个位置是创建还是复用授权记录；\(\nu\) 是状态版本。
Because \(\chi\) records authorization and workflow progress, the remote service may still need to supply a completion record and return value.
% 由于 \(\chi\) 记录授权和工作流进展，远端服务可能仍需提供完成记录和返回值。

\(\mathsf{Save}(k,b)\) creates a checkpoint for a current branch \(b\) under a fresh checkpoint ID \(k\).
% \(\mathsf{Save}(k,b)\) 使用新的检查点标识 \(k\) 为当前分支 \(b\) 创建检查点。
A trusted transaction stores an authenticated copy of branch \(b\)'s remaining contract \(\mathcal C_b\), ordered progress record \(\chi_b\), and relevant call and outcome-authority records.
% 一个可信事务存储分支 \(b\) 的剩余契约 \(\mathcal C_b\)、有序进展记录 \(\chi_b\) 以及相关调用记录与结果权限记录的认证副本。
The checkpoint check requires \(\mathcal C_b=\Gamma_b/\mathsf{raw}(\chi_b)\), and the transaction advances \(\nu\) without changing the current workflow, authorization records, bindings, monitor versions, or permission trace.
% 检查点检查要求 \(\mathcal C_b=\Gamma_b/\mathsf{raw}(\chi_b)\)，且该事务推进 \(\nu\) 而不改变当前工作流、授权记录、绑定、监控器版本或权限轨迹。
This internal transition changes \(H\), so an installation computed from the earlier state will fail its final state check.
% 这一内部转移会改变 \(H\)，因此根据较早状态计算的安装将在最终状态检查时失败。
Restore accepts only records created by this rule.
% Restore 仅接受由此规则创建的记录。

\subsubsection{Well-formedness}
% 良构性

\begin{definition}[Well-formed authenticated state]
% 良构认证状态
\label{def:well-formed-history}
\(H\) is well formed when the following groups hold.
% 当下列各组条件成立时，\(H\) 是良构的。
\begin{enumerate}[leftmargin=*,itemsep=0pt,topsep=1pt]
\item \emph{Structure.}
% \emph{结构。}
\(G\) is acyclic, and branch and group IDs are globally unique across the recorded DAG and current workflow.
% \(G\) 是无环的，且分支标识和组标识在所记录的 DAG 与当前工作流中全局唯一。
Every ID that an edit may name has a unique context decomposition, and every node in \(\mathsf{heads}(T)\) is currently maximal.
% 编辑可以指明的每个标识都有唯一的上下文分解，且 \(\mathsf{heads}(T)\) 中的每个节点当前都是极大节点。
Every checkpoint names an immutable node and stores copies of its remaining contract and ordered progress record.
% 每个检查点都指明一个不可变节点，并存储其剩余契约与有序进展记录的副本。
Every original or edit-introduced outcome has exactly one signed policy authority, preserved when the controller carries, copies, or checkpoints it.
% 每个原始结果或编辑引入的结果都恰有一个经签名的策略权限方，并在控制器携带、复制或保存该结果时得到保留。
\item \emph{Identity and progress.}
% \emph{标识与进展。}
Call-position and monitor-entry IDs are unique, while call positions with the same action ID agree on the call authorization service, scope, canonical request, digest, and certified origin.
% 调用位置标识和监控器入口标识是唯一的，而共享同一动作标识的调用位置在授权服务、作用域、规范请求、摘要和认证来源上保持一致。
Processed call positions are downward closed in their pomset, consistent with every choice status, and absent from the remaining workflow.
% 已处理调用位置在其偏序事件集中向下闭合，与每个选择状态一致，并且不出现在剩余工作流中。
\item \emph{Current workflow.}
% \emph{当前工作流。}
\(\operatorname{dom}(\beta)=X_{\sem T}\), and every current call position \(x\) has exactly one authenticated binding \(\beta(x)=(j_x,\eta)\) to the domain's single current monitor version.
% \(\operatorname{dom}(\beta)=X_{\sem T}\)，且每个当前调用位置 \(x\) 都恰有一个经认证的绑定 \(\beta(x)=(j_x,\eta)\)，指向该域唯一的当前监控器版本。
Every current leaf \(b{:}\mathcal C\) equals its immutable registered contract \(\Gamma_b\) after removing the call positions recorded in \(\chi_b\); the caller cannot replace it with a smaller outcome set.
% 每个当前叶节点 \(b{:}\mathcal C\) 都等于其不可变已注册契约 \(\Gamma_b\) 移除 \(\chi_b\) 中所记录调用位置后的结果；调用方无法把它替换为更小的结果集合。
Every constructor in \(T\) is defined, so no complete sequence in any subtree is a strict prefix of another.
% \(T\) 中的每个构造器都有定义，因此任何子树中的完整序列都不是另一完整序列的真前缀。
\item \emph{Edit rules and domain.}
% \emph{编辑规则与域。}
Every edge and introduced contract follows one immutable edit rule at version \(\zeta\).
% 每条边和每个引入的契约都遵循版本 \(\zeta\) 的一条不可变编辑规则。
Every current, checkpoint, or rule-introduced call position, action ID, monitor entry, certified origin, and scope belongs to \(\omega\).
% 当前状态、检查点或规则引入的每个调用位置、动作标识、监控器入口、认证来源和作用域都属于 \(\omega\)。
Action IDs, authorization logs, and policies of distinct domains are disjoint, and an edit never crosses a domain.
% 不同域的动作标识、授权日志和策略互不相交，并且编辑绝不跨域。
\end{enumerate}
The policy domain has exactly one active monitor version, namely the version recorded in \(H\).
% 策略域恰有一个活动监控器版本，即 \(H\) 中记录的版本。
\end{definition}

\subsubsection{Authorization and completion state}
% 授权与完成状态

The full state also contains policy version \(\kappa\), a regular prefix-closed authorization policy \(\mathcal A\subseteq\mathcal U^*\) over label alphabet \(\mathcal U\), append-only authorization log \(\Delta\), and queue \(\mathsf{out}\) of requests awaiting release.
% 完整状态还包含策略版本 \(\kappa\)、定义在标签字母表 \(\mathcal U\) 上的正则前缀闭合授权策略 \(\mathcal A\subseteq\mathcal U^*\)、仅追加授权日志 \(\Delta\)，以及等待发出的请求队列 \(\mathsf{out}\)。
Authorization records can only be appended.
% 授权记录只能追加。
A completion update advances an authorization record's status and fills its return record with a stable return value.
% 完成更新会推进授权记录的状态，并用稳定返回值填充其返回记录。
Each authorization record binds its action ID, immutable canonical tool request, creator call position, and permission label.
% 每条授权记录都绑定其动作标识、不可变规范工具请求、创建者调用位置和权限标签。
Each entry in \(\chi\) points either to the authorization record it created or to the earlier record it reused, so \((\chi,\Delta)\) determines retry and return lookup.
% \(\chi\) 中的每个条目都指向它创建的授权记录或它复用的较早记录，因此 \((\chi,\Delta)\) 决定重试与返回值查找。
\(\mathsf{lab}(\Delta)\) is the sequence of permission labels on calls that create authorization records.
% \(\mathsf{lab}(\Delta)\) 是创建授权记录的调用所带权限标签的序列。
Restore may reconstruct workspace payload but never restores \(\Delta\).
% Restore 可以重建工作区载荷，但绝不会恢复 \(\Delta\)。

The full state \((\kappa,H,\Delta,\mathsf{out},\mathcal A)\) is \emph{well formed} when \(H\) is well formed, \(\mathsf{lab}(\Delta)\in\mathcal A\), each action ID has at most one authorization record, each processed call names the record it created or reused, the authorization log, request queue, and policy belong to \(\omega\), and the queue preserves the order of new authorizations.
% 当 \(H\) 良构、\(\mathsf{lab}(\Delta)\in\mathcal A\)、每个动作标识至多有一条授权记录、每个已处理调用都指明它创建或复用的记录、授权日志/请求队列/策略均属于 \(\omega\)，且队列保持新授权的顺序时，完整状态 \((\kappa,H,\Delta,\mathsf{out},\mathcal A)\) 是\emph{良构的}。
All definitions and results below quantify over such well-formed states.
% 下文所有定义与结果均量化于这样的良构状态。

\subsection{Adversary and trusted boundary}
% 对手与可信边界

The adversary controls Agent output, edit requests, tool arguments, copied workspace, retries, stale authorization tokens, and scheduling, including races between calls and edits.
% 对手控制 Agent 输出、编辑请求、工具参数、复制的工作区、重试、过期授权令牌和调度，包括调用与编辑之间的竞态。
It cannot forge registries, the checkpoint directed acyclic graph (DAG), authenticated action-ID mappings, policy, or authorization log.
% 它无法伪造注册表、检查点有向无环图（DAG）、经认证的动作标识映射、策略或授权日志。
The policy authority signs policies, outcome requirements, and authorized removals.
% 策略权限方签署策略、结果要求和获授权移除。
The call authorization service registers protected calls, action IDs, and authorization tokens.
% 调用授权服务注册受控调用、动作标识和授权令牌。
The trusted controller derives and checks each edit, while the trusted installation service re-verifies the answer and atomically replaces the monitor.
% 可信控制器推导并检查每次编辑，而可信安装服务重新验证答案并原子替换监控器。
These roles, the authenticated registries and authorization log, certificate verifier, atomic rules, and complete mediation form the trusted computing base (TCB).
% 这些角色、经认证的注册表与授权日志、证书验证器、原子规则和完全中介共同构成可信计算基（TCB）。
Within one policy domain, this TCB completely mediates every protected call and commits every state change and visible edit answer through a recoverable linearizable transaction.
% 在一个策略域内，该 TCB 完全中介每次受控调用，并通过可恢复的线性化事务提交每项状态变更和可见编辑答案。
After an unexpected stop and restart, each transaction appears entirely before or entirely after its linearization point.
% 在意外停止并重新启动后，每项事务都完整呈现在线性化点之前或之后。
Before the checker reads the authenticated state, the call authorization service may instantiate finitely many registered call templates.
% 在检查器读取认证状态之前，调用授权服务可以实例化有限个已注册调用模板。
For tool request \(m\), it computes canonical request \(m^\circ=\mathsf{canon}_\kappa(m)\), reuses an action ID certified for \(m^\circ\) or allocates a fresh one, and signs \((x,j,d,\mathsf{scope},\mathsf{digest}(m^\circ),\mathsf{origin})\) into the authenticated registry.
% 对于工具请求 \(m\)，它计算规范请求 \(m^\circ=\mathsf{canon}_\kappa(m)\)，复用已认证用于 \(m^\circ\) 的动作标识或分配新标识，并把 \((x,j,d,\mathsf{scope},\mathsf{digest}(m^\circ),\mathsf{origin})\) 签入认证注册表。
The resulting finite call model \(R\) remains unchanged while the checker evaluates that state.
% 由此得到的有限调用模型 \(R\) 在检查器评估该状态期间保持不变。
Unmatched calls fail closed.
% 不匹配的调用以关闭方式失败。
The platform supplies authenticated workflow \(\mathcal W\), call model \(R\), edit rules, canonicalization rules, policy, checkpoints, and one consistent state containing the authorization log and queued requests.
% 平台提供经认证的工作流 \(\mathcal W\)、调用模型 \(R\)、编辑规则、规范化规则、策略、检查点，以及包含授权日志和排队请求的一致状态。
From these inputs and an Agent request naming an edit and its objects, the controller derives the edited workflow, required outcomes, call decisions, fixed point, monitor, rejection explanation, monitor version, and authorization tokens.
% 控制器根据这些输入以及指明编辑及其对象的 Agent 请求，推导编辑后的工作流、要求实现的结果、调用判定、不动点、监控器、拒绝说明、监控器版本和授权令牌。
Every derived object therefore comes from authenticated state rather than Agent-supplied semantics.
% 因此，每个派生对象都来自认证状态，而不是 Agent 提供的语义。

Registration turns the protected-call behavior of a typed Agent workflow into a finite call model \(R\).
% 注册把类型化 Agent 工作流的受控调用行为转换为有限调用模型 \(R\)。
\(\mathsf{CheckReg}\) verifies exact correspondence of outcomes, call order, action IDs, and first-time authorization records.
% \(\mathsf{CheckReg}\) 验证结果、调用次序、动作标识及首次授权记录的精确对应关系。
The model stores these traces as outcome-indexed runs \(\mathsf{BRuns}(R)\), together with a map \(\lambda\) from source traces.
% 该模型把这些轨迹存为带结果索引的执行 \(\mathsf{BRuns}(R)\)，并存储从源轨迹出发的映射 \(\lambda\)。
Write \(\mathcal W\sqsubseteq_\lambda R\) when \(\lambda\) is a bijection preserving outcomes, the mapping from call positions to action IDs, order, outcome authority, and authorization-log updates.
% 当 \(\lambda\) 是保持结果、调用位置到动作标识的映射、次序、结果权限和授权日志更新的双射时，记作 \(\mathcal W\sqsubseteq_\lambda R\)。
\Cref{def:registration-refinement,lem:registration-reflection} give the exact finite check and proof.
% \Cref{def:registration-refinement,lem:registration-reflection} 给出精确的有限检查与证明。
Registered contracts enter through \(\mathsf{CheckReg}\), and an idempotent or queryable remote service supplies authenticated completion records for its actions.
% 已注册契约通过 \(\mathsf{CheckReg}\) 进入理论，幂等或可查询的远端服务为其动作提供认证完成记录。

\subsection{Security Objective}
% 安全目标

The security objective is fixed independently of the checker that will implement it.
% 安全目标独立于随后实现它的检查器而确定。
For an edit derived from authenticated state, a safe implementation satisfies four requirements.
% 对于从认证状态派生的编辑，安全实现满足四项要求。
First, it preserves every source outcome that is neither already satisfied nor explicitly authorized for removal, and every admitted execution belongs to the derived target workflow.
% 第一，它保留每个既未满足、也未被明确授权移除的源结果，并且每段获准执行都属于派生目标工作流。
Second, every admitted prefix is allowed by the policy after accounting for authorization records already present in the append-only log.
% 第二，在计入仅追加日志中已经存在的授权记录后，每个获准前缀都满足策略。
Third, each admitted prefix extends to a complete admitted execution.
% 第三，每个获准前缀都能扩展为一段完整的获准执行。
Fourth, every outcome still compatible with an admitted prefix retains such a completion.
% 第四，每个仍与获准前缀兼容的结果都保留这样一条完成路径。
The last requirement rejects the example in \cref{sec:lifecycle}, where separately safe outcomes cannot remain safe under one monitor.
% 最后一项要求拒绝 \cref{sec:lifecycle} 中的示例：分别安全的结果无法在同一个监控器下持续保持安全。
\Cref{def:safe-implementation} states these requirements over outcome-indexed executions.
% \Cref{def:safe-implementation} 在带结果索引的执行上表述这些要求。
\Cref{lem:most-permissive} then proves that the checker computes the unique most-permissive safe implementation.
% \Cref{lem:most-permissive} 随后证明检查器计算唯一且限制最少的安全实现。

\section{Exact Checking of Execution Edits}
% 执行编辑的精确检查
\label{sec:admission}

The checker first derives the exact edited workflow from the authenticated state and the requested edit.
% 检查器首先从认证状态与所请求编辑中推导精确的编辑后工作流。
It then decides whether each call position creates or reuses an authorization record and removes precisely those complete executions that violate the security objective after some prefix.
% 随后，它判断每个调用位置创建还是复用授权记录，并精确移除那些在某个前缀之后违反安全目标的完整执行。

\subsection{Constructing the Edited Workflow}
% 构造编辑后的工作流

\subsubsection{Checking an edit rule}
% 检查编辑规则

The six disjoint constructors of \(\mathsf{Edit}_6\) are exactly the typed operation signatures in \cref{tab:history-rules}.
% \(\mathsf{Edit}_6\) 的六个互不相交构造器恰为 \cref{tab:history-rules} 中带类型的操作签名。
\(\mathsf{Save}\), initial installation, later rule registration, and protected calls use their own transitions.
% \(\mathsf{Save}\)、初始安装、后续规则注册及受控调用分别使用各自的转移。

An Agent request \(u\) names an edit kind, current object IDs, and edit-rule ID \(\sigma\).
% Agent 请求 \(u\) 指明编辑种类、当前对象标识和编辑规则标识 \(\sigma\)。
Registry \(\Sigma_\zeta\) binds \(\sigma\) to the expected source and checkpoint patterns, any workflow steps the edit adds, the certified origin of copied regions, and the signed authority for each introduced outcome.
% 注册表 \(\Sigma_\zeta\) 将 \(\sigma\) 绑定到预期的源状态与检查点模式、编辑添加的工作流步骤、复制区域的认证来源，以及每个引入结果的签名权限方。

The checker constructs explicit preservation maps for every region that the rule carries or copies.
% 检查器为规则携带或复制的每个区域构造显式保持映射。
For source contract \(\mathcal C\), target region \(\mathcal D\), and parent map \(\mu:X_{\mathcal D}\to X_{\mathcal C}\), write \(\mathcal C\preccurlyeq_\mu\mathcal D\) exactly when \(\mu\) is a global bijection, some surjection \(\pi:O_{\mathcal D}\twoheadrightarrow O_{\mathcal C}\) satisfies the conditions below for every target outcome \(v\), and \(\mu\) preserves action IDs and certified origins.
% 对于源契约 \(\mathcal C\)、目标区域 \(\mathcal D\) 和父映射 \(\mu:X_{\mathcal D}\to X_{\mathcal C}\)，当且仅当 \(\mu\) 是全局双射、存在满射 \(\pi:O_{\mathcal D}\twoheadrightarrow O_{\mathcal C}\) 使下列条件对每个目标结果 \(v\) 成立，且 \(\mu\) 保持动作标识和认证来源时，记作 \(\mathcal C\preccurlyeq_\mu\mathcal D\)。
\[
\begin{aligned}
 x\in X_{p_v}
   &\Longleftrightarrow \mu(x)\in X_{p_{\pi(v)}},\\
 x\prec_v y
   &\Longleftrightarrow \mu(x)\prec_{\pi(v)}\mu(y).
\end{aligned}
\]
Global bijection and call position--outcome membership equivalence prevent splitting a source call position shared across outcomes into outcome-specific target call positions.
% 全局双射和调用位置--结果成员关系等价防止将跨结果共享的源调用位置拆分为特定于结果的目标调用位置。

For candidate \(T'\), let \(R_u\) index the disjoint regions carried or copied inside the replaced subtree.
% 对候选 \(T'\)，令 \(R_u\) 索引被替换子树中互不相交的携带或复制区域。
\(\mathcal P_u=\{(\mathcal C_r,\mathcal D_r,\mu_r,\pi_r)\}_{r\in R_u}\) collects these preservation maps.
% \(\mathcal P_u=\{(\mathcal C_r,\mathcal D_r,\mu_r,\pi_r)\}_{r\in R_u}\) 收集这些保持映射。
A separate identity map verifies that the surrounding workflow preserves syntax, outcomes, call positions, action IDs, certified origins, and order.
% 另一个恒等映射验证周围工作流保持语法、结果、调用位置、动作标识、认证来源和次序。
Writing \(X_{\rm ctx}\) for its call positions and \(X_{\rm added(u)}\) for call positions added by the rule, the checker verifies the following disjoint cover.
% 将其调用位置记为 \(X_{\rm ctx}\)，将规则添加的调用位置记为 \(X_{\rm added(u)}\)，检查器验证下列不交覆盖。
\[
 X_{\sem{T'}}=X_{\rm ctx}\uplus
   \biguplus_{r\in R_u}X_{\mathcal D_r}\uplus X_{\rm added(u)} .
\]
The edit rule and surrounding workflow induce \(\mathsf{pr}^u_r:O_{\sem{T'}}\rightharpoonup O_{\mathcal D_r}\).
% 编辑规则和周围工作流诱导 \(\mathsf{pr}^u_r:O_{\sem{T'}}\rightharpoonup O_{\mathcal D_r}\)。
For choice, this projection is defined only in the arm containing \(r\), while product and sequence select the corresponding indexed component.
% 对于选择，该投影仅在包含 \(r\) 的分支上有定义，而乘积和顺序选择相应的带索引分量。
Define
% 定义
\[
\begin{aligned}
 \mathsf{EditedRequired}_u&=\{(r,o)\mid r\in R_u,\ o\in O_{\mathcal C_r}\},\\
 \mathsf{Covers}_u(t,r,o)&\Longleftrightarrow
   \exists v\in O_{\mathcal D_r}.\quad
   \mathsf{pr}^u_r(t)=v\ \land\ \pi_r(v)=o .
\end{aligned}
\]
Let \(O_{\rm unchanged}\) be the outcomes outside the edited region, and let \(\iota^u_{\rm ctx}:O_{\rm unchanged}\hookrightarrow O_{\sem{T'}}\) be their unchanged embedding into the target.
% 令 \(O_{\rm unchanged}\) 为编辑区域之外的结果，并令 \(\iota^u_{\rm ctx}:O_{\rm unchanged}\hookrightarrow O_{\sem{T'}}\) 为它们进入目标工作流的不变嵌入。
Define the outcomes that remain required and the target outcomes that cover them by
% 仍然要求实现的结果及覆盖它们的目标结果定义为
\begin{equation}
\label{eq:target-required}
\begin{aligned}
 \mathsf{StillRequired}_u&=\mathsf{EditedRequired}_u\\[-3pt]
   &\quad\uplus(\{\mathsf{ctx}\}\times O_{\rm unchanged}),\\
 \mathsf{Covers}_u(t,(\mathsf{ctx},o))
   &\Longleftrightarrow\\[-3pt]
   &\quad t=\iota^u_{\rm ctx}(o).
\end{aligned}
\end{equation}
For \(a=(r,o)\in\mathsf{EditedRequired}_u\), \(\mathsf{Covers}_u(t,a)\) denotes the relation above.
% 对 \(a=(r,o)\in\mathsf{EditedRequired}_u\)，\(\mathsf{Covers}_u(t,a)\) 表示上述关系。
The checker also requires \(\forall a\in\mathsf{StillRequired}_u.\ \exists t\in O_{\sem{T'}}.\ \mathsf{Covers}_u(t,a)\): every required source outcome has a complete target outcome, shared call positions remain shared, and inherited calls remain distinguished from steps added by the edit rule.
% 检查器还要求 \(\forall a\in\mathsf{StillRequired}_u.\ \exists t\in O_{\sem{T'}}.\ \mathsf{Covers}_u(t,a)\)：每个要求实现的源结果都有完整目标结果，共享调用位置保持共享，继承调用与编辑规则添加的步骤保持区分。

The edit-rule check uses the following judgment.
% 编辑规则检查使用以下判定。
\[
\Sigma_\zeta;H\vdash_{\rm edit}u\Rightarrow(T',\mathcal P_u)
\]
It holds exactly when every named object belongs to \(\mathsf{addr}(T)\), every introduced object belongs to \(\omega\), the source pattern matches, the applicable preservation maps and disjoint cover hold, every still-required outcome is covered, every removal carries the proper authority, and \(\sem{T'}\) is defined.
% 当且仅当每个具名对象属于 \(\mathsf{addr}(T)\)、每个引入对象属于 \(\omega\)、源状态模式匹配、适用的保持映射与不交覆盖成立、每个仍然要求实现的结果都被覆盖、每次移除都具有适当权限且 \(\sem{T'}\) 有定义时，该判定才成立。
The policy authority may authorize removal of the unselected arm of a typed \(\mathsf{MergeSelect}\) or the current branch of \(\mathsf{RestoreReplace}\), using the signed sets defined below.
% 策略权限方可以授权移除类型化 \(\mathsf{MergeSelect}\) 中未被选择的分支，或 \(\mathsf{RestoreReplace}\) 的当前分支，并使用下文定义的签名集合。
\subsubsection{Required-outcome preservation}
% 要求实现结果的保留

The registered edit rule determines every outcome that the edit must account for.
% 已注册编辑规则确定编辑必须处理的每个结果。
Fork accounts for both copies, Restore for the current and checkpoint branches, \(\mathsf{MergeSelect}\) for the selected and unselected arms, and \(\mathsf{MergeJoin}\) for both arms.
% Fork 处理两个副本，Restore 处理当前分支和检查点分支，\(\mathsf{MergeSelect}\) 处理选中和未选中的分支，而 \(\mathsf{MergeJoin}\) 处理两个分支。
Outcomes outside the edited region remain unchanged.
% 编辑区域之外的结果保持不变。
\Cref{def:source-outcomes} defines the outcomes required before the edit, those already satisfied, and those whose removal the policy authority signed.
% \Cref{def:source-outcomes} 定义编辑前要求实现的结果、已经满足的结果，以及策略权限方签名允许移除的结果。
The checker accepts the edit rule when the target-derived set from \cref{eq:target-required} satisfies
% 当由 \cref{eq:target-required} 从目标推导出的集合满足下式时，检查器接受该编辑规则：
\[
\begin{aligned}
\mathsf{StillRequired}_u
 &=\mathsf{RequiredBefore}(H,u)\\[-2pt]
 &\quad\setminus\bigl(
   \mathsf{Satisfied}_{H,u}\uplus
   \mathsf{AuthorizedRemoval}_{H,u}\bigr),
\end{aligned}
\]
and hence the exact disjoint partition
% 并因此得到精确的不交分解：
\[
\begin{aligned}
\mathsf{RequiredBefore}(H,u)
 &=\mathsf{StillRequired}_u\\[-2pt]
 &\quad\uplus\mathsf{Satisfied}_{H,u}\\[-2pt]
 &\quad\uplus\mathsf{AuthorizedRemoval}_{H,u}.
\end{aligned}
\]
This partition accounts for every source outcome and prevents an Agent request from silently dropping one.
% 这一分解处理每个源结果，并防止 Agent 请求悄然删除其中任何一个。
The preservation maps retain action IDs, certified origins, and order, while installation retains the recorded evidence for satisfied outcomes and the signed removal set.
% 保持映射保留动作标识、认证来源和次序，而安装保留已满足结果的记录证据及签名移除集合。

Let \(\mathcal E[-]\) be the current workflow with one editable region replaced by a hole.
% 令 \(\mathcal E[-]\) 表示当前工作流中一个可编辑区域被孔替换后的结构。
\(\mathsf{carry}\) preserves branch, outcome, and call-position IDs, pomset order, action IDs, signed outcome authorities, base contracts, ordered progress records, and nested choices.
% \(\mathsf{carry}\) 保留分支、结果与调用位置标识、偏序事件集次序、动作标识、经签名的结果权限、基础契约、有序进展记录和嵌套选择。
\(\mathsf{clone}_r\) assigns fresh branch, outcome, and call-position IDs while preserving pomset order, action IDs, scope, digest, certified origin, and signed outcome authority.
% \(\mathsf{clone}_r\) 分配新的分支、结果和调用位置标识，同时保持偏序事件集次序、动作标识、作用域、摘要、认证来源和经签名的结果权限。
Each copied branch starts from its registered remaining contract with an empty progress record.
% 每个复制分支从其已注册的剩余契约和空进展记录开始。
Branches added by an edit rule likewise start from their registered contract and an empty progress record.
% 编辑规则添加的分支同样从其已注册契约和空进展记录开始。
The contracts \(E_\sigma^L,E_\sigma^R,E_\sigma^J\) are additional workflow steps derived from the rule registry.
% 契约 \(E_\sigma^L,E_\sigma^R,E_\sigma^J\) 是从规则注册表派生的附加工作流步骤。
Define
% 定义
\[
 L_\sigma=\mathsf{clone}_L(\mathcal C)\triangleright E_\sigma^L,\qquad
 R_\sigma=\mathsf{clone}_R(\mathcal C)\triangleright E_\sigma^R .
\]
New identifiers and the target monitor version \(\eta^+\) are deterministically allocated from \((\omega,\zeta,\nu,u,\mathsf{role})\).
% 新标识和目标监控器版本 \(\eta^+\) 由 \((\omega,\zeta,\nu,u,\mathsf{role})\) 确定性分配。
\(\mathsf{role}\) identifies which operation argument receives each new ID.
% \(\mathsf{role}\) 标识每个新标识属于哪个操作参数。
Write \(\mathsf{Copy}_r(\mathcal C)\) for the proof tuple \((\mathcal C,\mathsf{clone}_r(\mathcal C),\mu_r,\pi_r)\), and \(\mathsf{Keep}(\mathcal C)\) for \((\mathcal C,\mathsf{carry}(\mathcal C),\mu,\pi)\).
% 将证明元组 \((\mathcal C,\mathsf{clone}_r(\mathcal C),\mu_r,\pi_r)\) 记为 \(\mathsf{Copy}_r(\mathcal C)\)，并将 \((\mathcal C,\mathsf{carry}(\mathcal C),\mu,\pi)\) 记为 \(\mathsf{Keep}(\mathcal C)\)。
Each abbreviation asserts the corresponding \(\preccurlyeq_\mu\) relation.
% 每个缩写都断言相应的 \(\preccurlyeq_\mu\) 关系。
For a current workflow \(T_0\), \(\mathsf{Keep}(T_0)\) abbreviates \(\mathsf{Keep}(\sem{T_0})\) and has target contract \(\sem{\mathsf{carry}(T_0)}\).
% 对于当前工作流 \(T_0\)，\(\mathsf{Keep}(T_0)\) 是 \(\mathsf{Keep}(\sem{T_0})\) 的缩写，其目标契约为 \(\sem{\mathsf{carry}(T_0)}\)。
Every \(b\) or \(g\) named below must lie in \(\mathsf{addr}(T)\).
% 下文具名的每个 \(b\) 或 \(g\) 都必须位于 \(\mathsf{addr}(T)\) 中。

\(\mathcal E[b_L{:}L_\sigma\oplus_g^{\mathsf{open}}
 b_R{:}R_\sigma]\) &
\(\{\mathsf{Copy}_L(\mathcal C),\mathsf{Copy}_R(\mathcal C)\}\)\\
\(\mathsf{ForkParallel}(b,\sigma)\) &
\(\mathcal E[b{:}\mathcal C]\) &
\(\mathcal E[b_L{:}L_\sigma\parallel_g b_R{:}R_\sigma]\) &
\(\{\mathsf{Copy}_L(\mathcal C),\mathsf{Copy}_R(\mathcal C)\}\)\\

 \parallel_g b_k{:}\mathsf{clone}_k(\mathcal C_k)]\) &

 s\in\{\mathsf{open},w\}\) &

In an open choice, the first processed call position atomically selects its arm and disables later calls from the other arm, whether that first call creates or reuses an authorization record.
% 在开放选择中，第一个已处理调用位置会原子选择其分支并禁用另一分支的后续调用，无论该调用创建还是复用授权记录。
Consequently, \(\mathsf{MergeSelect}(g,w,\sigma)\) is valid precisely while the unselected arm has made no recorded progress.
% 因此，\(\mathsf{MergeSelect}(g,w,\sigma)\) 恰在未选择分支尚无记录进展时有效。
\(\mathsf{MergeJoin}\) replaces the current \(\parallel_g\) node with \(\mathsf{join}\), removes \(g\) from the set of IDs an edit may name, and prevents the same pair from being joined again.
% \(\mathsf{MergeJoin}\) 以 \(\mathsf{join}\) 替换当前 \(\parallel_g\) 节点，将 \(g\) 从编辑可指明的标识集合中移除，并防止同一对分支再次合并。

Every edit replaces the monitor for its whole policy domain, and every current entry in \(H\) belongs to \(\eta^-=\eta\).
% 每次编辑都会替换其整个策略域的监控器，且 \(H\) 中的每个当前入口都属于 \(\eta^-=\eta\)。
\subsubsection{Replacing the monitor}
% 替换监控器

The execution-edit judgment consists exactly of one row of \cref{tab:history-rules} applied inside the well-typed workflow context \(\mathcal E\), followed by the state update below.
% 执行编辑判定恰由两步组成：在良类型工作流上下文 \(\mathcal E\) 中应用 \cref{tab:history-rules} 的一行，再执行下述状态更新。
Let \(e_u\) contain the edit record and exactly the copied, added, and group nodes prescribed by \(T'\); carried node IDs remain unchanged.
% 令 \(e_u\) 包含编辑记录以及恰由 \(T'\) 指定的复制节点、新增节点和组节点；被携带节点的标识保持不变。
For every current target call position \(x\), the call authorization service deterministically creates \(j_x^+,h_x^+\), and \(\rho'\) preserves the action ID, certified origin, scope, digest, and retry information while refreshing monitor entries and authorization tokens.
% 对每个当前目标调用位置 \(x\)，调用授权服务确定性地创建 \(j_x^+,h_x^+\)，而 \(\rho'\) 保留动作标识、认证来源、作用域、摘要和重试信息，同时刷新监控器入口和授权令牌。
Define
% 定义
\[
\begin{aligned}
 \mathcal H_u^+
   &=\{(x,j_x^+,h_x^+)\mid x\in X_{\sem{T'}}\},\\
 \beta'(x)&=(j_x^+,\eta^+).
\end{aligned}
\]
The new authorization tokens are inactive and inaccessible to the caller before installation.
% 安装前，新授权令牌尚未激活，调用方也无法访问。
The complete judgment is shown below.
% 完整判定如下。
\begin{equation}
\label{eq:derived-cut}
\begin{aligned}
 \Sigma_\zeta;H\vdash u\Downarrow
   &(H',\mathcal C_{H,u},\eta^-,\eta^+),\\
 H'&=(\omega,G\mathbin{\cdot}e_u,T',K,\Sigma_\zeta,
      \rho',\beta',\chi,\nu+1,\eta^+),\\
 \mathcal C_{H,u}&=\sem{T'},\qquad \eta^-=\eta .
\end{aligned}
\end{equation}
Here \(G\mathbin{\cdot}e_u\) retains earlier progress, outcome-authority records, and existing nodes, and initializes each copied or added branch from its remaining registered contract with inherited or rule-signed outcome authority and no progress.
% 其中 \(G\mathbin{\cdot}e_u\) 保留先前进展、结果权限记录和已有节点，并从剩余已注册契约初始化每个复制或新增分支，同时赋予继承或规则签名的结果权限且进展为空。
Thus an edit preserves \(K,\Sigma_\zeta,\chi\), appends one typed edit record and its target nodes, refreshes every current monitor entry and authorization token, and moves the domain to \(\eta^+\).
% 因此，一次编辑保持 \(K,\Sigma_\zeta,\chi\)，追加一条类型化编辑记录及其目标节点，刷新每个当前监控器入口和授权令牌，并将整个域迁移到 \(\eta^+\)。
Table constructors determine new group modes, while carried nested modes remain unchanged.
% 表中构造器决定新组模式，而被携带的嵌套模式保持不变。
A nonexistent checkpoint, wrong group mode, nonmember winner, mismatched rule pattern, unauthorized removal, or undefined composition produces \(\mathsf{Invalid}\).
% 不存在的检查点、错误的组模式、非成员胜者、不匹配的规则模式、未经授权的移除或无定义的组合都会产生 \(\mathsf{Invalid}\)。
Independent domains step by asynchronous product, with complete monitor replacement inside each domain.
% 独立域通过异步乘积推进，每个域内部都执行完整监控器替换。

\begin{lemma}[Exact edit derivation and complete monitor replacement]
% 精确编辑推导与监控器完整替换
\label{lem:history-derivation}
For well-formed \(H\), the judgment in \cref{eq:derived-cut} is deterministic.
% 对于良构的 \(H\)，\cref{eq:derived-cut} 中的判定是确定性的。
If it derives \(H'\), then \(H'\) is well formed.
% 如果它推导出 \(H'\)，则 \(H'\) 是良构的。
It preserves required outcomes and their signed authorities, retaining evidence for every satisfied outcome and every still-required source outcome except a signed authorized removal.
% 它保留要求实现的结果及其签名权限，保留每个已满足结果和每个仍然要求实现的源结果的证据，签名授权移除除外。
The surrounding-workflow identity map and family \(\mathcal P_u\) preserve global call-position sharing, action IDs, certified origins, outcome authorities, and causal order.
% 周围工作流恒等映射和族 \(\mathcal P_u\) 保持全局调用位置共享、动作标识、认证来源、结果权限和因果次序。
For every \(a\in\mathsf{StillRequired}_u\), some complete target outcome \(t\) satisfies \(\mathsf{Covers}_u(t,a)\), including every unchanged outcome outside the edited region.
% 对每个 \(a\in\mathsf{StillRequired}_u\)，都存在某个完整目标结果 \(t\) 满足 \(\mathsf{Covers}_u(t,a)\)，其中包括编辑区域之外的每个不变结果。
Every current target call position has a monitor entry and authorization token bound to \(\eta^+\).
% 每个当前目标调用位置都有绑定到 \(\eta^+\) 的监控器入口和授权令牌。
\end{lemma}
\begin{proof}[Proof sketch]
% 证明概要。
The six cases use the copy/keep bijections and surrounding-workflow identity map to preserve sharing, action IDs, certified origins, and order and to construct every \(\mathsf{Covers}_u\) witness.
% 六种情况使用复制/保留双射和周围工作流恒等映射来保持共享、动作标识、认证来源和次序，并构造每个 \(\mathsf{Covers}_u\) 见证。
The common state update establishes well-formedness and binds every current target call position to \(\eta^+\).
% 公共状态更新建立良构性，并将每个当前目标调用位置绑定到 \(\eta^+\)。
\Cref{app:schema-fidelity-proof} gives the full argument.
% 完整论证见 \cref{app:schema-fidelity-proof}。
\end{proof}
