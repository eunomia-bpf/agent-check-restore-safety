\section{Executable Validation}
\label{sec:validation}

The main result is a pen-and-paper theorem.  The dependency-free bounded
artifact validator handles finite instances.  It is neither the trusted
installation checker nor a mechanized proof of \cref{thm:exact-history}.

\paragraph{Decision kernel}
Given a derived indexed-pomset contract, the validator enumerates topological
sorts, resolves \Fresh/\Alias occurrences, checks authority projections,
iterates \(\widehat\Phi\), verifies removal causes and survivor witnesses, and
reconstructs \(W^\dagger\).  Outcome indices remain distinct under equal trace
projections.  Search fails closed above 128 outcomes, eight occurrences per
outcome, 50,000 linearizations per pomset, or 100,000 safe indexed
completions.  These bounds do not constrain the theorem.

\paragraph{Litmus tests}
The focused suite comprises 19 of the repository's 81 passing tests.  It
covers the rejecting \(2,1,0\) chain, identical-trace indices, completion
observability, structural fixtures for all six edit shapes, same-cell and gate-borrowing cases,
receipt-silent \Alias progress, and both orders of \Fresh/\Alias versus
installation.  The focused tests also pass after clean archive extraction.
These executions test only the decision kernel and bounded structural/race
fixtures.  They do not mechanize schema fidelity, authenticated handle handoff,
durable refinement, or \cref{thm:exact-history}.
Occurrence loss, an unwitnessed elimination, an incorrect survivor language,
or stale-cut acceptance falsifies the executable subset.  Obligation loss,
language mismatch, an enabled old epoch, or observable LTS divergence
falsifies the theorem.
