\section{Scope and Limitations}
\label{sec:discussion}

\paragraph{Contracts and progress}
A contract covers one finite registered slice of protected calls.  Agent
reasoning remains open-ended, but an unregistered protected call fails closed
until another admission.  Complete raw traces are prefix-free, so stopping
versus continuing requires an explicit occurrence.  Completion nonblocking
preserves a safe completion for each compatible outcome.  It guarantees
neither fairness, useful task completion, nor later admission.  The policy
governs authority commitments, not prompt integrity, confidentiality, action
quality, or Agent alignment.

\paragraph{Durability and deployment}
The theorem assumes complete mediation and linearizable, crash-stable
transactions.  Remote exactly-once execution still needs idempotency,
queryable outcomes, or a transactional sink.  Changing policy version
\(\kappa\) requires re-admission.  Each disjoint domain has one logical epoch
and state machine, possibly replicated behind a fault-tolerant store.
Deployment must protect registries, authenticate contracts and cell lineage,
mediate every protected effect, and minimize sensitive provenance.  The
artifact does not integrate with Agent runtimes and causes no external effects
or human-subject risk.  Decentralized controllers and symbolic reduction
remain future work.

\section{Conclusion}

An Agent may rewrite its logical history but not committed world facts.
The Exact Agent History Realization Theorem characterizes exactly which
registered edits admit a prefix-robust implementation and then either constructs
their greatest behavior and canonical program or certifies impossibility.
The Agent only requests an edit.  A trusted checker decides each Fork, Restore,
or Merge request, and the kernel atomically installs accepted programs across
fresh/alias and cut races.  History editing is authority editing with exact
admission.
