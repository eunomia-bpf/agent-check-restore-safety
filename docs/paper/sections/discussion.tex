\section{Scope and Limitations}
\label{sec:discussion}

\paragraph{Bounded, observable contracts}
The model does not predict an Agent's complete future.  A contract covers the
finite protected slice registered at one cut; internal reasoning and
unprotected computation remain open ended.  A newly proposed protected call
outside the frontier fails closed and triggers another registration and
admission.  This boundary is essential: omission cannot silently weaken
outcome coverage.  Complete raw traces must also be prefix-free.  If stopping
and continuing are indistinguishable at the same prefix, the workflow must
register an explicit durable logical decision; otherwise the history
operation has no exact derivation.

\paragraph{Safety and progress}
Completion nonblocking means that every admitted prefix has some safe
completion and every derived outcome has an initial witness.  It does not
guarantee scheduler fairness, useful task completion, or that a later explicit
history edit preserves the old obligation.  The policy governs authority
commitments, not action quality, prompt integrity, confidentiality of
speculative branches, or Agent alignment.

\paragraph{Durability}
The theorem requires complete mediation plus linearizable, crash-stable
occurrence and installation transactions.  It proves receipt order and FIFO
release order.  Physical exactly-once execution and completion order at a
remote service still require idempotency, queryable outcomes, or a compatible
transactional sink.  Policy migration is outside one theorem instance:
changing \(\kappa\) invalidates every seal and requires re-admission.

\paragraph{Centralized logical epoch}
The compiled controller is one logical state machine, although it may be
replicated behind a fault-tolerant store.  Factoring it into
communication-free branch controllers is a separate decentralization problem
and is not assumed.  Parallel enumeration can be exponential; symbolic
pomsets, partial-order reduction, and verified localization are natural future
work.

\paragraph{Deployment and ethics}
The artifact is a bounded executable model, not an integration claiming that
current Codex or Claude histories are trustworthy.  A deployment must protect
the history registry, authenticate tool contracts and cell lineage, and
mediate every protected effect.  Our evaluation uses synthetic histories and
causes no external effects or human-subject risk.  History retention can itself
contain sensitive provenance; a deployment should minimize payload storage
and retain only authenticated security metadata needed by the cut.

\section{Conclusion}

An Agent may rewrite its logical past, but it cannot rewrite facts already
committed to the world.  Agent history admission makes that mismatch a precise
security boundary.  The history structure itself derives the outcomes that
must remain possible and every old owner that must be fenced; length-preserving
resolution accounts for copied occurrences without confusing them with fresh
effects.  The Exact Agent History Realization Theorem then characterizes every
implementable edit and refines the characterization to a durable runtime
across arbitrary Fork, Restore, Merge, fresh, alias, and installation races.
History editing is therefore authority editing---and can be admitted exactly,
not heuristically.
