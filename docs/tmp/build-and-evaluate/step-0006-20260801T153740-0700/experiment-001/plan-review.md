## Gate-by-gate assessment

### Hypothesis and RQ fit

Pass. The experiment tests one explicit uncertainty inside the existing RQ2: whether a once-computed final-support predicate exactly characterizes universal owner-group executability and atomic convergence under exact promotion plus cleanup. It does not rename or broaden the RQ. Both success and failure change the paper decision.

The admission case is strong. Runtime fault injection or another public-trace scan cannot settle the current theorem-novelty blocker; a source-level reduction attempt plus general mechanization can. Existing Python cases are correctly treated as cross-checks, not as a replacement for the general result.

### Non-circularity

Pass, with a strict interpretation during execution. `UniversallyOwnerSerializable` must quantify source-fixed owner schedules and actual sequential `PrepareOK`/`CoreStep.prepare` transitions. `FinalOwnerSupport` must inspect only the atomic final guarded family. Atomic equality and universal enabledness may not appear as fields of a generic interface.

The existing Lean model supports this separation: `PrepareOK` contains nonemptiness, current tentative/open status, base capacity, assignment coverage/injectivity, and operation freshness; it contains neither final support nor target equality. The planned proof therefore has a genuine cross-prefix obligation.

I also attacked the one-owner edge case. It is not a counterexample under the plan's well-formed/atomic-valid premises: moving an owner's own claims from conditional to durable leaves the load of every configuration containing that owner unchanged, so source owner support supplies final support. For multiple owners, putting an unsupported owner last exposes the intended cleanup failure.

### Closest-work and baseline fairness

Pass. The source comparison is correctly framed as a matched semantic derivation attempt, not a numerical benchmark.

The closest-work audit fixes the maximum defensible novelty:

- van Glabbeek--Plotkin Definition 2.1 already defines an asynchronous step `x -> y` by requiring every intermediate set between `x` and `y` to be a configuration. Thus “all intermediate subsets/orders are possible” is established configuration semantics. Their all-pairs-without-the-triple family also removes any novelty claim for higher-order conflict.
- Flanagan--Godefroid Definition 1 already defines independence by enabledness preservation plus a unique commuting diamond, and explicitly excludes conditional dependency while citing Katz--Peled. Katz--Peled already lets commutativity depend on a state predicate. The project cannot claim contextual independence itself.
- resource-tracking concurrent games provide true-concurrency resource annotations, but their resources are described as not affecting control flow; their leading parallel operator is idempotent and does not provide this cleanup-triggered enabledness theorem. They are a resource/concurrency foundation, not yet the same result.
- supervisory control can encode the full authority/cleanup plant and synthesize permitted behavior; guarded transaction work can compile control decisions to propositional guards. The possible delta is therefore a closed-form specialization and certificate, not a new generic supervisor or guard formalism.
- consumable credentials already own global bounded use and atomic multi-credential ratification, but do not provide branch-support promotion or the owner-order iff.

Accordingly, the plan's positive interpretation is appropriately narrow: the only plausible new claim is that, for this support-erasing promotion semantics, one final-support test characterizes an otherwise prefix/order-quantified operational property and yields a failing last-owner order when false.

In particular, incomplete source mapping does not become a novelty win, and compiling only fixed examples remains dependency evidence.

## Non-blocking polish

These are useful refinements, not conditions for starting preflight:

1. Freeze the eventual theorem signature before the general proof: `LWF`/`AC`, atomic `PrepareOK`, source-fixed owner partition, exact prefix repair, immediate deterministic cleanup, and no interleaving should be visible rather than hidden behind “valid batch.”
2. Treat configuration/conditional-independence semantics as the strongest theorem competitor. Resource games and consumable credentials are better labeled inherited foundations, while supervisory control is the encompassing generic framework. The current three-family table is acceptable, but “missing operator” alone is not evidence of non-definability or novelty.
3. Begin mechanization authority-native with the existing `PrepareOK` and `prepareState`; extract a generic support-erasing calculus only after the native theorem works. This reduces the risk that a convenient typeclass field silently assumes the conclusion.
4. State the runtime value as elimination of factorial schedule enumeration, not automatically as a cheap algorithm. A support query over a guarded configuration family may itself require SAT/SMT or a certificate depending on representation.
5. If full lifecycle equality (epochs and tickets) is proved, report it as a strengthening. The paper-facing theorem only requires equality of durable/tentative/terminal authority state and contract denotation, so full equality should not become an accidental blocker.
